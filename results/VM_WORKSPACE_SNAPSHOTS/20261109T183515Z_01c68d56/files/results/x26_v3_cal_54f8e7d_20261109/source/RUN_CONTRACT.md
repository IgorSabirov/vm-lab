# X26 v0.3 — замороженная условная физика и основной опыт

9 ноября 2026, МСК. Основание: прямое поручение пользователя «Изучи мнение соседей и замораживай физику, запускай прогон на ВМ». Оно снимает прежний STOP для этого пакета и разрешает необходимые исправления, заморозку и запуск. Исходная ветка PR #2; main не меняется.

Вопрос: создаёт ли локальный переход носителя доступ к тёмному сектору через объявленный загрузчик и сохраняется ли реально загруженное состояние при следующем шаге? Все численные коэффициенты ниже — фиксированный выбор условной модели, не измеренные величины и не вывод из ADD. Не оптимизируются по результатам.

Родители: ADD-K/R126, R040 (спектральная защита), R041 (статическое отсутствие загрузки), R042/R105 (каналы/секторы), R115 (спектральная классификация). U009 о соответствии авторскому переносу остаётся открытым. U008 — другой причинный опыт. NOW, L05/B09/X10 и автопоэзис этот опыт не подтверждает.

## Принятые положения нового отзыва

1. Для вывода о неограниченном росте по K>0 обязательно X0∈E0. Проверяются все три входных слова, включая перестановку. После шага E0 не навязывается: split может возникнуть штатно. Шесть кратностей и K1/K2 исправлены; битовые произведения сохранены отдельно.
2. F_carrier, payload_map и T_quantum — разные объекты. При коллизии якорей три ролевые моды остаются различимыми внутренними степенями свободы; размер квантового пространства не равен числу вершин ADD. Это явный постулат, не следствие merge. Коллизии протоколируются; T=I в выбранном базисе не является нетривиальной теоремой переноса.
3. Выполняется единая цепочка: X0→X1, регистрация локального изменения, задержка, подготовка пакета, загрузка на H1, закрытие загрузчика, восстановление контакта, X1→X2 и TρT†, удержание на H2, считывание и условный платный сброс. Сохраняются rho_load, rho_after, rho_final, оба H, T и P. Старый H0 для загрузки не используется.
4. Φ зависит от локальных плотностей; Ψ — от разности более полного вектора признаков. Равные qV=q1 при общей формуле барьера уже дают ellV2=ell12. Вычисленные барьеры сохраняются; независимые расстояния не вводятся.
5. Тепловой канал — селективная пара B↔D с реальным разрывом H3. Конечный gate не обязан достичь стационара. При конечной β обратный переход ненулевой, третья мода не связана: чистота/глобальная уникальность стационара не постулируется.
6. Chang не даёт универсального закона для любого BIC. Нулевая g-only ветвь и движущийся проектор проверяются раздельно. Guo относится к одноэкситационному переносу. Новое исследование источников ADD и письмо авторам в этот запуск не включены.

## Физические постулаты

- Единицы ħ=kB=κ=1. F — точный pinned FIG2A_FULL blob `6e44c12cd1f27aadc9e2c73c1f82222944cd2e7b`. Авторская семантика этим не аттестуется.
- Внешний протокол задаёт два момента применения F. Между ними X фиксирован. Загрузка 8, удержание 8, задержка регистрации/подготовки 1 в единицах ħ/κ. Это управляемый стробоскопический опыт, не непрерывная автономная динамика всего мира. Во время задержки одноэкситационный пакет ещё не подготовлен; внешний источник затем поставляет его с объявленной ценой.
- Φ: окно r=1; q = число битов/(4·3). E_pair0=.1, E_20=.2, lambda_pair=.6, lambda_2=.4; t0=.3, ell0=.2, contrast=1, alpha=1; g=.25, bath onsite=0. Полная схема и числа — PHYSICAL_MANIFEST.json. Коэффициенты выбраны как размерностный тестовый случай порядка κ; не подставлены как «физические определители ADD».
- Исходные слова: активное [9,6,0,0,9,6,0,0]; его заранее заданная перестановка [9,9,6,6,0,0,0,0]; тихое [5,10,0,0,5,10,0,0]. Все имеют одинаковые четыре числа битов, но тихое имеет другие чистые полусостояния. Роли V=0, 1=4, 2=2, следуют payload_map. Тихий K=0 не означает отсутствия изменений локальных признаков и поэтому не обязан выключать Ψ.
- Начальный пакет — верхний bright-собственный вектор H1, ортогональный D. Если исходного BIC нет, строка NOT_EVALUABLE_NO_INITIAL_BIC сохраняется; этот протокол BIC-загрузки на ней не определён. Параметры не подстраиваются, строка не заменяется новым кандидатом.
- Ψ-A: Ω=.6·activity, Hc=Ω(|D><B_pair|+h.c.), sin²(πt/8). Вся эволюция проводится совместно с конечным кольцом, контакт не выключается. Работа — интеграл <dH/dt>, положительный ввод и возврат раздельны.
- Ψ-B: g=0 при подготовке/загрузке; отдельный идеальный изотермический резервуар β=4; γdown=.5·activity·sin², γup/γdown=exp(-βΔE). Jump |D><B_upper| и обратный заданы как селективный интерфейс. После gate g=.25 возвращается; сохраняются все компоненты полученной смешанной матрицы. Полный thermal генератор для H3+ring не заявляется. Контактная работа рассчитывается, хотя для данного факторизованного пакета ожидается нуль.
- T=I на ролевых модах и кольце. Отрицательный T переставляет V и узел 2. В симметричной ветви D постоянно: положительный тест T=I тривиален, проверка состояния и отрицательный T необходимы для надёжности исполнения.
- ΔE на переключении H1→H2 и T оплачивается внешним актуатором. Это моделирование внешнего управления, не доказанный обмен энергией с ADD. В итоговом балансе Efinal−Einitial = Wcontrol+Wcontact+Wcarrier−Qloading.
- Ресурсы: 20 единиц топлива, КПД .8, 2 прекурсора, пакет 2, переключение .1, считывание .1, thermal gate .1; контроллер 128 бит, Tcontroller=.01, цена сброса .02/бит (выше T ln2). 128 бит покрывают 72 бита двух наборов локальных окон, 24 бита позиций и 8 бит квантованного локального индикатора; полные журналы считаются внешним измерительным оборудованием. Цена конечного сброса принята как модельный контракт, не выведена из нижней границы Ландауэра. Реальный актуатор/сброс не моделируется микроскопически.
- До подготовки резервируется консервативная верхняя граница затрат через нормы операторов; если её нет, воздействие не запускается. После исполнения расход списывается и остаток сохраняется; no_resource задаёт нулевой запас. Это один ресурсно ограниченный протокол с внешним снабжением, не воспроизводство условий. Тепловой резервуар идеальный изотермический; конечная теплоёмкость не имитируется неизменной температурой.

## Объём, контроли и критерии

Выполняются 249 задач, состав порождается `tasks()` и фиксируется хешем:

- 180 строк: 3 слова × 2 загрузчика × 5 режимов (active, loader_off, trigger_off, bad_transport, no_resource) × N=64,128,256 × 2 точности.
- 9 полных спектральных проверок: три слова на X0,X1,X2; непрерывная мера плюс дискретные массы, Шур–Фешбах, полюса второго листа, моменты и off-axis N-сходимость. N=32,64,128,256. Одинаковые заранее заданные старты; неудача root — технический результат, не отсутствие резонансов.
- 60 ramp-задач: 2 семейства × T=.5,1,2,4,8 × N=64,128,256 × 2 точности. Формы s=3u²−2u³. g-only: g=.1→.5, неизменный D. Moving-dark: r=1→1.4, gamma=.3r, t2=.3, t1=.25, E1=.3, E2=.25, EV=.3+.25(r−1/r), κ=1,g=.1. Это дополнительная контролируемая R040-деформация, не утверждение, что Φ производит этот путь. Энергия D=.3−.25/r внутри полосы. P_leak=1−<P_D(t)> и p_bath измеряются отдельно.

Точности DOP853: (rtol=1e−8,atol=1e−10,max_step=.2) и (2e−10,2e−12,.1). По 41 наблюдаемой точке загрузки/удержания/ramp; внутренние шаги адаптивны и записываются. Удержание — sparse expm_multiply, смешанные состояния через полный набор из ≤3 весовых векторов, без отбрасывания физического bright-сектора.

Критерий отдельной активной строки: p_load≥.1; BIC после переноса; min(p_hold)≥.95 p_load; T — изометрия с сохранением проектора. Причинное сравнение: p_final(active)−p_final(control)≥.05 для обоих loader_off/trigger_off. Порог задаётся до расчёта, не является универсальной границей существования организации.

Технические допуски: след 1e−6; отрицательность 1e−7; энергетическая невязка 2e−6; N-сходимость 1e−4; уточнение 2e−5; нулевые контроли 1e−7. Финальные исходы на N=256/refined используются только после сопоставления N и точности. Ramp fit: только значения выше 1e−10 и ≥3 точки; R²≥.9 — диагностик качества локального power fit, не требование наклона 1 и не доказательство асимптотического закона. Предел N→∞ не подменяется конечным кольцом.

## Исполнение и ограничения

Новый вход — `python -m x26r040.physical_cli`. Legacy v2 full manifest отклоняется явно: он не кодирует полную хронологию. Спектральные модули и проверенные базовые тесты переиспользуются. Изолированный v2 resource ledger теперь выдаёт только LOWER_BOUND_WITHIN_BUDGET, а новый цикл имеет явную платную модель.

Технический PASS, отрицательный физический исход, NOT_EVALUABLE и RESOURCE_BLOCKED сохраняются раздельно. Отрицательный результат не приводит к поиску удачного начального состояния. Код выхода 0 не означает научного принятия.

Калибровка на целевой ВМ: 104 заранее выбранные задачи (60 active_word, 10 quiet_word на максимальном N/refined, 1 неоцениваемая строка, 9 спектральных, 24 ramp по крайним T). Это измерение стоимости, не основной отчёт. Прогноз складывается из измеренных размерных страт, поправок quiet/active и интерполяции времени ramp; учитывает I/O, диагностику и bootstrap. Все физические входы после калибровки неизменны. Main — отдельное задание, 249 задач, полный гейт времени перед submit.

Лимиты: калибровка 300 с, основной процесс 1800 с, память 2048 MiB, результаты 512 MiB; один BLAS/OMP-поток. Никакой набивки времени. По каждой задаче атомарный JSON и checkpoint, NPZ матриц, контрольные суммы. Возобновление допускается только при точном совпадении кода/манифеста и хешей сохранённых состояний; сравнимость времени такого запуска маркируется отдельно.

В GitHub сохраняются исходники, манифест, квитанция, калибровка, прогноз и краткий основной отчёт/индекс строк. Полные NPZ остаются на ВМ по действующей политике сырых данных. Публикация через MCP выполняется ассистентом в рамках постоянного разрешения сохранять все материалы в частном репозитории; автоматического bridge данный launcher не обещает.
