## Проверка отзывов

[Полная таблица решений](../../experiments/e002e_corr/REVISION_REVIEW.md).
Несколько блокеров не подтвердились: чужие размеры сектора, запись checkpoint на каждом шаге, отсутствие numerics в хеше, непроверяемая обязательная память. Умножение порога расхождения решателей на 2–10 не обосновано невязкой; допуски не ослаблены.

Доработки: явный q=0/roundtrip сертификат без проекции; полная PSD на контрольных моментах; хеши и спектры начальных маргиналей; оба приготовления проверяются симметрично; κ_out извлекается из jump и сверяется по операторному тождеству; дрейф всех sham-колонок; целые индексы сеток; обязательный один поток; pin байтов исходных данных; точный счёт checkpoint/I/O, временные файлы, диск и честное отсутствие resume; пересчёт человекочитаемого отчёта; опциональная локальная реконструкция initial.npz.

Полные матрицы остаются на ВМ, в GitHub публикуются только их хеши. Утверждение соседей, что initial.npz уже опубликован, неверно. Deep verify не открывает ВМ самостоятельно.

## Copilot

CLI 1.0.105 восстановлен в текущей среде. Новый device login подтвердил IgorSabirov; отдельный ping получил точный случайный маркер за 13,216 с. Секреты в материалы ревью не включены.
[Запрос](request_001.txt) содержит точный SHA кода, полный CORR-пакет, тесты и критичные зависимости; 125431 байт, SHA-256 d69d4eb7213bd19781968bb69f050c77c7a794d55d7d1b2f777a493829d7c8b2.
Запрос технический; Copilot не уполномочен менять научную цель/модели/пороги.
[Ответ 001](response_001.json) получен за 158,215 с при ориентире 180 с.
Все три замечания подтвердились; [самостоятельный разбор и исправления](FINDINGS_001.md):

1. Отдельно измеряются и прогнозируются обе записи отчёта и обе его проверки.
2. Два экспорта F сверяются на общей сетке; подмена всех raw F с пересозданием
   манифеста теперь отвергается.
3. Runtime gate пересчитывается; ложный PASS с согласованно подменённым
   человекочитаемым текстом также отвергается.

[Запрос 002 для итоговой версии](request_002.txt) содержит полный исправленный
пакет, тесты и границы технической приёмки. [Ответ 002](response_002.json)
получен за 101,029 с при ориентире 160 с. Первые два замечания закрыты;
третье уточнено: нужен независимый пересчёт сравнения среды, а не доверие
сохранённому comparable-флагу. [Разбор и исправление](FINDINGS_002.md).

Сверка теперь идёт с отдельной закреплённой калибровкой из исходного дерева,
по recorded before/after и фактическим потокам. Добавлен сценарий согласованной
подмены CPU, положительного флага и текста PASS. Тесты повторены по заранее
опубликованному прогнозу: попытка 005, 71/71, 4,979878269 с при 5,5 с, PASS.
Попытка 004 также сохранена: 71/71, 4,925329328 с при 6 с, PASS.

[Запрос 003](request_003.txt) передаёт окончательную версию для проверки закрытия.
[Проверка идентичности кода](CODE_INTEGRITY.json): все 8 файлов пакета побайтно
совпали с Git blob закреплённого source. После этой версии код не менялся.


[Ответ 003](response_003.json) получен за **85,363 с** при ориентире 120 с.
Copilot подтвердил закрытие согласованной подмены среды и не нашёл оставшихся
блокеров для ограниченной sham-only калибровки в заявленных границах доверия.
Все ответы и их SHA сохранены; [закреплённая техническая проверка](technical_review.json).

Необязательное предложение о равенстве reviewed_source_commit и source_commit
не принято: ревью привязано к хешу всех байтов реализации/зависимостей.
Коммит, добавляющий только отчёт/конфигурацию/само ревью, может иметь другой SHA
без изменения проверенного кода. Обе исходные ссылки сохраняются отдельно;
изменение кода меняет implementation_sha256 и блокирует запуск со старым ревью.

**Техническое ревью завершено.** Шаблоны теперь ссылаются на проверенный JSON
ревью по SHA-256, но не являются готовыми заявками: source/budget/calibration
не подменены вымышленными значениями. Ни калибровка, ни production не запускались.

## Следующая граница

Ревью не заменяет научную приёмку и калибровку на производственной ВМ. Полное время процесса, фактический объём, память и отчёт калибровки должны быть проверены и закреплены до production. Здесь производственный прогон не назначается.
