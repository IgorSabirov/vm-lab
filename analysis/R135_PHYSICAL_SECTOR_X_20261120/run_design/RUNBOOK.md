# R135. Запуск, возобновление и сдача

## 1. Что доступно для исполнения

Комплект содержит автономный контроль T1/T2/G6a, искусственные поля G4, проверку суррогата T3, измеритель отдельного поля и оценку связного кумулянта по целой страте. Production G4 требует независимых ансамблей. Для G5 и G6b нужны размерные физические входы из [спецификации опыта](EXPERIMENT.md). Для T3 нужны реализованные каналы столкновений и согласованные адаптеры решателей. Статус каждого входа и имена выходных файлов заданы в [PROTOCOL.json](PROTOCOL.json). Публикация проекта и принятие физического результата — разные события. [Контракт прогона](../../../infra/RUN_CONTRACT.md) · [политика вычислений проекта](../../../COMPUTE_AUTHORITY.md).

### Воспроизвести контроль

Пример для чистого клона. Получить опубликованную редакцию по ветви разработки либо по SHA, указанному в задаче #151 после слияния. Поле `base_commit` в протоколе указывает редакцию **исходной R135**. Код нового проекта появился позже.

```bash
git clone https://github.com/IgorSabirov/vm-lab.git
cd vm-lab
git switch --detach origin/main
d=analysis/R135_PHYSICAL_SECTOR_X_20261120/run_design
out=$(mktemp -d)
git rev-parse HEAD > "$out/code.commit"
python -c 'import sys,numpy,mpmath; print(sys.version,numpy.__version__,mpmath.__version__)' > "$out/environment.txt"
python "$d/../verify.py" > "$out/R135.json"
python analysis/BH1_YANG_MILLS_COMPARISON_20261119/check_r131_r134_sector.py > "$out/parent.stdout"
python "$d/controls.py" > "$out/reference.json"
cmp "$out/reference.json" "$d/CONTROL_REFERENCE.json"
python tools/registry_links.py
```

Для точного повторения одной редакции перед расчётом выполнить `git switch --detach <SHA_слияния_из_задачи_151>`. В сборке эталона работали CPython 3.12.14, NumPy 2.3.5 и mpmath 1.3.0. Их можно установить в отдельное окружение (`python -m pip install numpy==2.3.5 mpmath==1.3.0`). Предусловие — полный клон с родителями, на которые ссылается манифест. Скрипт проверяет SHA-256 исходных данных и кода, порядок этапов, точные целые моменты, коэффициент ряда, действительные орбиты именованного движка и два вычисления спектра при 80/100 знаках точности. Ошибка прекращает команду. При переносе платформы сначала сравнить структуру, строки и целочисленные величины точно, затем числа с плавающей точкой. Для малой спектральной разности допустимое абсолютное отклонение $10^{-22}$, для корня $10^{-9}$, для бюджетных и геометрических безразмерных величин $10^{-10}$. Отклонение с причинами записать. Изменение эталона оформляется как отдельная версия.

### Измерить подготовленные поля G4

Нужен комплексный массив `.npy` размера $N_s^3$ с локальным нормированным следом тепловой петли. Идентификатор конфигурации, плакетка, цепь, шаг и привязка к исходным ссылкам хранятся в манифесте. Команды ниже создают маленькое синтетическое поле для проверки интерфейса. В физическом прогоне файлы страт формируются по порогам плакетки, замороженным по калибровочной выборке.

```bash
python - "$out/field.npy" <<'PY'
import numpy as np
import sys
word = np.array([0, 0, 1, 2, 1, 2, 2, 1])
ell = np.exp(2j * np.pi * word / 3)
np.save(sys.argv[1], np.broadcast_to(ell[:,None,None], (8,8,8)))
PY
python "$d/measure_field.py" "$out/field.npy" --stride 1 --cut 0 > "$out/one.jsonl"
python "$d/cumulants.py" "$out/one.jsonl" > "$out/one_estimate.json"
```

Один JSON на конфигурацию, одна строка, все три оси. Для страты передать `cumulants.py` файл со строками всех входящих конфигураций. Получаются покрытие в числе принятых окон, сырые чётная/нечётная плотности и связная чётная плотность. Первичный физический результат — разность оценок верхней и нижней страт, в каждой повторной блочной выборке оценка целиком пересчитывается. Одно синтетическое поле не имеет физической статистической ошибки. Проверки разделения на цепи, стратификацию, автокорреляцию и bootstrap выполняет исполнитель ансамблевого анализа по [разделу G4](EXPERIMENT.md). Синтетические образцы и архивные данные маркируются разными типами происхождения.

## 2. Контракт файлов

Хранить результаты под отдельным идентификатором прогона и SHA. Массивы связей и траектории остаются в вычислительном архиве с проверяемым получением, на GitHub публикуются манифест, компактные результаты, проверки и отчёт. Для каждого файла записать путь или URI, версию/неизменяемый идентификатор, объём в байтах, SHA-256 и условия доступа. Для внешнего архива указать лицензию и дату получения. Каждый производный файл содержит ссылки на версию кода и родительские данные.

При передаче времени в секундах привести коэффициент перевода и его источник. Всегда явно указывать, берётся ли плотность на физический или комовый объём. ## 3. Ресурсы и порядок исполнения

1. Зарегистрировать редакцию, независимые входы и единицы. Проверить родительскую R135 и контрольный вывод. G6a, контрольные T1/T2 и суррогат T3 исполнимы на одном CPU. При переносе измерять wall time отдельно от получения архивов, установки пакетов и публикации.
2. Для G4 предпочесть пригодный лицензированный ансамбль. При новой генерации ресурс калибровать отдельно для каждой решётки на выбранной владельцем площадке. Прогноз в core-hours/GPU-hours строится из измеренного времени цикла обновления × числа независимых цепей × числа циклов. Добавить отдельно стоимость прогрева, измерения и 4000 блочных повторов. Длину отложенного опыта рассчитывать по автокорреляции пилота. Бюджет фиксируется до открытия ответа отложенной выборки.
3. Одна конфигурация несжатых исходных SU(3)-связей complex128 требует $N_s^3N_t\times4\times9\times16$ байт. На решётках $4\times24^3$, $4\times32^3$, $8\times48^3$, $8\times64^3$ это 30.375, 72, 486 и 1152 МиБ соответственно. Поле следов требует $16N_s^3$ байт. Рабочие буферы и места для checkpoint учитывать по фактическому пилоту. Допустим потоковый расчёт с сохранением исходной цепи либо проверяемого архивного ключа и достаточных данных для повтора.
4. Для G5 измерить стоимость одной сходимой траектории в каждой ветви. Учесть сетку, сценарии нуклеации, удвоения разрешения и ошибки входов. Для T3 оценить минимум пять углов/историй × три допуска × два BBN-backend на набор параметров. Общие baseline переиспользовать только при полном совпадении хеша входов. CLASS запускается для каждой различной согласованной истории, выбранной в G6b. Указывать размер кэша и фактически прочитанные данные.
5. При отсутствии физического входа присвоить этапу PHYSICAL_INPUT_OPEN с указанием поля. Независимые ветви продолжаются. Сырые данные пилота не пополняют отложенную выборку; изменение дизайна после открытия результата требует новой версии и отметки об известном результате.

## 4. Восстановление и приёмка

Для G4 единица сохранения — завершённая конфигурация цепи. Для G5/T3 — завершённая точка/история на одном допуске. Писать временный файл, проверить хеш и структуру, затем атомарно переименовать и только после этого отметить единицу в манифесте. Возобновлять с последнего целого checkpoint, восстанавливая и состояние PRNG. Выявлять дубли по составному ключу набора, исходного SHA, цепи и шага либо угла/допуска. Повтор запуска на неизменных входах должен воспроизводить уже сохранённые единицы. При утрате исходного состояния цепи сохранять новый идентификатор цепи и заново учитывать прогрев. Не смешивать результаты после смены входов, порогов и версии.

Для технической сдачи приложить входной/выходной инвентарь с хешами, версию протокола и измерения времени, успешно воспроизведённые контроли, таблицы условных выводов и сбоев, PR со ссылкой в карточке R135/U006. Независимый читатель должен получить $D_4$ из конфигурационных строк, баланс каналов из истории, а вывод о завершении из $f(t)$ и интервала его ошибки. INTERPRETATION_OPEN допускается при исправных вычислениях. Отдельно отметить случаи, где данные исключили конкретный закон или оказались совместимы с нулевым эффектом. Научное решение по модели принимает владелец. [Карточка результата](../../NOW_RESULTS_SYNTHESIS_20261106/R135.md) · [вопрос U006](../../NOW_RESULTS_SYNTHESIS_20261106/OPEN_QUESTIONS.md).
