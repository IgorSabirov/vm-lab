# Как исполнить и сдать полный R135

[Основное задание](README.md) · [разработка физических входов](DEVELOPMENT.md) · [машинный план](PLAN.json).

## Старт и организация исполнения

**Первая поставка после утверждения проекта — физические входы.** Оператор открывает реестр гипотез и выпусков данных P0. Затем запускает работу по архивам/генератору P3, по калибровке масштаба и сшивке EOS P1, по кандидатам энергии/отображения P2 и по матричным элементам P6. Первый физический результат на линии G4 — диагностированный ансамбль со статистическими ошибками и происхождением каждого поля. Тесты из предыдущих PR прикладываются по SHA в качестве базы сравнения. Их повтор нужен при изменённом коде, данных или среде, в объёме изменившейся зависимости.

**Площадка и роли.** GitHub ведёт исходники, задания, статусы, проверяемые ссылки на исходные данные, выходы и изменения реестра. Для исполнения через нативный Copilot брать проверенный путь предыдущей серии: фиксированный execution SHA → нативный CLI вызывает определённую команду → независимый сбор фактической квитанции и манифеста → публикация результатов → перепроверка из GitHub. Оператор может исправить техническую ошибку с новым SHA и записью причины. Научные параметры и вскрытую выборку сохраняют под исходной версией. Площадку тяжёлых вычислений выбирает владелец по калибровке; для выбранного внешнего исполнителя GitHub связывает job ID и контрольные суммы архива с задачей. Научную приёмку проводит владелец. [Проверенный запуск](https://github.com/IgorSabirov/vm-lab/actions/runs/44719756079) · [workflow](https://github.com/IgorSabirov/vm-lab/blob/7b26fd4a6cfa20d9768ee295917b10926537d60b/.github/workflows/bbn-copilot.yml) · [квитанции и сырьё в PR #144](https://github.com/IgorSabirov/vm-lab/pull/144) · [политика проекта](../../../COMPUTE_AUTHORITY.md).

Техническая разработка исполнителя R135 включает команду для каждого P1–P9, адаптеры форматов, закрытые от обучающей стадии выходы отложенных цепей и сборку пакета результатов. До старта пакет фиксирует исходный SHA, исходные SHA исполнителей, окружение, workflow, манифест данных/лицензий, checkpoint, выборку и оценку затрат. Конкретная команда допускается в production, когда принимает физический вход этапа и создаёт выход указанного типа. В архиве последнего BBN-прогона имеется статус COMPLETE_CONTROL_DISCREPANCY; при переносе решателей выяснить, влияет ли соответствующее расхождение на новый вывод.

### Рабочая очередь и передача ответственности

| Очередь | Ответственная функция | Что выдаётся следующему исполнителю |
|---|---|---|
| Утверждение постановки | Научный руководитель формирует P0, владелец рассматривает научные решения и выбирает площадку физических вычислений | Версия гипотез, условия отбора и таблица «обязательный вход → исполнитель → ожидаемый файл» |
| Независимые поставки | Разработчик термодинамики и размерной привязки — P1; разработчик графовой модели — P2; решёточный исполнитель — P3; разработчик микрофизики — P5/P6 | Для каждого отсутствующего входа — запланированное получение, метод независимой проверки и идентификатор поставки. Неполученный вход остаётся в очереди |
| Интеграция | Исполнитель реальновременной динамики — P4, космологического интегратора — P7, BBN/CLASS — P8/P9 | Размерные истории и неопределённости каждой ветви, пригодные для проверки в другом процессе |
| Сдача | Copilot на GitHub исполняет закреплённое задание и фиксирует квитанции. Проверяющий сопоставляет их с проектом, владелец принимает научный вывод | Заполненная матрица P10 и пригодный для повторного чтения архив |

При техническом сбое исправляется реализация и переисполняются затронутые потомки. При отсутствующем физическом входе разработчик получает точный незаполненный контракт и способы из DEVELOPMENT.md. При доказанном отрицательном ответе фиксируются гипотеза, область и свидетельство. Эти три случая создают разные записи в трекере.

## Затраты и управление выборкой

| Работа | Из чего строится прогноз и что измеряет калибровка |
|---|---|
| P1–P2 | Число EOS-ветвей и достижимых термодинамических интервалов, стоимость вычисления операторов по размерам графа, число независимых подготовок. Отдельно оценить научную разработку модели, не переводить отсутствие закона в часы CPU |
| P3–P4 | Четыре решётки по восемь цепей. Для каждой решётки измерить цену одного цикла, сохранения и извлечения поля, память и дисковый поток. Стоимость генерации — сумма по цепям произведений длительности цикла на число циклов с поправкой на прогрев и прореживание. Из $\tau_{\rm int}$ и дисперсии спрогнозировать достижимый 95%-интервал. Расход real-time расчёта оценивать отдельно от генерации равновесных полей |
| P5–P7 | Калибровать один профиль пузыря и одну совместную историю по каждому режиму, включая уточнение сетки, число точек температуры и перенос ошибок входов. Учесть время хранения состояний при повторном нагреве |
| P8–P9 | На сочетание физической точки и выбранной архитектуры/тепловой ветви с двумя действующими связями минимум 5 историй × 3 точности × 2 BBN-backend = 30 BBN-интегрирований. Умножать только на фактически различные точки/истории. Для CLASS, оценки likelihood и её статистической калибровки вести отдельные числа вызовов. Кэш переиспользовать только по полному совпадению входов и версии |
| Все этапы | Сохранять калибровочное измерение и диапазон прогноза, фактические CPU/GPU-часы, пиковую память, объём диска, выдачу архива, резерв и цену повторного продолжения. Если требуемая мощность превосходит площадку, сначала предложить архив, потоковую обработку или другую конфигурацию ресурсов с тем же физическим критерием |

Исходная диагностическая сетка использует $T_\gamma=0.02,0.2,2$ МэВ и $\xi=0.3,0.44118895,0.6,1$ в точке события. Узел 0.44118895 — исторический поздний бюджетный ориентир. В физическом основном скане независимые оси, включая $\Lambda_X$, начальные условия и связи, выбираются в P0. Тогда $T_c$, $T_\gamma$ в событии и $\xi$ обязаны удовлетворять истории и калибровке. Произвольные комбинации несовместимых параметров отмечаются вне модели. Порог, неразрешённое окно и изменение знака требуют уточнения сетки до объявленной точности или публикации явной незамкнутой границы. Оценки памяти для конфигураций приведены в [существующем порядке запуска](../run_design/RUNBOOK.md).

## Первичные измерения, статистика и отрицательные решения

| Предмет | Что замораживается до измерения | Как трактуется результат |
|---|---|---|
| Граф как носитель X-A | Гамильтониан, мера, подготовка, размерная калибровка, прогноз энергии/ветвей на независимой выборке | Устойчивый прогноз в объявленном диапазоне поддерживает данную реализацию. Нарушение необходимого тождества либо отсутствие перехода, доказанное для этого класса при его предпосылках, исключает конкретный механизм |
| Граф как маркер X-B | Карта всех достижимых состояний, физическое приготовление, прогноз знака/значения и неопределённости; контроль 1–3-точечных данных | Отдельно оценить наличие $D_4$ в YM и согласие независимого предсказания графа. Интервал $D_4$ внутри $\pm10^{-3}$ поддерживает практическую эквивалентность по указанной величине. Для отрицания более широкого класса требуется свой необходимый критерий |
| Время моды | Какие фаза, возмущение, наблюдаемая, часы и диапазон $T_X/T_c$ исследуются | Сдать интервалы $H\tau_q$. Если весь интервал выше 1 — запаздывание на хаббловском масштабе; ниже 1 — соответствующая мода быстрее расширения. Перекрытие 1 или неразрешённый хвост — неопределённый результат. Длительность фазового превращения оценивается самостоятельно |
| Gate D / BH1 | $t_0,H_0$, цель $f$, шкала времени, определение остатка, тепловая ветвь | Сообщить $f$, $1-f$ и физический объём старой фазы через 1 и 10 начальных $H_0^{-1}$, $t_{50,90,99}$, перколяцию по $I=0.34$ и убывание $a^3 P_{\rm old}$. Для заданного горизонта завершение — нижняя 95%-граница $f\ge0.99$. Сохранение значительной доли к 10 $H_0^{-1}$ — верхняя граница $f<0.90$. Иные интервалы публикуются с числами. Окно 10 $H_0^{-1}$ конечно |
| Доставка энергии | Единицы, знак, канал, знаменатель доли, форма источника и окно. Поздние 59.12%/40.88% и резкий 4%-нагрев — контроль прежней квитанции | Предсказать из источников доли в электромагнитной плазме, нейтрино, ином излучении и остатке. При изоляции перенос видимому сектору во время перехода строго нулевой по условию модели. Поздний распад получает самостоятельное окно |
| Совместный отклик R134/T3 | Углы 00,10,01,11-full,11-add, общие начальные состояния, шкала амплитуд, интеграторы и фиксированный пол разрешения | На общем состоянии сравнить $Q_{11}$ с $Q_{\rm add}$, затем разность full/add по D/H, $Y_p$ и истории. Нулевой смешанный микроскопический член возможен при ненулевой нелинейной разности наблюдаемых. Обе величины входят в итог |

В численной проверке T3 применять правило из [проверки готовности](../run_design/preflight/README.md): три допуска, отдельная сходимость каждого из пяти $O$ и самого остатка, потом фиксированное разрешение $10^{-6}$ по относительному D/H. При выключенном расширении остаток баланса полной энергии не более $10^{-8}$ на проверочной истории. При включённом расширении оценивать отклонение интегрального закона с работой $p\,d(a^3)$ на трёх шагах и влияние остатка на научные пороги. Невязка численного баланса, сравнимая с измеряемой доставкой, блокирует вывод о переносе.

**Наблюдательное решение.** Конкретный вариант для предварительной регистрации — D/H Cooke et al. 2018, $Y_p$ Aver et al. 2015 и официальный likelihood Planck 2018 TT,TE,EE+lowE. Это исторический воспроизводимый базовый набор. До раскрытия результатов закрепить релизы/хеши, общие космологические и вспомогательные параметры, ядерные и атомные систематики, предпосылки независимости наборов либо совместную ковариацию. Согласованно вычислять гелий в рекомбинации и в BBN, проследить разницу между $\eta_{\rm BBN}$ и $\eta_{\rm CMB}$. При подаче полных CMB-спектров вторично не накладывать опубликованное из тех же данных гауссово ограничение на $N_{\rm eff}$ или $\Omega_b h^2$. Проверить стандартный baseline на том же наборе. Выбрать и закрепить статистику до анализа: например, профильное отношение правдоподобия с калибровкой порога 95% симуляциями при границах и неидентифицируемости. Хранить вклады D/H, гелия и CMB раздельно, профиль ошибок и сходимость. Если область альтернативы превышает возможности выбранного likelihood, указать область применимости и отдельную задачу для расширения. [D/H](https://doi.org/10.3847/1538-4357/aaab53) · [гелий](https://arxiv.org/abs/1503.08146) · [Planck](https://pla.esac.esa.int/).

## Состав итоговой поставки

1. **Привязка к источнику.** Один run ID и execution SHA. Для каждой реализации и тепловой ветви — model ID, point ID, область условий, SHA данных/конфигурации, значения и ковариации внешних параметров, допуски, версии CLI и решателей.
2. **Сырьё и повтор.** Реестр ансамблей/траекторий, архивы либо проверяемая регенерация, SHA каждой единицы, код измерения, калибровочные и отложенные идентификаторы, архив истории, исходники решения и квитанции фактических команд. Баланс и числа отчёта воспроизводятся из этих материалов. Сбой посередине цепи восстанавливает состояние PRNG и checkpoint; двойной учёт шага и повторное использование вскрытой выборки исключаются по ключам.
3. **Научная строка.** Указать $T_c$ и его источник, $H\tau_q$, $f_{1H}, f_{10H}, t_p, t_{90}, t_{99}$, $H_0(t_{99}-t_{50})$, интегралы $Q_j$, массу и долю остатка, $\eta$, D/H, $Y_p$, $N_{\rm eff}$ в определённую эпоху, CLASS-файл, результат likelihood и уровень неопределённости. Для незавершившегося превращения и ненаступившего события цензурировать время и указывать нижний предел наблюдения. Для определимого нуля указывать физическое основание.
4. **Итог по ветвям.** Раздельно выдать «граф — носитель», «SU(3) — физический сектор», «граф — маркер SU(3)», отдельно по изоляции и обмену. Для раннего опровержения прикрепить доказательство применимости необходимого условия и список освобождённых зависимостей. Для условного результата перечислить внешние допущения. Для незавершённого — точный вход, ограничение и ответственную научную работу.
5. **Приёмка.** Исполнитель публикует квитанции и отчёт, независимый проверяющий повторяет первичные числа из архива и проверяет охват. В карточке R135 и U006 ставят ссылки на состоявшиеся физические результаты и фактические ограничения; научный статус обновляется после решения владельца. Публикация проекта в #155 завершает проектирование. Сам трекер полного результата остаётся открыт.
