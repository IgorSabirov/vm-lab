# R135 P8–P9: исполняемые адаптеры и наблюдательная часть

Модули [observations.py](../r135/observations.py), [backends.py](../r135/backends.py) и
[likelihood.py](../r135/likelihood.py) принимают вычисленную историю P7. Они не
используют заданный нагрев из прежнего контрольного опыта PR #144. Точность,
происхождение физического входа и научный вывод сохраняются раздельно.

## Реализованные вычисления

**P8.** Истории пяти углов `00,10,01,11full,11add` проверяются и преобразуются в
существующий канонический контракт PRIMAT/LINX. Число барионов проверяется на
сохранение; все массивы должны иметь согласованные сетки, единицы и область.
Немонотонная температура допустима: независимая переменная — физическое время.
Слабые скорости подаются по времени. Для нетепловых электронных нейтрино и
антинейтрино требуется рассчитанная таблица слабых скоростей, связанная SHA-256
с обоими спектрами. Их нельзя заменить одной температурой.

При явно обоснованном тепловом замыкании выполняется действующий интеграл
`LINX.WeakRates` отдельно в каждой точке времени. Две точки с одинаковой
температурой фотонов и разными температурами нейтрино остаются разными. Условия
применимости штатной тепловой поправки LINX записываются в конфигурации.

**P9 BBN.** Исполняются настоящие, независимо реализованные ядерные ядра
`LINX.NuclearRates` и `PRIMAT._K_LT`. В режиме общего входа интеграторы —
`scipy.solve_ivp` BDF для LINX и Radau для PRIMAT; оба получают одинаковую историю,
прямые ядерные таблицы, коэффициенты обратных реакций, слабые скорости и начальное
состояние. Это отдельный режим от штатного расчёта фона каждой библиотеки.
`native_baseline()` сохраняет такой штатный контроль в отдельном новом каталоге.

Пять историй × три уровня точности × два ядра дают 30 интегрирований. Проверка T3
сначала требует сходимости всех пяти обилий, затем смешанного остатка.
Нестабильность одного угла возвращает `FAIL_CONVERGENCE`. Ядерные таблицы могут
иметь разрыв на границе области: интегратор перезапускается при **каждом**
пересечении этой границы, включая повторные пересечения при нагреве.

У каждого расчёта есть `input.json`, `trajectory.npz`, `observables.json`,
`segment_diagnostics.json` и `receipt.json`. Квитанция содержит реальные вызовы
чтения истории, первые/последние аргументы ядра, SHA ядерных и слабых таблиц,
точность, исполненную реализацию и хеши результатов. Ключ повторного использования
включает весь физический вход, начальные обилия, точность и исходный код. Изменённый
вход или файл результата отвергается.

**CMB.** Нативный CLASS выполняет явно выбранное приближение свободной
безмассовой радиации после завершения передачи энергии. Требуются обоснования
адиабатичности, отсутствия взаимодействующего остатка и завершения передачи до
входа нужных мод под горизонт. Поздняя поверхность P7 должна находиться после
аннигиляции электронов. Из её фактических плотностей вычисляется `N_ur`, из
числа барионов и температур — `eta`; `omega_b` затем получается из `eta`,
измеренной `T_cmb` и финального изотопного состава BBN с массами закреплённого
PRIMAT. Нельзя заменить холодный массивный остаток безмассовой радиацией:
проверяется его давление.

CLASS выдаёт линзированные TT,TE,EE,BB до **ℓ=2508**. Адаптер явно переводит CAMB
`D_ell` в `C_ell` в мкК² и проверяет полноту мультиполей. Хвост 2501–2508 не
достраивается. Для общего взаимодействующего X имеется отдельный импорт
**уже вычисленных** спектров из зарегистрированного решателя с привязкой к P7,
BBN, исходному commit и квитанции исполнения. Такой импорт не означает, что
произвольные уравнения возмущений X реализованы в нативном CLASS этого пакета.

Точность CLASS задаётся отдельным словарём `precision`. Для численной приёмки
P9 принимает `class_refinement` из двух или трёх последовательно уточняемых
словарей и заранее выбранный `max_cmb_delta_logL`. Каждый уровень действительно
вычисляет свой спектр и его полный likelihood; изменения `ln L` проверяются
отдельным `class_refinement_gate()`. Все уровни сохраняются. Неизменные или
ослабленные параметры отвергаются. Без такого опыта результат прямо получает
`cmb_precision_status: NOT_VALIDATED`, в том числе в `likelihood_grid.csv`.
Искусственное испытание связки ниже проверяет передачу при одной точности и не
объявляет её достаточной для физического вывода.

Поддерживаемые параметры точности: `tol_background_integration`,
`tol_thermo_integration`, `tol_perturbations_integration`, `tol_tau_approx`,
`perturbations_sampling_stepsize`, `l_linstep`, `l_logstep`,
`k_max_tau0_over_l_max`, `accurate_lensing`. Они соответствуют
`include/precisions.h` закреплённого CLASS. Нельзя передать через этот словарь
посторонние команды, пути или новые физические параметры.

**Likelihood.** Используются полные закреплённые Plik, Commander и SimAll:
проверяются 134 файла, матрицы, 47 nuisance-параметров, единая калибровка и
совместный SZ-приор. Проверяются исходный архив установленного clipy и хеши его
Python-кода из wheel RECORD. Дополнительно вычисляется совместная BBN-функция в
координатах `(log10(D/H), Yp)` с явно переданной теоретической ковариацией.
Профилирование 21 варьируемого nuisance реализовано при фиксированной космологии;
космологические и X-параметры задаются внешней зарегистрированной сеткой.
Gaussian-ограничения на `Neff/omega_b`, извлечённые из того же Planck, дополнительно
не добавляются. Исключение требует отдельно калиброванного порога статистики.

## Входы и единицы

P8 получает `inputs["channel_history"]`, JSON со следующими полями:

```text
schema: R135-channel-history-v1
units: {time: s, temperature: MeV, density: MeV^4, rate: s^-1}
histories: {00: history, 10: history, 01: history, 11full: history, 11add: history}
```

В каждой истории обязательны `time_s, scale_factor, H_s_inv, T_gamma_MeV,
n_b_cm3`. Тепловой режим использует `T_nu_MeV`; нетепловой — `f_nu_e` и
`f_antinu_e`, каждый с `energy_MeV` и двумерным массивом `values`. Позднее
сопоставление CLASS использует `rho_gamma_MeV4, rho_nu_MeV4,
rho_extra_MeV4, p_extra_MeV4`. **rho_nu — сумма по всем видам**.

Слабые скорости находятся в `history.weak_rates` либо во входе `weak_rates`:
`time_s, lambda_n_to_p_s_inv, lambda_p_to_n_s_inv, unit: s^-1, source`.
Нетепловая таблица дополнительно имеет `neutrino_spectra_sha256`, compact JSON hash
объекта с полями `f_nu_e,f_antinu_e`. Таблицы ядерных скоростей можно передать через
`nuclear_rates` (`rates` канонического контракта и `reverse_alpha_beta_gamma`) или
получить из закреплённого LINX с заданными `nuclear_rates_q`.

Начальные обилия задаются как `common_initial_abundances` либо
`initial_abundances[corner]` в порядке `n,p,d,t,He3,a,Li7,Be7`. Они должны иметь
физическое происхождение. Если история начинается позже горячей подготовки,
нужна привязанная SHA запись `prehistory_baseline`. Короткая история до 10 H0⁻¹,
не дошедшая до BBN, не считается входом окончательных обилий.

Для `weak_rates_mode: linx_thermal_pointwise` одних признаков теплового
равновесия недостаточно. В `thermal_weak.applicability` обязательны `source`,
`T_gamma_range_MeV: [min,max]`, `T_nu_range_MeV: [min,max]` и
`xi_nu_range: [min,max]`. Вся передаваемая история должна лежать внутри этих
явно обоснованных интервалов. Дополнительно применяются пределы закреплённой
реализации LINX: область фотонной температуры ограничена `const.T_end`,
`const.T_start` и пересечением областей обеих таблиц тепловых поправок;
нейтринная температура не может превышать `const.T_start`. Эти ограничения
реализации сохраняются в рассчитанной таблице и не доказывают применимость
теплового приближения к конкретной модели.

Полная история P7 должна доходить от подготовки X до завершения BBN.
Начало при 404 МэВ или выше нельзя непосредственно передать штатному расчёту
BBN слабых скоростей. Для него нужен отдельно подготовленный и физически
согласованный сегмент истории в заявленной области, начальные обилия с
привязкой к сохранённой предыстории, либо независимо вычисленные слабые
скорости для всей нужной области. Адаптер не обрезает ранние времена и не
экстраполирует тепловые поправки автоматически. Полная предыстория и её
контрольная сумма должны сохраняться вместе с подготовкой сегмента.

P9 получает `bbn_inputs`, `class_inputs`, `data_release_lock`; конфигурация
содержит три уменьшающихся пары `rtol,atol`, `theory_covariance_logD_Yp`, пути к
закреплённым внешним библиотекам/данным и политику nuisance. Полный исполнимый
пример этих JSON создаёт [validate_native.py](validate_native.py).

### Внешние рассчитанные спектры

P8 поддерживает `class.perturbation_model.kind = external_computed_perturbations`
и `external_solver = {repository, commit, equations_source}`. P9 запускается с
`cmb_mode = external_computed_spectra` и входом `computed_spectra_manifest`.
Для каждого ключа `linx/00`, …, `primat/11add` манифест содержит:

```text
producer: {repository, commit, equations_source}
P7_history_sha256: exact source_history_sha256 from the P8 item
BBN_observables_sha256: canonical_hash of the converged observables.json object
spectra_input: logical name of a separately hashed stage input
spectra_sha256: SHA-256 of that file
execution_receipt_input: logical name of a separately hashed receipt
execution_receipt_sha256: SHA-256 of that receipt
```

Квитанция должна иметь те же `producer`, `inputs.P7_history_sha256`,
`inputs.BBN_observables_sha256`, `outputs.spectra_sha256`, а также
`state: COMPLETED, exit_code: 0`. Спектр — JSON с `ell` от 2 до 2508,
`TT,TE,EE`, `unit: microK^2`, `convention: Cl` (BB/TB/EB при наличии).
Проверяются соответствие точке и реальные файлы. Корректность внешних физических
уравнений остаётся отдельным условием научной приёмки.

## Воспроизводимая среда и проверки

[requirements.lock](requirements.lock) фиксирует 22 колеса испытанной среды
BBN под CPython 3.12/Linux x86_64 с SHA-256. Исходники LINX и PRIMAT должны
находиться на `PYTHONPATH` в чистых checkout на SHA из
[sources.json](sources.json). CLASS собирается из закреплённого исходника.
Незапланированное изменение отслеживаемого исходника отвергается до расчёта.

```sh
python3.12 -m venv /tmp/r135-bbn-env
/tmp/r135-bbn-env/bin/pip install --require-hashes --only-binary=:all: -r requirements.lock
git clone https://github.com/cgiovanetti/LINX.git /tmp/r135-LINX
git -C /tmp/r135-LINX checkout bfba07c77a5fcba1cc772d42f2d9e9be8a542df8
git clone https://github.com/CyrilPitrou/primat.git /tmp/r135-primat
git -C /tmp/r135-primat checkout 6f7e5680614fb119d65a6c9c65a292240b27c61e
git clone https://github.com/lesgourg/class_public.git /tmp/r135-CLASS
git -C /tmp/r135-CLASS checkout e85808324f51fc694d12e3ed7439552a3c3f9540
make -C /tmp/r135-CLASS -j2 class
```

Planck использует собственные уже закреплённые
[инструкции установки](../planck_pr3/README.md). Его NumPy lock отличается от
BBN. Параметры `planck_python` и `planck_python_sha256` включают фиксированный
процесс `python -m r135.likelihood --worker …`; командная оболочка не применяется.
Все спектры и результаты связаны хешами, данные likelihood загружаются один раз
для целой пачки. Это сохраняет обе исходные проверенные среды.

Обычные испытания работают с базовыми NumPy/SciPy и `unittest`. Для фактической
проверки установленных библиотек из корня репозитория:

```sh
S=analysis/R135_PHYSICAL_SECTOR_X_20261120/full_run/software
R135_NATIVE_TESTS=1 R135_CLASS_ROOT=/tmp/r135-CLASS \
  PYTHONPATH=/tmp/r135-LINX:/tmp/r135-primat OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  /tmp/r135-bbn-env/bin/python -m unittest discover -s "$S/tests" -p test_backends.py -v
R135_PLANCK_ROOT=/path/to/extracted-release \
  R135_PLANCK_THEORY=/path/to/COM_PowerSpect_CMB-base-plikHM-TTTEEE-lowl-lowE-lensing-minimum-theory_R3.01.txt \
  OPENBLAS_NUM_THREADS=1 /path/to/pinned-planck-env/bin/python \
  -m unittest discover -s "$S/tests" -p test_likelihood.py -v
```

Полное испытание связки P8→P9 с 30 настоящими интегрированиями, 10 CLASS и полной
Planck-функцией использует **искусственный программный контроль**, не физический
прогон X:

```sh
PYTHONPATH=/tmp/r135-LINX:/tmp/r135-primat OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  /tmp/r135-bbn-env/bin/python "$S/backend/validate_native.py" \
  --class-source /tmp/r135-CLASS --planck-root /path/to/extracted-release \
  --planck-python /path/to/pinned-planck-env/bin/python --out /tmp/r135-adapter-validation
```

Искусственный контроль имеет заданные начальные D/He и нулевые ядерные таблицы.
Он нужен для проверки передачи файлов, реального чтения таблиц, нормировок,
смешанного остатка и связи со спектром/likelihood. Его обилия не являются
прогнозом R135. Фактические команды и результаты разработки записаны в
[VALIDATION.json](VALIDATION.json).

## Что код сознательно не объявляет решённым

`backends.capabilities()` отдельно перечисляет реализованные методы, требуемые
физические входы и отсутствующие общие физические модули. Последующая
[доработка](../EXTENSIONS.md) добавляет собственные Born-интегралы произвольных
ν-спектров в P8 и проверяемое сопоставление с CLASS ETHOS IDM–IDR в P8/P9.
Отдельный модуль ACROPOLIS вычисляет позднюю фотодиссоциацию на фоне P7;
автоматическая передача его состава/ковариации в общий likelihood ещё открыта.
Точностные поправки слабых скоростей для произвольного спектра, полный
адронный транспорт и возмущения вне выбранного семейства ETHOS
**не реализованы этим адаптером**. При их необходимости расчёт останавливается
с точной причиной либо принимает проверяемый внешний вычисленный результат.
Неизвестные физические коэффициенты, ковариации и пороги не назначаются из
удобства прохождения проверки. Физический прогон R135 этими проверками не начат.
