**Ориентир при готовой среде: 1–3 минуты, 2 GiB RAM и 1 GiB дополнительного
свободного диска.** Это инженерный запас для указанного ниже состава,
не таймер остановки и не оценка полного физического R135.

## Фактический результат

Один полный диагностический запуск завершился успешно за **64,528 с**.
Пик суммарного RSS одновременно живых процессов — **630,207 MiB**;
PSS — **624,541 MiB**. Созданы 290 файлов общим объёмом
**276 411 137 байт = 263,606 MiB**. Исходники во время замера не менялись.

| Часть | Фиксированный состав | Время | Пик RSS группы |
|---|---|---:|---:|
| P0 | Заморозка и проверка реестра | 0,160 с | 11,7 MiB |
| P3 | Одна холодная цепь 4 × 8³, два sweep, 16 384 обновления; измерение, gauge-проверка, checkpoint и восстановление | 1,760 с | 37,3 MiB |
| P7 | Пять историй из `coupled_control.json`, горизонт 10 H0⁻¹, 4097 точек | 28,189 с | 291,3 MiB |
| P8/P9 | Существующий искусственный контроль: 30 BBN, 10 CLASS, 10 полных Planck | 34,159 с | 630,2 MiB |
| Служебные команды P7 | Привязка запроса и проверка выходного манифеста | 0,257 с | 13,9 MiB |

Итоговое время включает запуск процессов, работу команд и наблюдение за памятью.
Время установки среды, скачивания файлов и публикации исключено. Пики
последовательных фаз берутся по максимуму, а не складываются.

Наблюдатель каждые 50 мс суммирует RSS и, где доступна, PSS всей отдельной группы
процессов. В группе учитываются Python и его CLASS/Planck-потомки; сам наблюдатель
исключён. RSS может повторно учитывать общие страницы. Краткий пик между отсчётами
может быть пропущен; поэтому 630 MiB не назначены жёстким пределом памяти.
Первичные ряды памяти и журналы каждой команды сохранены в `smoke_reference`.

## Сопоставимость среды

Измерение выполнено на **текущей среде Intel Xeon Platinum 8573C**, Python 3.12.14.
Численные зависимости и потоки выбраны как в последнем исполненном GitHub-прогоне
44719756079: NumPy 2.2.6, SciPy 1.15.3, JAX/jaxlib 0.4.38, Diffrax 0.7.1,
`OMP_NUM_THREADS=2`, `OPENBLAS_NUM_THREADS=1`, JAX CPU/x64.

У последнего GitHub-исполнителя Python 3.12.16, но CPU/RAM/квота не записаны.
Поэтому **64,528 с — измерение текущей машины**, а ориентир 1–3 минуты для
повтора на GitHub остаётся предварительным до исполнения той же команды там.
Установленные среды, данные Planck и файловый кэш уже существовали. Их объём
не входит в дополнительный 1 GiB для результатов. Холодная установка не измерялась.

2 GiB RAM дают более трёхкратного запаса к наблюдавшемуся суммарному RSS;
1 GiB свободного диска — более трёхкратного запаса к созданным файлам.
Диапазон времени учитывает запуск, кэш и нагрузку; он не является статистическим
доверительным интервалом из серии повторов.

## Повтор

Работать из checkout с уже установленными закреплёнными решателями, описанными
в [backend/BACKENDS.md](../backend/BACKENDS.md). Пути задаются явно:

```sh
python analysis/R135_PHYSICAL_SECTOR_X_20261120/full_run/software/runtime_gate/smoke_resources.py \
  --python /path/to/native-env/bin/python \
  --linx-source /path/to/LINX \
  --primat-source /path/to/primat \
  --class-source /path/to/class \
  --planck-root /path/to/planck-data \
  --planck-python /path/to/planck-env/bin/python \
  --out /path/to/new-smoke-output
```

Новая папка результата обязательна; старые свидетельства сохраняются.
Скрипт фиксирует команды, CPU/wall time, память, версии, SHA исходников и статус.
Код измерения появился поверх `363bd8c`; точный хеш исполнявшегося файла сохранён
в `RESOURCES.json`. Этот базовый SHA не выдаётся за коммит нового файла.

## Область результата

P7 и наблюдательный контроль используют отдельные заданные диагностические входы.
В BBN-контроле ядерные скорости нулевые, начальные D/He назначены. Профилирование
nuisance и серия уточнений CLASS в этот состав не входят.

Два sweep маленькой SU(3)-цепи проверяют исполнение и сохранение состояния;
они не измеряют равновесие, автокорреляцию или скорость production-решёток.
Этот запуск **не выполняет** пилот из 16 цепей по 2048 циклов и не закрывает
[временной гейт полного R135](README.md). Физический прогон не запускался.
