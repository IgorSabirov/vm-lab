# Сохранение научной рабочей области ВМ

Подготовлен host-публикатор [publish_now_workspace_v01.py](../../infra/publish_now_workspace_v01.py). Он использует существующий транспорт `/etc/vm-lab-sync/config.json` исключительно для `IgorSabirov/vm-lab`, ветка main. Запуск не является научным прогоном или приёмкой результатов.

Одна команда в SSH на ВМ:

```bash
sudo systemd-run --unit=now-workspace-publish-v01 --collect /usr/bin/python3 -I -u /var/lib/vm-compute/work/code/publish_now_workspace_v01.py --max-gib 5
```

Статус:

```bash
sudo journalctl -u now-workspace-publish-v01 -n 25 --no-pager
```

Разрыв SSH не останавливает systemd-службу. Повтор той же команды после завершения/сбоя продолжает сохранённую публикацию. Пока служба работает, второй запуск не нужен. Для другого будущего снимка существует явный флаг `--new-snapshot`.

## Объём и формат

Снимок охватывает `code/`, `data/`, `results/`, `jobs/` под `/var/lib/vm-compute/work`. Сохраняются исходные байты исходников, входов, отчётов, численных массивов, трасс, квитанций, контрольных точек и журналов. Уже имеющиеся архивы не создаются заново. Нового сжатия нет; Git использует собственный внутренний формат объектов.

Предел выбранных исходных файлов — 5 GiB; флаг `--max-gib` принимает 1–5. Это лимит данного снимка, не оценка общего размера истории репозитория. При превышении сохраняется явный список `capacity_limit`; статус не будет COMPLETE. Публикатор работает временными порциями около 128–176 MiB, удаляет только собственную временную staging-копию после push и оставляет исходники ВМ нетронутыми. При недостатке свободного места останавливается с возможностью повторного запуска.

Файлы до 48 MiB лежат как обычные файлы. Более крупные делятся на последовательные несжатые части; манифест содержит исходный путь, размер, SHA-256 целого и частей, смещения и Git blob ID. Восстановление: [restore_now_workspace_v01.py](../../infra/restore_now_workspace_v01.py), из локальной копии опубликованного снимка в новый каталог, с проверкой всех хешей.

Путь GitHub: `results/VM_WORKSPACE_SNAPSHOTS/<timestamp_id>/`. Каждый push содержит очередные файлы и актуальный MANIFEST.json. Перемещение main — только обычное fast-forward, с повторным чтением головы при конфликте; чужие файлы не удаляются. После push проверяется опубликованная ссылка. Технический статус экспорта не повышает научные статусы.

## Пропуски и границы

Не экспортируются ОС, домашние каталоги, конфигурация транспорта, ключи, скрытые каталоги, виртуальные среды и воспроизводимые кэши. Проверяются имена и распространённые сигнатуры секретов в обычных файлах и содержимом поддерживаемых архивов. Вложенные/неподдерживаемые архивы и файлы, изменившиеся после инвентаризации, откладываются с причиной; секретные значения не пишутся в манифест. Сканер консервативен, не является доказательством отсутствия любых неизвестных секретов. Источники не редактируются и не удаляются.

`COMPLETE`/`COMPLETE_WITH_EXCLUSIONS` означает завершение выбранного снимка с опубликованным перечнем исключений. `PARTIAL_REQUIRES_ATTENTION` означает отложенные файлы, недоступные корни или превышение лимита. По отсутствию ошибок в SSH нельзя объявлять весь экспорт законченным: смотреть финальный статус и манифест.

Транспортные ошибки сохраняются только на хосте в закрытом каталоге `/var/lib/vm-compute/publication/now-workspace-v01/`; они не отправляются в репозиторий, поскольку stderr может содержать детали доступа. Состояние возобновления хранится там же.

Доступный MCP-исполнитель не имеет сети, SSH и sudo. Он не может исполнить host-push; поэтому подготовка скрипта в code/ и публикация его исходника не означают, что массивы уже отправлены. Команда выше запускает именно недостающую host-стадию.
