## 1. Вердикт

Обе пары чисел воспроизведены независимой десятичной арифметикой с 50 знаками. В отзыве вычислены режимы **абсолютных** изменений a₀, эквивалентные абсолютным изменениям сечений с общим множителем 4π. Раздел 3 исходного отчёта определяет x_p=δlnσ_p и x_n=δlnσ_n: это **относительные/логарифмические** изменения. Именно их считает опубликованный verifier.

Следовательно, обнаружено несовпадение вычисляемых величин, а не ошибка чисел 1.410647/0.100377. Утверждение «сжатие неопределённости отношения ×8.92» не следует из абсолютной разности сечений.

## 2. Прямая арифметика для 112.2 keV

Элементы Table V в порядке (p,n):

\[
A=0.0046104,\quad B=0.0053203,\quad C=0.0049029.
\]

Средние интегральные сечения: μ_p=19.77 mb, μ_n=21.07 mb. Для исходной абсолютной ковариации сумма диагоналей S=A+B=0.0099307 — в точности число, приведённое в отзыве.

Для u_±=(x_p±x_n)/2 отношение стандартных отклонений полной модели к независимой при тех же маргиналах:

\[
r_\pm=\sqrt{1\pm\frac{2C_{pn}}{C_{pp}+C_{nn}}}.
\]

Выбор координат определяет, какую матрицу следует подставить:

| Координаты | C_pp, C_nn, C_pn с опущенным общим множителем | r₊ | r₋ | 1/r₋ |
|---|---|---:|---:|---:|
| Абсолютные a₀ или σ | A, B, C | 1.409759852 | 0.112147937 | 8.91679356 |
| Относительные / δlnσ | A/μ_p², B/μ_n², C/(μ_p μ_n) | 1.410646811 | 0.100377160 | 9.96242573 |

Во второй строке общий (4π)² опущен **во всех трёх элементах**, поэтому он сокращается в r_±. Это не приближённая замена одной матрицы другой: используется якобиан логарифма в линейном распространении ошибок,

\[
C_{\ln\sigma}=\operatorname{diag}(1/\mu)\,C_\sigma\,\operatorname{diag}(1/\mu).
\]

В опубликованном [verify_connection.py](https://github.com/IgorSabirov/vm-lab/blob/dc393897eb63886ab330545959e9cdae9a90fd11/analysis/CCC_BBN_NETWORK_20261114/s3_standard/bh_covariance_20261115/verify_connection.py#L47) это строка `log_cov = cov / np.outer(mu, mu)`. Далее и диагонали, и межканальный элемент берутся из log_cov. Поэтому S=0.0099307 нельзя использовать для воспроизведения логарифмических режимов.

Для проверки без NumPy достаточно:

```python
from decimal import Decimal as D, localcontext
with localcontext() as c:
    c.prec = 50
    A, B, C = D('.0046104'), D('.0053203'), D('.0049029')
    p, n = D('19.77'), D('21.07')
    q = 2 * C / (p*n) / (A/p**2 + B/n**2)
    print((1+q).sqrt(), (1-q).sqrt())
```

Коэффициент корреляции ρ=C/√(AB)=0.989955496 сохраняется при переходе к относительным координатам. Однако число, входящее в r_±, равно

\[
\rho_{eff}=\frac{2\rho s_ps_n}{s_p^2+s_n^2}\le\rho.
\]

Оно составляет 0.987422840 для абсолютных координат и 0.989924426 для логарифмических. Значение 0.9926 из отзыва не воспроизводится. Во втором случае относительные ошибки двух каналов ближе друг к другу, поэтому разность сильнее подавляется. Около ρ_eff≈1 малая абсолютная разница в ρ_eff даёт заметное относительное изменение малого r₋.

## 3. Что означает «примерно в десять раз»

Это уменьшение стандартного отклонения **логарифма отношения двух сечений на одном лабораторном энергетическом узле**, в линейном приближении и без дополнительного 1% масштаба. Оно не является уменьшением неопределённости D/H или отношения термоядерных скоростей. Для последних нужны энергетическое интегрирование и совместный posterior функций.

Раздел 3 основного отчёта дополнен явной таблицей двух координат, чтобы абсолютную разность нельзя было спутать с логарифмом отношения. Исходные численные результаты не заменяются.

## 4. Дополнительно проверены a и b из S_eta

Открыты исходные завершённые ETA_LOW/ETA_HIGH RESULT.json, их ETA_INPUTS и RESPONSE.json; SHA256 всех пяти файлов сверены с закреплённым ARTIFACTS.json. Сверен также SHA ранее опубликованного S3 RESULT.json. Нового BBN-прогона не было.

| Величина | ETA_LOW | ETA_HIGH |
|---|---:|---:|
| η | 6.076064184041776×10⁻¹⁰ | 6.198812955436560×10⁻¹⁰ |
| Y_p | 0.2469048322712782 | 0.24709761486465803 |
| D/H | 2.4771090869576702×10⁻⁵ | 2.3970956799209610×10⁻⁵ |

При Y_p,0=0.24700178588830685 использованная оценка имеет вид:

\[
a=Y_{p,0}\frac{\ln(Y_{p,+}/Y_{p,-})}{\ln(\eta_+/\eta_-)},\qquad
b=\frac{\ln[(D/H)_+/(D/H)_-]}{\ln(\eta_+/\eta_-)}.
\]

Независимый пересчёт даёт a=0.00963883078901442 и b=−1.64166118983211031. Отличия от опубликованных чисел — соответственно 7.77×10⁻¹⁶ и 1.56×10⁻¹⁴. Это воспроизведение арифметики по сохранённым выходам, не подтверждение сходимости производной.

Важная конвенция: a получено умножением логарифмической секущей на baseline. Прямая секущая (Y_p,+−Y_p,−)/Δlnη равна 0.00963880835610059 и немного отличается на конечном интервале ±1%. Эти оценки не следует молча отождествлять. В исходном S3 использована первая; она теперь указана явно.

В отзыве также есть знаковая опечатка: отрицательный коэффициент при δlnN_eff,ν в R_D равен **+(3/4)b**, не −(3/4)b. Число −1.23124589 и исходное тождество верны.

## 5. Воспроизводимость и статус

[verify_coordinates.py](verify_coordinates.py) использует только стандартную библиотеку Python, не импортирует исходный verifier и не использует NumPy. Он воспроизводит обе спорные пары и чувствительности S_eta. [REVIEW_CHECKS.json](REVIEW_CHECKS.json) сохраняет входные SHA, промежуточные величины и фактическое время. Его 50 десятичных знаков относятся к проверке арифметики, не к точности экспериментальных данных.

Исходный опубликованный verifier также запущен на скачанных с GitHub входах: весь содержательный вывод совпал с исходным CHECKS.json; различается только время выполнения.

Результат разбора: замечание о невоспроизводимости исходных чисел снято этим воспроизведением; различие координат документировано. Никакой физической приёмки BH1, продвижения R/C/L/U, изменения порогов, очереди или новых научных запусков из этого не следует.
