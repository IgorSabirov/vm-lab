## 1. Вопрос исследования

Нужно измерить, насколько межканальная корреляция двух приоритетных D+D неопределённостей меняет неопределённость выходов стандартного BBN при одинаковых маргинальных распределениях параметров:

- (d+d\rightarrow{}^3\!He+n), LINX channel `ddHe3n`;
- (d+d\rightarrow t+p), LINX channel `ddtp`.

На этом этапе цель **не** состоит в определении физического значения корреляции `rho`. Цель — вычислить локальные отклики выходов BBN на каждый из двух параметров и получить условную зависимость коррелированного/независимого результата как функцию `rho`.

## 2. Физико-математическая постановка

### 2.1 Что означает параметр LINX

В закреплённом LINX upstream commit `bfba07c77a5fcba1cc772d42f2d9e9be8a542df8` неопределённость табличной скорости задаётся третьим столбцом `expsigma`. Для реакции (i):

[
r_i(T,q_i)=\mu_i(T)\exp\left[q_i\ln f_i(T)\right],
\qquad f_i(T)=\mathrm{expsigma}_i(T),
\qquad q_i\sim\mathcal N(0,1).
]

Это не независимый случайный draw в каждой температурной точке. Для каждого канала используется **один скалярный** (q_i), общий для всей закреплённой температурной таблицы. Поэтому модель заранее задаёт особую температурную структуру неопределённости: изменение формы скорости вдоль (T) пропорционально одной функции (\ln f_i(T)).

Если (\operatorname{Cov}(q_1,q_2)=\rho), то межканальная температурная ковариация имеет ограниченный вид

[
\operatorname{Cov}[\ln r_1(T),\ln r_2(T')]
=\rho\,\ln f_1(T)\,\ln f_2(T').
]

Это двухпараметрическая редукция, а не полная ковариационная модель двух экспериментальных (S)-факторов. Реальная совместная лабораторная posterior/covariance могла бы содержать дополнительные температурные моды и общие систематики. Их этот пакет не восстанавливает.

Источники реализации и таблиц:
- [LINX `reactions.py` на закреплённом commit](https://github.com/cgiovanetti/LINX/blob/bfba07c77a5fcba1cc772d42f2d9e9be8a542df8/linx/reactions.py)
- [PRIMAT 2023: `ddHe3n`](https://github.com/cgiovanetti/LINX/blob/bfba07c77a5fcba1cc772d42f2d9e9be8a542df8/linx/data/nuclear_rates/key_PRIMAT_2023/ddHe3n.txt)
- [PRIMAT 2023: `ddtp`](https://github.com/cgiovanetti/LINX/blob/bfba07c77a5fcba1cc772d42f2d9e9be8a542df8/linx/data/nuclear_rates/key_PRIMAT_2023/ddtp.txt)

### 2.2 Сравнение коррелированного и независимого случаев

Пусть (q=(q_1,q_2)^T), а маргинальные дисперсии обеих координат равны единице. Сравниваются

[
R(\rho)=
\begin{pmatrix}1&\rho\\\rho&1\end{pmatrix},
\qquad -1\leq\rho\leq1,
]

и (R(0)=I). (R(0)) — **контрольный независимый вариант с теми же маргиналами**, а не утверждение, что физические ядерные ошибки независимы. В закреплённом аудите для (\rho) нет измеренного значения или posterior; поэтому (\rho) остаётся параметром.

Для положительной наблюдаемой (O) определим локальные отклики

[
a_i(O)=
\left.\frac{\partial\ln O}{\partial q_i}\right|_{q=0}.
]

В первом порядке

[
\ln O(q)\simeq\ln O(0)+a^Tq,
\]

откуда по delta method

[
\operatorname{Var}_{\rho}(\ln O)
\simeq a^TR(\rho)a
=a_1^2+a_2^2+2\rho a_1a_2.
]

Для независимого контроля (\operatorname{Var}_{0}(\ln O)\simeq a_1^2+a_2^2). При ненулевом отклике вводится

[
\kappa(O)=\frac{2a_1a_2}{a_1^2+a_2^2},
\qquad
\frac{\sigma_{\rho}(\ln O)}{\sigma_0(\ln O)}
\simeq\sqrt{1+\kappa\rho}.
]

Из (2|a_1a_2|\leq a_1^2+a_2^2) следует (-1\leq\kappa\leq1). При ненулевых откликах (\kappa=1) тогда и только тогда, когда (a_1=a_2), а (\kappa=-1) — когда (a_1=-a_2). Если оба отклика нулевые, (\kappa) не определена и должна маркироваться как нулевой отклик, а не как число.

**Ограничение интерпретации:** формула — результат локальной линейной аппроксимации для (\ln O). Она не равна точной ковариации нелинейных выходов BBN при широком распределении (q), не заменяет correlated Monte Carlo и не измеряет (\rho).

### 2.3 Масштабная ловушка

(\kappa) не меняется при общем масштабировании (a_1,a_2\mapsto c(a_1,a_2)). Поэтому (\kappa\simeq1) не означает, что абсолютный вклад D+D велик. Для каждого выхода обязательно сохранять и

[
V_{\mathrm{ind}}^{\ln O}=a_1^2+a_2^2,
]

и коррелированную квадратичную форму (a^TR(\rho)a). Особенно важно это для (Y_p): малость абсолютного отклика нельзя доказывать отношением стандартных отклонений, близким к единице.

### 2.4 Знаки — гипотезы о сетевом отклике, не теоремы из стехиометрии

Оба прямых D+D канала расходуют дейтерий, поэтому для (D/H) заранее ожидаются (a_1<0), (a_2<0). При положительном (\rho) это означало бы увеличение локализованной дисперсии (D/H). Но обратные реакции и потоки через остальную сеть означают, что окончательный знак должен быть измерен на полной сети; одна стехиометрия прямого канала не доказывает знак производной выхода.

Для поздних (^{3}\mathrm{He}/H) и (^{7}\mathrm{Li}/H) положительные знаки — только направленные ожидания: прямое образование (^{3}\mathrm{He}), распад трития и потоки через T/(^{3}\mathrm{He}) в (^{7}\mathrm{Be}) конкурируют с другими реакциями. Сетевой отклик может изменить знак. Для (Y_p) знак не пререгистрируется.

## 3. Предлагаемая вычислительная матрица

Пакет `S3_DD_RESPONSE_20261115_r1` содержит девять интеграций:

| Интеграция | (q_{ddHe3n}) | (q_{ddtp}) | Все остальные (q) |
|---|---:|---:|---:|
| Run 0: native baseline | 0 | 0 | 0 |
| Runs 1–4: отклик `ddHe3n` | (-1,+1,-0.5,+0.5) | 0 | 0 |
| Runs 5–8: отклик `ddtp` | 0 | (-1,+1,-0.5,+0.5) | 0 |

Центральная разность для шага (h):

[
a_i(O;h)=
\frac{\ln O(q_i=+h)-\ln O(q_i=-h)}{2h},
\qquad h\in\{1,0.5\}.
]

Run 0 — обязательный baseline с (q=0) **для всех активных реакций**. Его нельзя подменять более ранней парой native/override из `LINX_BBN_IDENTITY_20261115_r3`: в той паре D+D координаты были нулевыми, но десять остальных реакций имели ненулевые контрольные (q). Та пара проверяла тождество реализации адаптера при другом векторе входов, а не центральную точку новой чувствительности.

Все девять интеграций должны использовать один и тот же фон, начальное состояние, (\eta), время жизни нейтрона, weak rates, сеть, температурный интервал, solver, допуски, dtype и pinned upstream tables. Run 0 записывает фактическое wall time; прогноз оставшихся восьми интеграций фиксируется **до** запуска perturbation arms.

### 3.1 Наблюдаемые выходы

Для порядка частиц LINX `(n,p,d,t,He3,He4,Li7,Be7)` контракт задаёт:

- (D/H=Y_d/Y_H);
- (Y_p=4Y_{^4He});
- позднее (^{3}He/H=(Y_{^3He}+Y_t)/Y_H), учитывая последующий распад трития;
- позднее (^{7}Li/H=(Y_{^7Li}+Y_{^7Be})/Y_H), учитывая последующий переход (^{7}Be\to{}^{7}Li).

В контракте обозначение знаменателя записано как `Y_p`; в итоговом отчёте его следует показывать как (Y_H), чтобы не путать число свободных протонов с обычным обозначением массовой доли первичного гелия (Y_p).

### 3.2 Проверка шагов

Сравнение (a_i(h=1)) и (a_i(h=0.5)) с относительным порогом 1% — только первичная проверка согласия двух конечных шагов. При обоих откликах ниже заранее заданного абсолютного порога (10^{-8}) результат должен маркироваться `NEAR_ZERO_RESPONSE`, а не оцениваться делением на практически ноль.

Даже прохождение этого критерия **не доказывает асимптотическую сходимость производной**: два шага могут иметь близкое смещение. Для строгого численного исследования понадобится отдельный заранее допущенный шаг/контроль, но пакет не должен автоматически запускать (h=0.25) или менять критерии после просмотра данных.

Поэтому корректная формулировка: **raw outputs двух завершённых arms дают точное совпадение по проверенным полям; опубликованный workflow summary остался FAIL**. Это не следует переименовывать в научный PASS S3. Сравнение выполняется по [ARTIFACTS.json](https://github.com/IgorSabirov/vm-lab/blob/b24c7e0cc47ff964d576f903ce7ba507d2dd731e/analysis/CCC_BBN_NETWORK_20261114/s3_standard/linx_dd_adapter_20261115/full_run_20261115/results/LINX_BBN_IDENTITY_20261115_r3/ARTIFACTS.json) и двум raw [RESULT.json native](https://github.com/IgorSabirov/vm-lab/blob/b24c7e0cc47ff964d576f903ce7ba507d2dd731e/analysis/CCC_BBN_NETWORK_20261114/s3_standard/linx_dd_adapter_20261115/full_run_20261115/results/LINX_BBN_IDENTITY_20261115_r3/native/RESULT.json) / [RESULT.json override](https://github.com/IgorSabirov/vm-lab/blob/b24c7e0cc47ff964d576f903ce7ba507d2dd731e/analysis/CCC_BBN_NETWORK_20261114/s3_standard/linx_dd_adapter_20261115/full_run_20261115/results/LINX_BBN_IDENTITY_20261115_r3/override/RESULT.json).

### 4.2 Почему identity-пара не закрывает D+D response

В `r3` у двух D+D каналов (q=0), но у десяти других активных реакций вектор (q) был ненулевым:
[
(-0.1,0.15,0,0,-0.05,0.1,0.2,-0.1,0.05,-0.15,-0.05,0.1).
]
Поэтому эти результаты проверяют передачу таблиц адаптером в заданной точке, а не локальную производную новой модели при (q=0) всех каналов. Для исходного пакета требовался новый Run 0; он уже выполнен и опубликован на 1ce668ca. Его фон и baseline переиспользованы для восьми меньших шагов.

### 4.3 Полученные отклики и оставшиеся границы

Девять интеграций h=1/0.5 опубликованы на 1ce668ca; восемь интеграций h=.25/.125 — в [текущем отчёте](refinement_20261116/REPORT.md). Получены a_i, κ, шаговые диагностики и условные rho-таблицы. Положительная знаковая гипотеза He3/ddtp противоречит вычисленным откликам. Научная приёмка остаётся false.

Correlated Monte Carlo, GP posterior и физическое rho не получены; observational likelihood, CMB, BH1 и S2 не входят в эти пакеты. Ни арифметическая репликация, ни Ричардсон не заменяют оценки ошибки решателя.

## 6. Исторический статус до первого запуска — снимок f7b6060

При чтении фактического tree на commit `f7b6060...` обнаружены следующие несоответствия. Они внесены сюда намеренно: наличие `RUN_REQUEST.json` с `execution_enabled=true` само по себе не доказывает, что пакет можно безопасно отправить.

1. `INPUT_MANIFEST.json` перечисляет `.github/workflows/s3-dd-covariance.yml`, но этого файла нет в tree ветки. Отдельный workflow не создан. Поле `trigger` в request описывает ожидаемый PR-ивент, но само по себе workflow не запускает.
2. `RUN_REQUEST.json` и `PACKAGE.json`/ `EXECUTION_PLAN.json` описывают публикацию в `science/autonomous-bbn-identity-v4-20261115`, тогда как пакет лежит в `science/autonomous-dd-covariance-20261115`. Это может быть задумано как merge-trigger, но PR/trigger wiring ещё не создано; текущая ветка не является целью публикации.
3. SHA-256 значения в собственном `INPUT_MANIFEST.json`, а также `input_manifest.sha256` и `acceptance.sha256` в `EXECUTION_PLAN.json`, не прошли независимую проверку по байтам в этой ревизии. В частности, SHA runner был внесён отдельным ручным значением, а не получен из воспроизводимой процедуры хеширования. До dispatch все такие значения необходимо пересчитать и проверить строгим validator на точном frozen commit.
4. `verify_math.py` присутствует, но не запускался. В этой ветке нет подтверждённого package-level CI результата, который проверяет schema, манифест, runner, worker и execution plan как единое целое.
5. В `ADAPTER_CONTRACT.json` указан путь будущего `ADAPTER_IDENTITY_RECOVERY.json`; сам receipt в текущем tree ещё не создан. Raw evidence можно проверить по manifest, но этот формальный receipt остаётся будущей работой runner.
6. Перед исполнением требуется проверить, что общий ledger и полный live Actions inventory не содержат активного compute-пакета, а затем получить свежую CAS admission. Эта проверка в рамках сохранения данного отчёта не выполнялась.

**Вывод по готовности:** научный дизайн локального отклика сформулирован; текущая реализация пакета — подготовительный draft. Сейчас нельзя утверждать, что он dispatch-ready. Исправление wiring/manifest/validator — инженерный gate перед расчётом, а не причина возвращать требование завершённого Monte Carlo к входным условиям.

## 7. Границы исходного дизайна и полученного результата

Исходный дизайн предусматривал следующие выходы; они теперь получены в опубликованных raw и SUMMARY, с указанными в текущем отчёте численными ограничениями:

- (a_i(O;h=1)) и (a_i(O;h=0.5)) для четырёх выходов;
- step discrepancy и диагностика near-zero;
- (\kappa(O)), (a^Ta), (a^TR(\rho)a) и таблица отношения стандартных отклонений как функции (\rho);
- SHA и provenance фактических upstream таблиц, исходного кода и результатов.

Это **локальная двухкоординатная чувствительность стандартной BBN**, не полная физическая covariance всех ядерных реакций. Для полной S3 позже понадобятся обоснованный совместный rate posterior, прочие ядерные/weak неопределённости, independent CMB likelihood, observational covariance и проверка delta method против correlated Monte Carlo. Ни один из этих будущих этапов не следует объявлять выполненным данным пакетом.
