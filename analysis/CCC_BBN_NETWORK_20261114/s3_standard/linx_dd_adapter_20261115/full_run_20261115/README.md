# Полная BBN-пара — пакет r3 (исполнитель v4)

Поручение владельца: запустить на GitHub после реестровой сверки #71. Рабочая
запись #72. Родители: #54 и #57; source commit связывается через RUN_REQUEST.

Матрица: один заранее объявленный coarse full-route calibration (rtol=1e-4,
atol=1e-6), затем два строгих BBN-arm исходного контракта (rtol=1e-6,
atol=1e-9). Строгие входы, species, интерполяция, q, фон и критерий тождества
сохранены. Калибровка отдельна и не используется как strict native результат.
Всего не более трёх интеграций, без повторов. GP/MC и новая физика отсутствуют.

Точный source SHA замораживается до калибровки. До неё резервируется один пакет
через существующий admit.reserve/CAS на опорной ветке. Только после измерения
на hosted runner создаются EXECUTION_PLAN и STRICT_ADMITTED. Прогноз: 3× время
coarse-процесса на каждый strict arm, минимум 60 s; запас — инженерный, не
оценка сходимости. Прогноз за пределами заранее заданных caps останавливает
пакет. Свидетельства допуска публикуются до strict; научная приёмка false.

Бюджет всего job 9900 s (165 min), калибровка ≤600 s, каждый strict process
≤3600 s, один процесс одновременно, суммарно ≤4 GiB, выходы ≤2 GiB. Это
конечные caps данного пакета, не восстановление общих 5400/2400. Суточной
квоты нет. GitHub выбран прямо владельцем. Контроллер, pip и материализация
также ограничены; запас включает подготовку, проверку и публикацию.

Исходный v1 на PR #57 сохраняется. В новом worker изменён только допуск и
добавлен явно маркированный калибровочный режим; numerical body строгих arm
сохранён. Verifier compare переиспользован без изменения критериев.
Контроллер не исправляет upstream и не перезапускает упавшие процессы.
Итог публикует численный PASS/FAIL реализации отдельно от scientific_acceptance.
Это предпосылка S3, не выполненный S3 posterior или эмерджентность шести моделей.

## Исправление материализации по прямому поручению «Исправь и запусти»

PR #74 / run 43742136639 завершился до калибровки с `KeyError: size`:
закреплённый LICENSE.txt имеет SHA-256, но не имеет необязательного размера.
Новый пакет r3 наследует сохранённый FAIL (ba157c8bd07d76760b4a4b87a48eeb13368e7821).
Материализатор всегда требует точное совпадение SHA-256 и дополнительно проверяет
размер, когда тот указан. Манифест upstream, его SHA и recorded patch неизменны.
Регрессия проверяет отсутствие size, изменённые байты, неверный size и отсутствие
SHA-256. Полная подготовка всех 38 файлов и патча проверяется до dispatch;
это проверка доставки входов, не BBN-вычисление или калибровка.
Фактические проверки зафиксированы в PRELAUNCH_CHECKS.json.
