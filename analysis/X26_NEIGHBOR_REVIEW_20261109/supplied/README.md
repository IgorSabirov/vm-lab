# X26 — локальный патч ADD–Fano–BIC

## Назначение

Пакет разделяет два уровня, которые нельзя смешивать:

- **X26-A** — исполняемая двухмодовая контрольная модель Friedrich–Wintgen BIC. Она показывает алгебру общего континуума, тёмного вектора, собственного состояния внутри континуума и отрицательных контролей.
- **X26-B** — граница будущего ADD-derived подъёма. В местах, где нет исходного кода, физического отображения, гамильтониана, континуума или взаимодействия, стоят явные заглушки `BLOCKED_MISSING` / `NotImplementedError`.

**X26-A не является результатом ADD.** В ней `Hd` и `W0` задаются вручную; в tuned control `Hd` специально строится так, чтобы ядро `W0` было его собственным вектором. Поэтому успешный BIC в этой модели — контроль корректности математического решателя, а не свидетельство того, что ADD порождает такую структуру.

## Зависимость

- Python 3.10+
- NumPy 1.24+

Установка зависимости при необходимости:

```bash
python -m pip install -r requirements.txt
```

## Запуск

Из каталога пакета:

```bash
python run_x26.py --out x26_report.json
python -m unittest -v test_x26.py
```

Отдельно:

```bash
python x26_core.py
python add_adapter.py
```

## Математическая конвенция

Континуум энергетически нормирован. Для двух внутренних мод и `M` открытых каналов:

\[
W_{\mu c}(E)=\langle E,\mu|V|d_c\rangle,
\qquad A(E)=W(E)d,
\]

\[
\Gamma(E)=2\pi W^\dagger(E)W(E),
\qquad
H_{\rm eff}(E)=H_d+\Delta(E)-\frac{i}{2}\Gamma(E).
\]

Для плоской полосы `[Emin,Emax]` и постоянной по энергии матрицы `W0`:

\[
\Delta(E)=W_0^\dagger W_0\log\frac{E-E_{\min}}{E_{\max}-E},
\quad E\in(E_{\min},E_{\max}).
\]

Тёмный вектор — `d` из `ker(W0)`. BIC в toy-модели засчитывается, только если энергия внутри континуума, тёмный вектор является собственным вектором `Hd + Delta`, ширина равна нулю в допуске, а континуальная компонента нормируема. В используемой плоской факторизованной модели `W(E')d=0` на всей полосе, поэтому континуальная компонента тождественно нулевая.

## Состав X26-A

- `T1`: ранг `W` и ядро. Важная оговорка: при `M=1` и двух модах `rank(W)<2` следует из размерности автоматически. Это только sanity check, не физическое свидетельство общего канала в ADD.
- `T2`: собственное состояние внутренней динамики.
- `T3`: энергия внутри континуума, нулевая ширина и нормируемость полного toy-состояния.
- `T4`: три класса параметрических возмущений: сохранение ранга 1 (масштабирование общей связи), внутренняя расстройка и добавление различимого which-path канала. Рассчитывается лог-лог наклон, но **не** выводится класс защиты.
- `T5`: статическая загрузка. Для точной тёмной моды, полностью развязанной от входного континуума, загрузка из того же континуума при постоянном `H` не следует. Временной протокол загрузки оставлен заглушкой.
- `N1`: независимые континуумы, ожидаемый полный ранг 2.
- `N2`: отдельно дана mapping-specific one-resonance/one-ADD-channel заглушка и контрпример: два резонанса могут быть отнесены к одному ADD-каналу, поэтому `K1>0,K2>0` не является общим условием всякого BIC.
- `N3`: скалярный Fano-нуль при конечной ширине — явная демонстрация `Fano zero != BIC`.
- `N4`: разные метки K-секторов; проверяется совместимость с изолированной K-сохраняющей динамикой, но квантовая суперселекция не заявляется.
- `N5`: old ADD transport — `BLOCKED_NOT_RUN`, потому что source bytes `carrier.py` в пакет не приложены.

## Состав X26-B: заглушки

В `add_adapter.py` намеренно не реализованы:

1. загрузка точного `carrier.py` и проверка Git blob;
2. перечисление ADD patch и извлечение `K1,K2`;
3. физически обоснованное отображение конфигураций в две резонансные моды;
4. ADD-derived `Hd`;
5. физическая среда, все открытые каналы и плотность состояний;
6. `W_mu,c(E)` из взаимодействия `V`;
7. физическая группа симметрий и классы возмущений;
8. протокол подготовки/загрузки BIC.

`run_x26_b()` возвращает причины блокировки в JSON, не подставляя вымышленные данные.

Вспомогательная `validate_finite_closed_orbit_lift()` строит перестановочный унитар только для действительно замкнутой конечной орбиты с сохранением `K1,K2`. Она не строит полный бесконечный `l²(X)` подъём растущего ADD и не устанавливает суперселекционное правило.

## Интерпретация статусов

Ожидаемый общий статус пакета:

```text
X26_A_CONTROL_MODEL_EXECUTED
X26_B_BLOCKED_NO_PHYSICAL_ADD_SPECTRAL_INPUTS
ADD_FANO_BIC_BRIDGE_NOT_ESTABLISHED
```

Не повышать автоматически R128 до физического механизма, не снимать блокировку соответствия ADD Definition 4 / Fig. 2(a), не закрывать L07/L09/L10 и не объявлять SSB.
