## 1. LINX: три разных размера задачи

Источник: [закреплённый reactions.py](https://github.com/cgiovanetti/LINX/blob/bfba07c77a5fcba1cc772d42f2d9e9be8a542df8/linx/reactions.py), функции `frwrd_rate_table` и `frwrd_rate_from_table`. Коррелированные межреакционные амплитуды `q=Lz` допустимы; сам вызов не навязывает независимый prior.

| Величина | Что она действительно означает |
|---|---|
| Число входных координат `r` | Размерность объявленной гладкой латентной параметризации и её меры |
| `rank(∂F/∂z)` | Число локально различимых направлений выходных функций, не обязательно `r` |
| `rank Cov(F)` | Ранг вторых моментов в выбранных выходных координатах; при нелинейном отображении может превышать латентную размерность |

Здесь `F` — вектор `log R` на объявленной положительной температурной сетке. Для сингулярной входной меры сначала нужны координаты её фактической поддержки. `ess sup_μ rank(∂F/∂z)` можно использовать как диагностику регулярного отображения относительно указанной меры; это не универсальное описание глобального posterior. При гладких заменах координат с обратимыми производными локальный ранг сохраняется. Примеры `F(q1,q2)=q1+q2` и `F(q)=q³` опровергают равенство ранга Якобиана числу всех случайных входов в каждой точке.

На узлах и при логарифмической интерполяции `F=m+S q`, поэтому `Cov(F)=S Cq Sᵀ`. Для одной реакции с одной амплитудой ранг не больше единицы. При линейной интерполяции **самих скоростей** внутри таблицы:

\[
R(q)=\sum_k w_k e^{m_k+s_kq},\qquad
\frac{d^2\log R}{dq^2}=\operatorname{Var}_{p(q)}(s),\quad
p_k=\frac{w_ke^{m_k+s_kq}}{R}.
\]

Кривая может иметь ковариацию ранга 2, оставаясь одномерной. В воспроизведённом примере `m=(0,ln2)`, `s=(0.1,0.3)`, `w=(1/2,1/2)`, `q~N(0,1)` собственные значения равны примерно `6.06773342e-6` и `0.0643414863`. `q` восстанавливается из первой компоненты; Якобиан имеет ранг 1 в проверенных регулярных точках. Квадратуры 100/200 узлов согласованы. Проверены также σ=0.3 и 3, Hessian и отдельная log-интерполяция на той же температурной сетке.

**Критерий адаптера:** совместные реализации функций на узлах и между ними, объявленные распределения, порядок реакций, единицы, интерполяция, допустимая область и хвосты. Совпадение ковариации, ранга или Якобиана по отдельности не устанавливает совпадение posterior. Ранговый контрпример для одной реакции при двух температурах нельзя подменять двумя коррелированными реакциями.

## 2. Leonard: экспериментальная матрица и модель переноса

Повторно прочитан [LEONARD_INPUT.json на историческом SHA](https://github.com/IgorSabirov/vm-lab/blob/b24c7e0cc47ff964d576f903ce7ba507d2dd731e/analysis/CCC_BBN_NETWORK_20261114/s3_standard/bh_covariance_20261115/LEONARD_INPUT.json). Происхождение — Table V работы [Leonard et al.](https://arxiv.org/pdf/nucl-ex/0601035v2); новая проверка не повторяет историческую сверку всех 256 ячеек с PDF.

В сохранённом пространстве коэффициентов `a0` матрица положительно определена: численный ранг 16, `λmin≈4.9517383e-5`, `λmax≈0.0357473677`, `cond≈721.9155`. Это 8 энергетических измерительных компонент для каждого из двух каналов, а не 16 реакций. Переход к полному сечению: `σ=4πa0`, `Cσ=(4π)²Ca0`; для d+d `Ecm=Elab/2`.

Для фиксированного линейного переноса `C_R=W C_lab Wᵀ` потолок ранга равен 16, для отдельного канала — 8. Он относится только к этим данным и заданному `W`; добавленные модельные, энергетические и экстраполяционные неопределённости могут иметь дополнительные направления. Полного функционального posterior одна covariance не задаёт без распределительных предпосылок.

Отозванная соседями **«измеренная потеря 8:1» не принята**. Также их случайный PSD-surrogate, искусственный множитель «S-factor-like» и ядро без квадратурных весов не являются физическим преобразованием экспериментальных сечений. Эффективный ранг зависит от масштаба и допуска; `np.linalg.matrix_rank` не является точным алгебраическим рангом.

Дополнительная поправка этой ревизии: при чистой смене **входных координат** `x′=D x` надо менять и `W′=W D⁻¹`. Тогда `W′ C′ W′ᵀ=W C Wᵀ`. Изменение только `C` с прежним `W` меняет физическую модель. При масштабировании **выходных координат** меняются собственные значения covariance, но обратимое преобразование сохраняет точный ранг. Это проверено на явных синтетических матрицах; не приписано Leonard как экспериментальный результат.

Следующий содержательный шаг: физическая модель сечений/S-факторов, интерполяция и квадратура с единицами и приведённой массой, дополнительные нормировочные/энергетические ошибки и экстраполяция; затем совместные функции скоростей. Потерю при сжатии оценивать по разности распределений `Yp,D/H` и других заранее объявленных abundances. Она ещё не измерена. Same-marginal контрфактуал из прежней S3-генеалогии сохраняется.

## 3. PRIMAT: изоляция обоих путей чтения

Проверены [resolver](https://github.com/CyrilPitrou/primat/blob/6f7e5680614fb119d65a6c9c65a292240b27c61e/primat/cache_utils.py), [fingerprints](https://github.com/CyrilPitrou/primat/blob/6f7e5680614fb119d65a6c9c65a292240b27c61e/primat/weak_rates/cache.py) и [документация](https://github.com/CyrilPitrou/primat/blob/6f7e5680614fb119d65a6c9c65a292240b27c61e/docs/howto/weak-rate-cache.md).

`cache_dir` — добавочный приоритетный путь, а не замена всего дерева. Пустой overlay допускает fallback в `data_dir/cache_plasma_weak`. Изолированный полный `data_dir` без weak-таблиц и `cache_dir=None` даёт промах. Заполненный overlay имеет приоритет и над изолированным `data_dir`. Это проверено исполнением трёх **точных Python resolver-функций закреплённого исходника** на временных синтетических файлах обеих категорий; весь PRIMAT не импортировался.

| Гейт | Условие физической проверки | Статус |
|---|---|---|
| G1 | В контролируемом полном дереве отсутствуют оба соответствующих кэша, внешний overlay отсутствует/пуст | Пересчёт обеих ветвей не выполнен |
| G2 | Добавлен controlled overlay с совпадающими fingerprint | Реальные загрузки интегратором не проверены |
| G3 | `weak_rate_cache=False`, thermal-таблица доступна | Ожидается nonthermal recompute, thermal может загрузиться |
| G4 | Thermal corrections включены; нужный thermal fingerprint отсутствует во **всех** путях чтения | CCRTh/VEGAS recompute не выполнен |

Проверки предстоят отдельно для Python и C. Не удалять оригинальные кэши: использовать отдельную копию с обязательными данными. `save_nTOp` и `save_nTOp_thermal` регулируют запись. Квитанция должна включать реальные пути/хеши, обе группы полей и fingerprint, constants hashes, format version 7, настройки и статистическую provenance VEGAS. Побитовое совпадение независимо пересчитанного Monte Carlo не является корректным критерием.

У закреплённой версии `custom_background` включён в fingerprint как путь. Для адаптера нужны неизменяемое имя/хеш содержимого и проверка зависимостей. Более узкий thermal fingerprint сам по себе не ошибка: поля должны отражать зависимости интеграла. Полный контракт — [PRIMAT_CACHE_ISOLATION.json](../NEUTRINO_GW_ARCHITECTURE_20261118/PRIMAT_CACHE_ISOLATION.json).

## 4. CMS: версия анализа и уровень доступа

[CMS-PAS-EXO-24-015, Figure 7](https://cms-results.web.cern.ch/cms-results/public-results/preliminary-results/EXO-24-015/index.html) подтверждает Majorana. [Статья v1](https://arxiv.org/html/2610.40911v1) уточняет muon-only benchmark; [официальный релиз](https://cms-results.web.cern.ch/cms-results/public-results/publications/EXO-24-015/) от 30 октября имеет статус submitted to JHEP. PAS и статья используют те же Run2 138 fb⁻¹ и 2022 34.6 fb⁻¹ и считаются одним анализом.

В паспорт внесены описанная binned Poisson/CLs likelihood, четыре SR-бина на период, общая между периодами нормировочная неопределённость сигнала 3.9% и TF uncertainties 26%/49%. Полная статистическая модель **не импортирована**; ссылка HEPData — `ins3220999`, а не запись CMS top-анализа.

`Lxy≈50–400 cm` — целевая область acceptance, не точный универсальный cut и не граница proper lifetime. Tracker-match veto устанавливает orthogonality к конкретному предшествующему displaced-отбору, а не ко всем CMS-каналам/CR. Нумерация библиографии HTML/PDF различается; использовать раздел и идентичность анализа. Совместные nuisance остаются даже при непересекающихся SR.

Условная геометрия сохраняется только как идеализация: `λT=(pT/m)cτ`, `P=e^(−a/λT)−e^(−b/λT)`, длинный хвост `P~(b−a)/λT`. Для фиксированной модели с `u=U²`, production ∝u и `λ=A/u`, малый-u yield ∝u². Ограниченная полоса исключения требует превышения порога максимумом yield. Ни эта формула, ни прежняя toy-таблица ширин не дают космологический вердикт.

## 5. HNL: производство и история энергии

[Dev–Wu–Xu v3](https://arxiv.org/html/2507.12270v3), разделы III/V: направление ограничения зависит от судьбы дочерней энергии. Быстрый возврат в SM требует соответствующих взаимодействий; freeze-in и низкий reheating не гарантируют отсутствия поздних ограничений. **Appendix C явно включает freeze-in и freeze-out в численный код** — фразу соседа «работа только в freeze-out» нельзя переносить на всю статью. Freeze-out аналитика Appendix B имеет собственную область применимости. Результат не переносится автоматически на 20–75 GeV.

В [HNL_COSMOLOGY_MAPPING.json](../NEUTRINO_GW_ARCHITECTURE_20261118/HNL_COSMOLOGY_MAPPING.json) разделены:

- **Входы:** история reheating, начальные распределения, массы/ароматы, операторы и взаимодействия, состав дочернего сектора, согласованные ширины/ветвления/спектры, фон.
- **Выходы:** production regime, распределения/численности, история возврата энергии и энтропии, decoupling и соответствующие `g*`, если такая эпоха существует.

`production_regime=freeze_in` нельзя назначить как независимую льготу. Кинетическое уравнение содержит расширение `−Hp∂p`, обратные процессы и согласованные знаки интегралов. Диагностика `Γprod/H` нужна по всей доступной истории. HNL остаётся кандидатом реализации X; стандартный BBN-контроль не обязан включать HNL.

## 7. Выполненная проверка

[verify_review.py](verify_review.py) и [CHECKS.json](CHECKS.json): четыре группы PASS — нелинейные функции, согласованная смена координат, реальная сохранённая матрица, точные resolver-функции. Факт времени сохраняется в CHECKS; прогноз масштаба — адресная короткая диагностика без интегрирования физической модели. Среда и SHA кода/внешних входов записаны. Контрпримеры были известны из обсуждения: это инженерная проверка, не слепой confirmatory experiment.

Для воспроизведения получить **точные текстовые файлы** `LEONARD_INPUT` и `PRIMAT_CACHE_RESOLVER` по fixed-ref URL из SOURCES (сохранить байты и проверить SHA), затем:

```bash
python analysis/NEIGHBOR_INTEGRATION_FOLLOWUP_20261118/verify_review.py \
  --leonard-input /path/to/LEONARD_INPUT.json \
  --cache-utils /path/to/primat/cache_utils.py \
  --output /path/to/FOLLOWUP_CHECKS.json
python tools/registry_links.py --summary /tmp/registry-summary.json
python -m unittest discover -s tests -p test_registry_links.py
```

Код проверяет хеши до чтения массива/исполнения resolver-фрагмента. Внешние исходники и матрица не скопированы в новую конкурирующую базу. Реальный rate posterior, physical G1–G4, BBN propagation и HNL history остаются спецификациями, а не результатами этих проверок.
