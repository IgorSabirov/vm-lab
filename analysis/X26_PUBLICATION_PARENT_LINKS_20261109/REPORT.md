Все 417 путей, размеров и Git blob SHA совпали с опубликованной квитанцией. Это проверка передачи, не повторная научная валидация матриц. SHA-256 взяты из существующей квитанции, не пересчитаны новым полным чтением ВМ. Повторная загрузка и вычисления не запускались.

Присланный traceback относится к fetch_pinned_receipt: git fetch завершился кодом 128 до чтения квитанции и до публикации в той попытке. SOURCE_BRANCH сейчас существует и указывает на ожидаемый cb8780f; отсутствие ветки текущим состоянием не подтверждается. Обёртка захватывает stderr, но в RuntimeError выводит только код, поэтому точную причину исторического сбоя (сеть/SSH/иная Git-ошибка) из сообщения установить нельзя. Позднейшая успешная публикация делает повтор bootstrap ненужным. Сбой не является отрицательным физическим результатом.

12 сопровождающих исходных файлов: CASE_PREPARATION.json, CHECKPOINT.json, ENVIRONMENT.json, FROZEN_RUNTIME_GATE.json, LAUNCH_PROCESS.json, OUTPUT_MANIFEST.json, PREFLIGHT.json, PROCESS.json, RESULTS.json, ROW_INDEX.json, TASK_TIMINGS.json, WORKLOAD.json.

### Исправление номера U009

В первичной карточке на b919e64 U009 — «Является ли пробуждение ADD спонтанным нарушением симметрии?». Статус OPEN: рост разных сохраняемых K-секторов не доказывает SSB. Ранее наша машинная сводка ошибочно назвала U009 вопросом авторской семантики. Теперь U009 сохраняет исходный смысл; AUTHOR_SEMANTICS_NOT_ATTESTED учитывается отдельно как граница R126. Оба вопроса остаются открыты; их нельзя соединять только общим номером.

## Научный результат сохранён без повторной приёмки

X26: четыре оцениваемые пары слово/загрузчик проходят условные критерии; p_final приблизительно .100213258/.826488135 для active и .140668790/.619074863 для quiet. Перестановка при K=8 — NOT_EVALUABLE_NO_INITIAL_BIC; quiet K=0 допускает загрузку. Φ/Ψ, управление, начальный пакет и резервуар заданы. Класс теоремы роста ADD не равен классу функциональной организации.

U008: 16/108 против 0/108, неповреждённый маршрут 72/108; 72 ремонта → 24 своевременных обмена → 16 функций. Обходной маршрут снимает необходимость ремонта. Одно следующее сообщение не воспроизводит аппарат.

NOW: локальный XOR не равен продолжению; U001 закрыт для конкретного взаимодействия, доставки, резервирования и расписания. Полный NOW остаётся REVIEW_REQUIRED по времени. X26 сохраняет исторический FAIL_STALE_FORECAST_HASH; последующая сверка байтов не приписывается старому launcher.

## Два новых отзыва: сохранение и адресный разбор

Оригиналы сохранены в sources/review_1.txt и sources/review_2.txt. Это мнения, не новая принятая архитектура и не основание дополнительных запусков.

Принимается различение состояния, доступа, действия, функции и воспроизводства условий. Предложение достаточного причинного описания относится к R049–R055/R120 как кандидат способа анализа; оно не заменяет исходную задачу происхождения «сейчас».

Две оговорки к отзывам:
- NOW и U008 не являются чистой парой, различающейся только временем: U008 использует отдельный событийный исполнитель и другой протокол. Их можно сопоставлять по причинному устройству, но нельзя приписывать весь межмодельный контраст одному временному вмешательству.
- В X26 опубликованное p_final уже равно населению защищённого D. Ошибка плохого T состоит не обязательно в попадании в иной более широкий сектор: он может увеличить именно Tr(P_D rho), не сохраняя исходный защищённый компонент. Дополнительный P_sector из отзыва не является автоматически наблюдаемой исходного опыта. Для ранга один нормированное состояние внутри фиксированного D определено проектором; сходство полных смешанных состояний — отдельный вопрос, не универсальное требование к наследованию.

## Цели после публикации

D01 — офлайн-анализ сохранённых граничных матриц и T: население D, сохранение проектора, сравнение с явно выбранным ожидаемым состоянием. D02 — спад населения при загрузке; промежуточных матриц cycle в архиве нет, только конечные и временные ряды наблюдаемых. D03 — движущийся проектор/утечка по ramp ket. Эти анализы остаются целями, настоящим коммитом не исполнялись и не объявлены обязательной повторной приёмкой опубликованного опыта.

L04/L06/L07: причинное использование записи, воспроизводство условий следующего действия и профиль преемственности — отдельные обязанности будущего концепта. L01/L02 и L09 сохраняют фундаментальную цель; она не подменяется исследованием приборов.

Все X26 данные для этих офлайн-задач теперь доступны из GitHub. Старый отчёт cb8780f правильно описывал своё время публикации; его слова «NPZ на ВМ» уточнены текущими навигационными документами, исходный отчёт не переписан.
