# NOW / R127, U008 и предложения R128: синтез трёх отзывов

Дата: 9 ноября 2026. Статус: проверка сохранённых данных и методический синтез;
новых симуляций и заданий ВМ нет. Научные статусы не повышены.

## 1. Результат разбора

Соседи верно выделили границы реализации: ресурсный ON старого NOW объединяет
производство и ремонт; DARK использует заданную подготовку состояния; U008 —
отдельная модель причинного канала; происхождение организации этими опытами
не установлено. Но отзывы нельзя переносить в реестр без поправок.

1. В отзыве S1 ошибочно названо условной вероятностью число **0,545333**.
   Оно воспроизводится при замене неопределённых условных значений нулями.
   Для явно определённой общей меры правильное условное значение — **0,860477**.
2. Заранее предсказанный эффект U008 остаётся содержательным условным результатом.
   Предсказанность не превращает всю проверку в тавтологию; происхождение
   заданного механизма при этом действительно не объяснено.
3. Введение переменной закона θ не доказывает изменения фундаментального закона:
   её динамика сама включается в полное состояние. Предложенный соседями критерий
   нельзя автоматически принимать как обязательную новую цель проекта.
4. Отсутствующие контрфактические ветви старого NOW нельзя получить одной
   переобработкой сохранённых исходов. Их реализация была бы отдельной доработкой.

Наиболее полезное общее продвижение: различать сохранение записи, декодирование,
наличие аппарата, восстановление маршрута, своевременный обмен, доставку,
функцию получателя и воспроизводство условий следующего перехода. Сейчас
подтверждены отдельные участки этой цепи в подготовленных конечных моделях.

## 3. Ресурсная панель: исправление знаменателей

Для конфигурации c исходный `amendment_report.report()` вычисляет:

\[
T_c=\sum_b w_{cb}\frac1{g_c}\sum_i y_{cbi},\qquad
R_c=\sum_b w_{cb}\frac1{g_c}\sum_i r_{cbi},\qquad
J_c=\sum_b w_{cb}\frac1{g_c}\sum_i y_{cbi}r_{cbi}.
\]

Здесь b — вход/ветвь, i — ячейка поколения, g — число ячеек,
r — признак полного фиксированного резерва. Условная величина C_c=J_c/R_c
определена только при R_c>0. При нулевом знаменателе код сохраняет `null`.

Для общей меры «равномерно выбрать конфигурацию, затем ячейку внутри неё,
затем исход по его весу»:

\[
P(Y\mid R)=\frac{\sum_c J_c}{\sum_c R_c}.
\]

Это отличается и от среднего C_c по определённым конфигурациям, и от среднего,
в котором null заменены нулями. Ни одна из этих величин не является вероятностью
успеха всей линии. Другая мера, например равномерная по всем ячейкам всей сетки,
потребовала бы дополнительных весов g_c; она здесь не подставляется молча.

| Величина, ON, 450 конфигураций | Пересчитано | Интерпретация |
|---|---:|---|
| Среднее T_c | 0,438962963 | Средняя доля успешных задач по объявленной мере |
| Среднее R_c | 0,503037037 | Доля полного резерва по той же мере |
| Число конфигураций с R_c>0 | 340 | В 110 конфигурациях условная вероятность не определена |
| Среднее C_c по этим 340 | 0,721764706 | Равновзвешенное по конфигурациям среднее условных величин |
| ΣJ_c / ΣR_c | **0,860477102** | Общая условная вероятность при полном резерве |
| Σ(C_c, с null→0) / 450 | **0,545333333** | Значение S1; не заявленная условная вероятность |

OFF и SHAM дают T=0 при том же среднем R=0,503037037. Основной контраст
ON-пакета подтверждается. Более того, средняя масса успеха **без полного**
фиксированного резерва равна 0,006111111: полный резерв не является необходимым
условием каждой успешной задачи. Поэтому делить просто среднее T на среднее R
тоже неверно: числителем условной вероятности служит совместная масса J.

| Слой ON | T | R | Общая условная ΣJ/ΣR |
|---|---:|---:|---:|
| Задержка 0 | 0,771444 | 0,774778 | 0,972035 |
| Задержка 16 | 0,545444 | 0,668222 | 0,816262 |
| Задержка 64 | 0 | 0,066111 | 0 |
| Глубина 3 | 0,555556 | 0,644444 | 0,862069 |
| Глубина 5 | 0,468000 | 0,528000 | 0,873737 |
| Глубина 8 | 0,293333 | 0,336667 | 0,836634 |

Таблица глубин S1 для условных значений тоже использовала нулевую подстановку.
После исправления условная успешность не убывает монотонно 3→5→8:
она сначала немного растёт. Падение безусловного успеха с глубиной подтверждено.
Насыщение по запасу также воспроизведено: T=0,369352 при 96, 0,453241 при 144,
0,457407 при 192/288/384. Это свойства данной сетки, не закон всех носителей.

В `task_probe.dispatch(task_restore)` ON вызывает сначала `produce`, затем
`repair`; OFF и SHAM не имеют соответствующего производства. Поэтому это
эффект пакета «производство + попытка ремонта» с согласованным резервированием.
Чистый эффект ремонта старой сеткой не идентифицирован. Четырёхветвевой
факторный дизайн, предложенный S1, полезен как возможная доработка, но не
существует задним числом в этих исходах. U008 содержит PROD_ONLY, однако
использует другой механизм и не заполняет отсутствующие ячейки старой сетки.

Для ADD-growing, g3/f144/d16/contact/ON первичная строка 001318 подтверждает
совместное присутствие нехватки топлива, `template_ports_incompatible` и
`inbox_expired:A/B`. Наличие нескольких записей отказов ещё не даёт уникального
причинного разложения. Это другой срез, чем исходная потеря 1/3 в U001:
вопрос U001 остаётся открытым до сверки первых расхождений и взвешенной массы.

## 4. U008: что подтверждено и что не следует отвергать

У U008 собственный событийный исполнитель; импорт отдельных компонентов NOW
не означает использования старого Engine для канала. В `World.configure()`
производство, резервирование и ремонт — разные события. A1 и A2 имеют одинаковое
производство; A2 отличается выключенным восстановлением соединителя.

| Основная ветвь | Y_R | Y_H | Y_T | Y_V | Y_F | Y_T2 | Y_star |
|---|---:|---:|---:|---:|---:|---:|---:|
| A0, неповреждённый маршрут | 0 | 108 | 72 | 72 | 72 | 72 | 72 |
| A1, повреждение и ремонт | 72 | 24 | 16 | 16 | 16 | 16 | 16 |
| A2, повреждение, без ремонта | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| A3, без производства и ремонта | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| A4, ремонт вне маршрута | 72 | 108 | 72 | 72 | 72 | 72 | 72 |

В каждой строке знаменатель 108. Подтверждены Δ(A1−A2)=4/27 и
Δ(A1−A0)=−14/27. Основная сетка — 540 задач, весь U008 с контролями — 592.
В ограниченном bypass-контроле A2 даёт 4/4, A3 — 0/4 по Y_star; у A3 при этом
доставка и целостность есть. Тем самым производство не «бесполезно» из-за
нулевого A2−A3 в основном классе: там его эффект маскирует разорванный маршрут.

Протокол заранее предсказал A1-успех при F≥10, M≥5, ready=8. Это 2×2×1×4=16
из 108 подготовленных состояний. Нулевой обмен A2 структурно следует из
удаления единственного используемого соединителя. Согласие с прогнозом —
проверка реализации и условного механизма, не независимое эмпирическое открытие.

**Поправка к S3:** «условие следует из модели» не равно «результат лишён
содержания». Предсказания и проверка механизма допустимы. Содержательны границы
выполнимости и разделение отказов; слабое место — подмена ими объяснения
происхождения самого механизма. Резервный маршрут опровергает универсальную
необходимость ремонта в более широком классе моделей, не утверждение о
необходимости восстановления единственного разорванного маршрута.

Здесь ремонт не присваивает успех обмену/передаче напрямую: `repair_done`
меняет соединитель и Y_R, Y_H записывается после доставки ответа, Y_T/Y_V —
при доставке/проверке пакета, Y_F — при выполнении функции. Это операционное
разделение полезно и не отменяется заранее заданной топологией.

## 6. Память и носители

Чтение `memory.py` подтверждает: DARK подготавливает |D⟩ явной заменой
начального яркого состояния, H при одинаковых modes/coupling/detuning тот же.
При нулевой расстройке строка и столбец D в этом H отделены от остальных:
сохранение подготовленного D следует из заданной матрицы. Энергетический
учёт ограничен памятью; привод и топливные кредиты не составляют вместе
замкнутого гамильтониана. Континуальный BIC этим запуском не установлен.

`q_final` — среднее `final_function`, то есть достижение функционального
порога последней ячейкой. Это не универсальная fidelity чтения. Нужны отдельные
взвешенные наблюдаемые читаемости, правильного декодирования, двухбитового
успеха и конечной функции. Повторное усреднение уже выбранных ветвей без их
вероятностей неверно. Полную численную волновую таблицу данный разбор не заменяет.

`Config.validate()` запрещает `task_probe` с неклассической памятью. Поэтому
ресурсная и волновая панели пока не измеряют совместный эффект в одной модели.

`carrier.py` явно задаёт Ising/CDT как детерминированные интерфейсные подготовки.
ADD использует заданное правило C2; оснований продвигать это до C3-D нет.
FOUR_CANDIDATE_RETURN сохраняет NOT_IMPLEMENTED для C3_D и physical_reverse,
NOT_ESTIMATED для Ising_j_star, NOT_ESTABLISHED для spontaneous_metric.
Согласие с ограничениями соседей не превращает невыполненную физическую
задачу в доказательство её невозможности.

## 7. Формирующая память: исправление предложенного критерия

Соседи правы, что различие начальных состояний при одном H не доказывает
изменения фундаментального закона. Но предложенная ими добавка
θ_(t+1)=G(θ_t,M_t,история) эту проблему не решает.

Если x_(t+1)=F(x_t,M_t,θ_t), а M и θ имеют заданные правила обновления, то
z=(x,M,θ) подчиняется одному правилу z_(t+1)=F_tilde(z_t). При необходимости
в z включается используемая память истории. Аналогично строится единое
стохастическое ядро на расширенном состоянии. Поэтому одна переменная θ
не различает «обычное состояние» и «изменившийся фундаментальный закон».
Это математическое замечание об описании, не теорема невозможности организации.

Полезная операциональная версия вопроса: **какие доступные преобразования
организация создаёт, сохраняет и передаёт благодаря собственной истории,
какими аппаратами и за какую цену?** Для этого до опыта следует определить
границу наблюдаемого состояния, набор проверяемых операций и интервенции
в память/шаблон/аппарат. Сравнивать при согласованных ресурсах и входах,
проверять перенос способности на отложенную задачу и следующий носитель,
сохранять ветвь разрушения и восстановления этой способности.

Это кандидат будущего критерия, не принятая новая физика и не утверждение,
что скрытое полное состояние должно быть буквально одинаковым при разных
историях. Сам факт существования фиксированного полного описания не запрещает
операционально различать исходную физику и внутреннюю коррекцию в терминах
пользователя. Не переименовываем тип 2 в тип 1 из-за включения контроллера в z.

Связь с исходной целью сохраняется: L06 требует воспроизводства условий,
L07 — сохраняемой способности продолжения и причинной передачи. Изменение
фундаментального закона не вводится как новый обязательный гейт вместо них.

## 8. Время, R128 и следующие действия

NOW: 3352,798579 с при прогнозе 2368,777674 с; верхняя оценка 3316,288744 с
превышена на 36,509835 с, запас до cap 3600 — 247,201421 с. Статус остаётся
REVIEW_REQUIRED. U008 имеет отдельную квитанцию runtime PASS; переносить один

категорический полный аудит v2 здесь не заявлен. По приведённым требованиям
есть основания считать готовность v2 **не подтверждённой**; это не новая
заморозка/разморозка протокола и не отзыв завершённого U008.
