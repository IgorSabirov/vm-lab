# Заимствование C++-инструментов сербской группы — 8 ноября 2026

Получен рабочий инструмент: оригинальный C++-классификатор сигнатуры подключён
к Python пакетным интерфейсом. Собраны три авторских генератора; проверена
склейка на оригинальном триангуляторе. Пройдено **41 586 авторских проверок**
и **12 проверок адаптера**. Это инженерное освоение кода, а не новый результат
о происхождении пространства-времени.

Основание работы — прямое поручение пользователя изучить и взять полезные
решения зрелой группы, включая C++. Требование сначала закрыть физическую
ветку L09 было лишним ограничением: полезность инструмента можно проверять
независимо от принятия физической модели. Соответствующее уточнение внесено
в начало `AGENTS.md`.

## Источник и конкретные заимствования

Mihailo Djordjevic, Igor Prlina, Marko Vojinovic;
[статья](https://arxiv.org/abs/2610.31776),
[официальный код, Zenodo DOI](https://doi.org/10.5281/zenodo.23547326), v1.0.0.
Сохранён снимок 95 файлов C++ с исходными лицензиями и SHA-256 каждого файла.
Авторские исходники не изменялись. Наши адаптеры отделены от снимка.

| Решение авторов | Что уже сделано у нас | Для чего это полезно |
|---|---|---|
| Численное ядро отдельно от генераторов | Собрана общая библиотека, добавлен пакетный C ABI и Python-интерфейс | Использовать оригинальный алгоритм без ручного переноса факторизации |
| Масштабирование, выбор блоков LDLᵀ, диагностика порога | Диагностические поля возвращаются в Python; ненадёжные ответы отвергаются по умолчанию | Не превращать почти вырожденный случай в уверенный знак |
| Топология через общие объекты симплициального комплекса | Проверены два соседних симплекса и минимальная 4-сфера | Общая грань действительно использует те же рёбра, а не независимо созданные копии |
| Проверки инвариантности, вырождений, выбора опорных блоков и ошибок | Восемь оригинальных наборов собраны и исполнены | Проверять свойства реализации шире нескольких удобных примеров |
| C++ для численного ядра и генерации | Собраны все три генератора; измерен наш пакетный вызов | Получить рабочую основу и выбирать место C++ по задаче и замерам |

Мы можем перенимать архитектуру, тесты и опыт сборки ещё до появления собственного
закона интервалов. Вопрос, чем наши отклики зададут `q_ij`, остаётся научным
вопросом; он не является запретом на эту инженерную работу.

`allocation_failure_test` намеренно вызывает ошибку выделения памяти; ожидаемый
текст ошибки в журнале сопровождается успешным завершением набора.

Наша проверка триангулятора получила числа симплексов размерностей 0…4:

- два 4-симплекса с общей тетраэдральной гранью: `(6, 14, 16, 9, 2)`;
  подтверждены шесть общих объектов рёбер;
- граница 5-симплекса, минимальная 4-сфера: `(6, 15, 20, 15, 6)`;
  каждая тетраэдральная грань инцидентна двум 4-симплексам.

Адаптер проверен на известных инерциях, вырождении, окрестности порога,
несимметричных и нечисловых входах, ошибочных формах массива, 4096 матрицах
с заранее известной инерцией и масштабировании 16 матриц на `2^(-500)` и `2^500`.
На хорошо обусловленных входах C++ и NumPy совпали.

Первая полная сборка дошла до проверки адаптера и выявила асимметрию округления
в **нашей тестовой матрице**, построенной умножением. Максимальная поправка
после явной симметризации — `4.440892098500626e-16`, при модуле собственных
значений не меньше `0.25`. Исправлена подготовка тестового входа; строгая
политика рабочего адаптера сохранена. Повторно выполнена только затронутая
проверка адаптера, и она прошла. Все авторские тесты и сборки до этого уже прошли.
Не выдаём эти две попытки за единственный безошибочный запуск.

## Измерение скорости

Локально: Linux x86-64, g++ 14.2.0, Python 3.12.14, NumPy 2.3.5;
`-O2 -fno-fast-math`, численные потоки ограничены одним. Одинаковые 4096
хорошо обусловленных симметричных матриц 4×4; медиана трёх измерений:

| Путь | Время на пакет |
|---|---:|
| C++ через наш пакетный интерфейс | 8.88 мс |
| Пакетный NumPy `eigvalsh` с подсчётом знаков | 3.99 мс |
| Python-цикл с `eigvalsh` и подсчётом знаков | 36.40 мс |

C++ здесь в 4.10 раза быстрее Python-цикла; пакетный NumPy в 2.23 раза быстрее
этого C++-пути. Работа не полностью одинакова: C++ дополнительно проверяет
надёжность и чувствительность к порогу. Результат не доказывает преимущество
языка вообще и не является прогнозом большого опыта на ВМ. Затраты записанных
этапов первой попытки — 18.313 с; исправленная проверка адаптера — 0.180 с.

Практический выбор: оставить Python для управления и анализа, сохранить
пакетный NumPy как быстрый путь для подходящих задач, применять авторское C++
как готовое численное ядро с диагностикой и основу дальнейшей работы с комплексами.
Не начинать с переписывания всего проекта на C++.

## Важная поправка к соседнему разбору

Порог `1e-30` относится к знаку детерминанта Кэли–Менгера в генераторах.
LDLᵀ-классификатор использует собственные масштабные допуски, связанные с нормой
матрицы и машинной точностью, и сравнивает классификацию при изменении допуска.
Пакетный NumPy сам по себе не «ненадёжен»; у границы вырождения нужно явно
обрабатывать неопределённость в обоих подходах. Полезно перенять именно эту
дисциплину численной диагностики.
