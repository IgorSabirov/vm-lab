# Реализация и проверка E002e v003

Поручение: согласованный концепт → собственный код и проверки → GitHub →
техническое ревью Copilot → проверка замечаний. Большой прогон не запускается.
Исходный репозиторий dbae595d794dfd23bb0972cf77b8cba465cb2f97.

Среда разработки перед вычислениями: Linux x86_64, Python 3.12.14,
AMD EPYC 9V74, 9 видимых CPU/affinity, квота cgroup 8 CPU, лимит памяти 8 ГиБ.
Численные процессы принудительно используют один BLAS/OMP/MKL-поток;
фактические библиотеки/пулы и паспорт ресурсов фиксируются в каждом отчёте.
Это локальная среда, не ВМ проекта; её скорость не переносится на ВМ.

Сначала ограниченный диагностический pilot: сравнение малых генераторов с
полной Kronecker-сборкой (4 случая) и полных QS/RR/IC сборок с прежним кодом
(3 случая, 2 комплексных вектора на каждый). Полных NESS 216-состоянийной
сети, спектрального поиска и физического прогона нет. После pilot — 20
объявленных unit-тестов, включая независимые малые решения, QRT против expm,
Schur против прямого решения, G0 против 3×3 резольвенты, гейты и целостность.

У нового ядра отсутствует измеренная скорость сборки. Первый pilot объявлен
**калибровкой с неоткалиброванным ориентиром**, а не проверкой готового прогноза.
Ориентир 5 с, инженерное окно [0,5;20] с: прежние ~0,25–0,37 с на запуск и
импорты плюс не измеренные заранее три пары новых/старых сборок, сравнения
разреженных операторов и сохранение. Число 5 с — предварительный ориентир,
не результат калибровки; его статус NOT_EVALUABLE сохраняется и при попадании
в окно. Разница разбирается до полного набора тестов. Эти границы не являются
тайм-аутом; остановка по времени не добавляется.

Прогноз полного набора фиксируется отдельной записью **после pilot и до
исполнения suite**, с опорой на измеренную стоимость основного дорогого блока
и явной оценкой дополнительных малых тестов. После правок пересчитывается
состав затронутых тестов; прежние прогнозы и результаты не перезаписываются.

Первый код/план закрепляются до исполнения. Для каждого запуска сохраняются
коммит, хеш ядра, число/имена тестов, время отдельных тестов, среда, stdout,
ошибки. Падение теста — дефект реализации или теста для разбора, не научный
вывод. Подробный итог и переписка Copilot сохраняются в этом разделе.
