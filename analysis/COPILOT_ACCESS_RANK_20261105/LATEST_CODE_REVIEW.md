## Конечный BFS имеет точное обоснование

В каждом состоянии хранится (x, Q, U), где Q=supp(q), а U — использованные
типы доступа. Для фиксированного семени и таблицы имеется не более
3·2³·2³=192 состояний. Условие разрешённости шага зависит только от этой
тройки. Все изменения q — добавления одного токена; вычитаний из резерва нет.

Поэтому два полных состояния с одной тройкой имеют одинаковые разрешённые
метки и одинаковые абстрактные преемники. Каждый абстрактный шаг поднимается
в конкретный шаг из любого соответствующего полного состояния: нужный токен
уже есть либо совмещение ролей явно разрешено моделью A. Индукция по длине
пути даёт точную эквивалентность достижимости цели. BFS возвращает минимальное
число событий; ограничение глубины или численности не требуется.

Это вывод для данных правил и цели. Потребление резерва, пороги количества,
конечные ресурсы или другая цель требуют заново проверить абстракцию.

В A дополнительно Q=U на всех достижимых состояниях. В B и C выполнено U⊆Q.
Следовательно, условие Q=X избыточно при U=X. Для этих моделей прежняя цель
с полным набором типов в c и новая цель с полным набором в q эквивалентны,
если обе требуют U=X и возвращения указателя.

## Правила различаются не косметически

| Модель | Разрешённый доступ | Новый указатель | Резерв |
|---|---|---|---|
| A, совмещение ролей | a∈Q∪{x} | r=f(x,a) | q+e_a |
| B, V1, отдельный инструмент | a∈Q | r | q+e_a |
| C, V2, копирование результата | a∈Q | r | q+e_r |
| Диагностическое переназначение | a∈Q | a | q+e_r |

Последняя строка — ранее предложенный контрпример исчерпывающему перечню
механизмов, не принятая архитектура. В ней реакция остаётся x+a→r+2a;
в C реакция x+a→2r+a. Одинаковое обновление q не делает модели одинаковыми.

В B supp(q) сохраняется при любом начальном q: добавляемый тип уже присутствует.
В C новый результат становится отдельным носителем по введённому правилу.
В A новый тип попадает в резерв через разрешённое совмещение с указателем.
Во всех этих моделях общее число токенов растёт на один за шаг по определению.
Положительное размножение не доказывает коррекцию относительно типа 1.

Числа A и C нельзя непосредственно читать как сравнительную эффективность:
у A три однотокенных семени, у C девять упорядоченных двухтокенных семян,
включая семена с двумя разными типами.

## Почему успешные C-таблицы не обязаны быть одной SCC

Аналитический свидетель, без перебора: к группе Z₂ на {0,1} присоединим новую
единицу 2. Получится тотальная строго ассоциативная таблица:

| f | 0 | 1 | 2 |
|---|---|---|---|
| 0 | 0 | 1 | 0 |
| 1 | 1 | 0 | 1 |
| 2 | 0 | 1 | 2 |

Ассоциативность следует из ассоциативности Z₂ и действия новой единицы.
Из 0 или 1 нельзя попасть в 2, поэтому SCC всех трёх вершин нет.
Для C возьмём указатель x=1 и отдельный начальный доступ a₀=2.
Доступы [2,1,0,1] дают указатели [1,1,0,0,1]. Резерв последовательно имеет
типы {2}, {2,1}, {2,1,0}, {2,1,0}, {2,1,0}; использованы все три доступа.
Цель достигнута. Тип 2 обеспечен семенем и в этом пути не произведён результатом.

Поэтому заявленные 21 успешная строгая таблица C не противоречат четырём
строгим таблицам с полной SCC. Точное число 21 этим примером не доказано.

## Проверка исходного кода

Прочитаны все 272 строки. Код перебирает 4⁹ таблиц; BOT=3 используется как
неопределённость. strict_v2_assoc сравнивает обе скобочные композиции вместе
с определённостью, weak_assoc — только значения при совместной определённости.
Полный трёхшаговый цикл проверяет разные вершины и разные метки; SCC —
достижимость по всем определённым правым композициям. Орбита фиксированного
доступа отличает посещение всех вершин от возврата в начальную вершину.

Три BFS согласуются с указанными правилами. Код различает упорядоченные
семена и таблицы, собирает минимальные длины через очередь BFS и не вводит
ограничения глубины. Это проверка реализации предикатов, не воспроизведение
чисел 31789/442, 114968, 576/225 или 48/21. Лог исполнения, время и хеш
исполнявшегося у соседей файла не представлены; результат нового нашего
численного запуска не заявляется.

Скрипт исполняет перепись непосредственно при импорте: для использования
отдельных функций потребуется отделить основной цикл или добавить main guard.
Это техническое свойство файла, не ошибка математических предикатов.

## Мост к наблюдаемости

Достаточность доступа, его наличие и воспроизводство — разные утверждения.
В групповой таблице R(x)=(X,X) постоянно, сколько бы токенов ни появлялось.
Напротив, один фиксированный доступ и один неинъективный выход могут различить
исходные состояния по истории. Поэтому необходима явно заданная внутренняя
запись/выход, а не просто расширение репертуара или формальное пересечение
ядер одиночных операций. В D_FIXED независимыми становятся эффективные
наблюдаемые при разных временах и полном указанном инструменте измерения.

Вопрос «реализовать V2 физически» следует разделить: вывести эффективное
правило из заданной микрофизики и объяснить происхождение самой микрофизики.
Первое — содержательная условная задача; её решение не закрывает второе.
Наличие фиксированного закона не отменяет внутренней причинной роли организации.
