## Автоматическая сборка HTML

Постоянная ссылка вверху открывает файл из ветки PR #219. После изменения источников GitHub Actions публикует проверенную модель по тому же пути. Процесс действует в `research/r141-r148-html` и после слияния в `main`. Для остальных PR выполняется проверка без записи. При совпадении байтов коммит не создаётся. Сборка из более старого коммита не может перезаписать новую вершину ветки.

| Что меняется | Где редактировать |
| --- | --- |
| Научный вывод, статус, условия и границы | В записи `RESULTS_REGISTER.json`, в `R141.json`–`R148.json` или в соответствующем поле Markdown-карточки. Структурированные списки источников и родителей редактируются в JSON. Сборщик сверяет формы с последним опубликованным состоянием. Противоречащие правки одного поля останавливают публикацию. |
| 28 связей | В `PAIRS.md` или `ATLAS.json → edges`. Меняются общая таблица и оба конца каждой связи. |
| Паспорта, описания, каталог и задачи | В `ATLAS.json`. Метки, адреса и внутренние ссылки проверяются при обратном чтении готового HTML. Новый материал получает уникальный якорь, путь в репозитории и метку с номером карточки. |
| Расчёты и скачиваемые комплекты | В `code/`, `results/`, `name_arithmetic/` и `ym_graph/`. ZIP строятся из исходников. Отдельный комплект R144 берётся из `analysis/R141_R147_MODEL/evidence/R144_review_kit.zip`. |
| Авторская вёрстка, доказательства, исторические вложения | В `edition.html` или через возврат отдельного HTML-блока. Шаблон сохраняет MathML, исходные редакции и источники из других коммитов. В карточке материала первой показывается текущая версия, когда файл присутствует в ветке. |

`build_state.json` хранит контрольные суммы согласованных полей и пути живых материалов. Сборка работает и при удалённой локальной копии выходного HTML. Перед публикацией проверяются 17 блоков, восемь карточек, 28 пар, паспорта, источники, якоря и встроенные архивы. Пять программ должны побайтно воспроизвести свои JSON. Правки публикуются одним коммитом после проверок. Ошибка входных данных оставляет в ветке последнюю успешную сборку.

## Как вернуть изменённый блок

Из каталога модели в актуальной рабочей копии выполните команды ниже. Для сборки нужны Python 3.12, lxml 6.1.1 и SymPy 1.14.0.

```sh
python model_blocks.py extract R145 R146 review -o work.html
# Отредактируйте work.html, затем обновите ветку репозитория.
python model_blocks.py apply work.html
python sync_html.py --write
python build_html.py --write --replay
```

`apply` проверяет хеши выделенных блоков. Явный импорт сохраняет редакционную правку в шаблоне и извлекает изменённые структурные данные в репозиторий. Панели с текущими копиями файлов редактируются по указанному в панели пути. Если исходники изменились после предыдущей сборки, сначала пересоберите модель и совместите правки. Для обычной работы с карточками и кодом достаточно коммита на GitHub. Локальная проверка актуальности запускается командой `python build_html.py`.

## Повтор вычислений R148

Из полного HTML извлечены исходные программы, эталон одноканального R130 и сохранённые таблицы. Программы выводят JSON. Проверка расширений использует SymPy. Для расчёта трёх полных шагов достаточно стандартной библиотеки Python.

```sh
python3 code/audit_extensions.py > /tmp/r148-extensions.json
python3 code/temporal.py > /tmp/r148-temporal.json
diff -u results/extensions.json /tmp/r148-extensions.json
diff -u results/temporal.json /tmp/r148-temporal.json
```

При фиксированных начальных длинах 3–7 история длины сохраняет условную информацию о следующей длине. При добавлении текущих чисел слияний и расщеплений остаток исчезает. Подготовка ансамбля задаётся извне. Причинная роль соседства проверена вмешательством, а создание и последующее чтение записи предыстории остаются открытыми.
