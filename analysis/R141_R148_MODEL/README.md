## Как вернуть изменённые блоки

Из этого каталога на Linux или macOS выполните команды ниже. Для выделения карточек достаточно Python 3. Для переноса в реестр нужен также пакет Python `lxml`. Команды используют текущую рабочую копию ветки. Полный HTML можно редактировать целиком.

```sh
python3 model_blocks.py extract R145 R146 review -o work.html
# После редактирования work.html обновите рабочую копию ветки.
python3 model_blocks.py apply work.html
python3 model_blocks.py check
python3 sync_html.py --write
python3 ../../tools/registry_links.py --write
python3 sync_html.py
python3 ../../tools/registry_links.py
```

Команда `apply` сверяет исходные хеши редактируемых блоков. При конфликте она укажет блок до записи. `sync_html.py` переносит редакционные уточнения восьми карточек, таблицу пар, паспорта, каталог и комплект воспроизведения в файлы репозитория. Основные научные статусы и родословная поддерживаются в RESULTS_REGISTER.json. Если меняется исходный научный вывод, пересмотрите поля результата и границ там же. Перед публикацией просмотрите изменения и зафиксируйте HTML, изменённые исходники и производные реестры одним коммитом. Хеши в индексе относятся к закоммиченным байтам.

## Повтор вычислений R148

Из полного HTML извлечены исходные программы, эталон одноканального R130 и сохранённые таблицы. Программы выводят JSON. Проверка расширений использует SymPy. Для расчёта трёх полных шагов достаточно стандартной библиотеки Python.

```sh
python3 code/audit_extensions.py > /tmp/r148-extensions.json
python3 code/temporal.py > /tmp/r148-temporal.json
diff -u results/extensions.json /tmp/r148-extensions.json
diff -u results/temporal.json /tmp/r148-temporal.json
```

При фиксированных начальных длинах 3–7 история длины сохраняет условную информацию о следующей длине. При добавлении текущих чисел слияний и расщеплений остаток исчезает. Подготовка ансамбля задаётся извне. Причинная роль соседства проверена вмешательством, а создание и последующее чтение записи предыстории остаются открытыми.
