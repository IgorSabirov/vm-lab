## 5. Главная предварительная находка

В исходном `add_backend_smoke_v1.py` уже существуют отдельный тип `Name`,
проекции `proj_left/proj_right`, упорядоченное слияние `merge_name` и сокращение
`merge_name(u.l,u.r)=u`. Поэтому заявление «в старом коде вообще нет алгебры
имён, там только четыре бита» фактически неверно. Неаттестованность реализации
и отсутствие структуры данных — разные утверждения.

Четыре бита старого кода записаны как **(a1,b1,a2,b2)**. Внешний порядок
**(a1,a2,b1,b2)** требует явного адаптера. Базовый C1 — два бита, в старом ядре
он вложен в C2 с нулевым вторым каналом.

Следующая проблема существеннее: **сохранённый BUGGY_UNIFORM и описанный соседями
LITERAL_DEF4 имеют одни и те же явные правила**. Для объявления их разными
моделями необходима конкретная дополнительная разница в коде. В предоставленном
тексте такого исходника нет.

На Fig. 2(a) показаны не только источники битов, но и новые рёбра. Подмена
только последнего пункта Definition 4 при сохранении прежних рёбер не
воспроизводит рисунок целиком.

Пусть старое ориентированное кольцо имеет рёбра
`u_i:b — u_(i+1):a`, а новая вершина `w_i=u_i.r vee u_(i+1).l`.

| Режим для будущего аудита | Новое ребро | Состояние w_i |
|---|---|---|
| LITERAL_DEF4 / BUGGY_UNIFORM | `w_i:b — w_(i-1):a` | `(a_i,b_(i+1))` |
| FIG2A_BITS_ONLY | `w_i:b — w_(i-1):a` | `(a_(i+1),b_i)` |
| FIG2A_FULL | `w_i:b — w_(i+1):a` | `(a_(i+1),b_i)` |
| PRESERVE_EDGES_LITERAL_BITS | `w_i:b — w_(i+1):a` | `(a_i,b_(i+1))` |

Здесь a,b применяются поканально; номер i — позиция вершины. Все четыре режима
используют ту же формулу имён. Название FIG2A_FULL обозначает нашу явную
реконструкцию всего показанного рисунка; оно не означает подтверждения авторами.

### Два полушага: статический разбор

При обратном соединении второй полушаг создаёт

`z_i=w_i.r vee w_(i-1).l=u_(i+1).l vee u_(i-1).r`.

При одинаковом битовом чтении на обоих шагах, как буквальном, так и переставленном,
состояние z_i равно исходному состоянию u_i. Циклическое слово восстанавливается,
но имена в общем случае другие; частичный перенос по старым именованным вершинам
из этого не следует.

При сохранённом соединении второй полушаг создаёт

`w_i.r vee w_(i+1).l=u_(i+1).l vee u_(i+1).r=u_(i+1)`.

Вместе с источниками битов рисунка получается на старых именах
`a'_i=a_(i+1), b'_i=b_(i-1)`, то есть следование соответствующим портам.
При буквальных источниках битов и сохранённых рёбрах получается обратный перенос.

Это предварительное алгебраическое наблюдение, сохранённое **до исполнения**.
Его надо включить в различающие тесты, а не заменять им результаты переписи.
Оно также показывает, почему утверждение «оба чтения дают один и тот же Q²=tau»
требует проверки полного определения оператора и эталона.

## 6. Конкретная привязка к Fig. 2(a)

На PDF-странице 3 исходные вершины слева направо обозначены t,u,v,w.
Их пары слева/справа — `(x0,x1)`, `(x2,x3)`, `(x4,x5)`, `(x6,x7)`.
Новые вершины и пары:

| Имя | a-бит | b-бит |
|---|---|---|
| `t.r vee u.l` | x2 | x1 |
| `u.r vee v.l` | x4 | x3 |
| `v.r vee w.l` | x6 | x5 |

В верхнем ряду b-порт левой новой вершины соединён с a-портом правой новой.
Именно эту часть рисунка пропускает исправление одних источников битов.
Печатные формулы на странице 5 сверены визуально: различие присутствует не
только в извлечённом HTML-тексте. Официальное исправление или ответ авторов
в текущей работе не получены; сообщений авторам не отправляли.

## 7. Какая дихотомия проверяется

Нужно разнести два утверждения:

1. Сильное: каждый старт E0 либо навсегда остаётся без мотивов, либо начиная
   со второго обновления расщепляется на каждом шаге без слияний.
2. Слабое: каждый старт E0 либо навсегда тихий, либо в конце концов растёт
   неограниченно.

Переходный участок способен опровергнуть первое и не опровергнуть второе.
Конечный рост не доказывает неограниченного роста. Период размеров не доказывает
периода полного состояния. Неограниченный класс конечных графов не является
конечным пространством состояний; обязательную периодичность всех орбит из
конечности каждого отдельного графа выводить нельзя.

Период по ориентированному циклическому слову разрешено использовать как
свидетельство для динамики размеров только после проверки, что проекция
автономна: будущие слова и события не зависят от отброшенных имён или скрытой
чётности шага. Точный именованный цикл учитывать отдельно. Зеркальное правило
по чётности, если оно будет исследоваться, требует включения этой чётности в
состояние и не может незаметно подменять один из четырёх операторов выше.

Полная машинная запись — [PLAN.json](PLAN.json).

- C1 и C2, L=3,4; перечисление E0 с точными весами исходных размеченных колец.
- Горизонт 32 обновления, предел 256 вершин: проектные ограничения, не замер.

  замера первого этапа. Эти пределы не являются прогнозом скорости.
- Классы: QUIET_PERIODIC, BREATHING_PERIODIC, EXPANDING_WITHIN_HORIZON,
  MIXED_TRANSIENT, UNKNOWN_BUDGET_EXCEEDED.
- Для каждого режима сохранять исходное состояние, шаги, split/merge, первые
  события, основания классификации, тип периода, число незавершённых случаев.
- Контрольный пример `[empty,B,empty,A]` проверять для всех четырёх определений.
- Для C2 используется унаследованное I2; проверка такого автомата не означает
