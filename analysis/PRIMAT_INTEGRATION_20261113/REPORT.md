# PRIMAT в общей системе внешних источников

PRIMAT зарегистрирован в существующем `SOURCE_INDEX` как `external:PRIMAT`.
Авторские исходники и ядерные таблицы остаются в `CyrilPitrou/primat`.
В vm-lab хранятся идентичность версии, ссылки на ресурсы, контракт интерфейса и
связи с нашим расчётом CCC+TL. Копия авторского кода или таблиц в этот пакет не входит.

## Одно описание источника и его ресурсов

[Запись источника](../FOUR_CANDIDATE_INTEGRATION_20261108/SOURCE_INDEX.json)
задаёт repository, commit и tree. [Манифест ресурсов](../../infra/external/sources/PRIMAT.json)
содержит относительные пути и идентичность каждого файла/каталога. Команда

```sh
python tools/external_sources.py resources PRIMAT
```

выдаёт JSON с неизменяемыми URL вида `repository/blob/commit/path` или
`repository/tree/commit/path`, описанием интерфейса и локальными обратными ссылками.
Она ничего не скачивает, не устанавливает и не исполняет. Несовпадение commit/tree
между источником и манифестом считается ошибкой; плавающая ветка не заменяет pin.

В ресурсах представлены:

| Роль | Авторский путь |
|---|---|
| API решателя и параметры | `primat/backend.py`, `primat/config.py` |
| Космологический фон и слабые скорости | `primat/background.py`, `primat/weak_rates/api.py` |
| Нуклиды, реакции, детальный баланс | `primat/data/csv/nuclides.csv`, `reactions_large.csv`, `detailed_balance.csv` |
| Состав выбранной сети | `primat/data/nuclear/networks/` |
| Ядерные таблицы | `primat/data/nuclear/tables/` |
| Нейтринные таблицы | `primat/data/NEVO/` |
| Эталоны и условия сравнения | `tests/README.md` |
| Происхождение и описание интерфейсов | `LICENCE`, `CITATION.cff`, `pyproject.toml`, закреплённые страницы `docs/` |

Индивидуальные реакции разрешаются через авторский каталог и файл сети той же
версии; собственной копии перечня реакций и численных таблиц vm-lab не создаёт.
Отдельная запись R для каждой реакции не нужна.

## Связи с нашим исследованием

В общем графе добавлены адресные переходы от `external:PRIMAT` к:

- `review:CCC_TL_20261112` — контекст космологического закона;
- `source:analysis/CCC_BBN_DRIFT_20261113/REPORT.md` — уже выполненный расчёт дрейфа и часов;
- `link:L10` — задача одной сквозной реализации;
- локальному манифесту, контракту и этому отчёту — воспроизводимое описание подключения.

Эти рёбра имеют смысл подключения кандидата и происхождения метаданных.
Они не объявляют PRIMAT подтверждением CCC+TL или решением вопроса возникновения.
Реестр R/C/L/U сохраняет прежние научные статусы. Обратные ссылки и хеши строит
тот же `tools/registry_links.py`; второй независимый реестр не добавлен.

## Интерфейс вычисления

Авторская стандартная точка входа — `primat.backend.run_bbn(params)`;
ключи примера результата включают `YPBBN`, `DoH`, `Neff`.
Манифест сохраняет три варианта состава по закреплённой документации:

| Параметры | Нуклиды | Ядерные реакции | Слабый канал | Всего |
|---|---:|---:|---:|---:|
| `network=small` | 8 | 12 | 1 | 13 |
| `network=large, amax=8` | 12 | 66 | 1 | 67 |
| `network=large` | 59 | 427 | 1 | 428 |

Числа здесь — авторские метаданные, не независимый пересчёт каталогов. Полная
выбранная сеть действует на поздней температурной стадии LT; HT/MT используют
сокращённые наборы по авторскому алгоритму. Вариант `small_parthenope` меняет
таблицы того же решателя и сам по себе не является независимым PArthENoPE-контролем.

При будущем запуске исполнитель должен получить именно закреплённую версию в
отдельную среду/кеш. История vm-lab от этого не пополняется авторскими таблицами.
Параметры среды и реальные входы фиксируются в квитанции запуска; сторонние
изменения таблиц требуют отдельного описания. Для создаваемых кешей используется
отдельный `cache_dir`, вне отслеживаемых файлов vm-lab.

## Граница подключения CCC+TL

[Контракт PRIMAT](../../infra/external/contracts/PRIMAT.json) остаётся DRAFT для
научного исполнения: точные параметры, эталонные допуски и время расчёта ещё не
зафиксированы. Это не мешает работающим регистрации, ссылкам и мониторингу.

Выведенный в нашем отчёте общий множитель должен охватывать реакции, распад и
охлаждение. Замена одного `H(T)` не реализует этот контроль. Для нестандартного
фона закреплённая документация указывает два существенных условия:

1. Табличный `custom_background` отключает неполное отделение нейтрино и
   спектральные искажения; такой запуск нельзя без оговорки сравнивать с эталоном,
   сохраняющим эти поправки.
2. Собственный `background=` поддерживается только Python-ядром. При изменении
   нейтринной истории нужны `weak_rate_cache=False` и `save_nTOp=False`, чтобы
   не использовать таблицу слабых скоростей от другой истории с тем же config.

Новый физический закон изменения отдельных реакций не введён. BBN не запускалась.

## Автоматизация и проверка

Существующий `upstream-monitor.yml` получает PRIMAT из общего SOURCE_INDEX:
мониторинг включён, обновления только предлагаются для ревизии.
`source_sha` автоматически не заменяется. Штатная проверка внешних контрактов
теперь также проверяет манифест ресурсов; отдельный workflow не требуется.

```sh
python tools/external_sources.py validate
python tools/external_sources.py resources PRIMAT
python tools/registry_links.py
python -m unittest discover -s tests -p 'test_external*.py'
python -m unittest discover -s tests -p test_registry_links.py
```

Отрицательные контроли проверяют другую версию/репозиторий, неверные пути,
дубли, плавающие URL и отсутствующую идентичность ресурсов. Граф отдельно
проверяет наличие переходов к CCC+TL и исходному расчёту BBN.

База vm-lab: `ead311fcf058b3a22c39a98d67ebe31ff070f565`.
[Рабочая задача №39](https://github.com/IgorSabirov/vm-lab/issues/39).
Это расширение существующего механизма по поручению владельца от 13 ноября.
