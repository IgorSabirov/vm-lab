## Решение
Принять одну причинную постановку C→D с четырьмя выходами: A — профиль продолжения, B — сохранность локальной памяти, C — генеалогия, D — конечная готовность. H3 (D→E с производством средств) и минимальное предсказательное состояние — отдельные направления. Не увеличивать сетку автоматически.

Обязательный минимум U010-A — **совместный** профиль действий/ответов, времени, расходов и готовности. Четыре раздельные маргинали могут скрыть различия корреляций. Включать отказ, отсутствие ответа, незавершение до горизонта, отходы и остатки; не отбрасывать неуспешные случаи. Список событий, единицы, горизонт, метрику и допуски зафиксировать до реализации. Изменение каждого компонента не требуется: память может изменить ответ при одинаковых времени и расходе.

## U010-A: различающий контроль
После валидной доставки и записи, до чтения D, построить матрицу M_D∈{m,Tm}, P_residual∈{m,Tm}. P_residual — доступная исполнителю остаточная копия payload, а не новая физическая доставка. T меняет один XOR-бит с согласованной кодировкой; перестановка двух битов для этой задачи не различает ответы. Дополнительно: отсутствие остаточной копии, отключённое чтение, стирание памяти. Повреждение checksum — отдельный контроль целостности.

| M_D | P_residual | Прогноз пути через память |
|---|---|---|
| m | m | f(m) |
| Tm | m | f(Tm) |
| m | Tm | f(m) |
| Tm | Tm | f(Tm) |

Прогноз условен на рабочую аппаратуру, ресурсы и валидность записи. Отказ фиксируется отдельно, не заменяется ожидаемым битом. Вмешательства должны давать допустимые физические состояния; их стоимость и изменение кодировки явны. Исходное снабжение и аппаратура сопоставимы, итоговый расход не принуждается быть одинаковым.

Контрасты: Δ_M сравнивает профили при смене памяти; Δ_P — при смене остаточного payload с фиксированной памятью; Δ_A — доступность конкретного реально используемого аппарата. Для распределений используются заранее выбранные расстояния, для отдельных скаляров — именованные разности. Нельзя вычитать произвольные профили как числа.

Нулевая Δ_P относится к последующему функциональному профилю, а не к диагностическому полю, куда намеренно записано новое значение payload. Отсутствие эффекта проверяется по каждому объявленному контексту; в выборочном исследовании нужен критерий эквивалентности с допуском, а не просто незначимый тест.

Для каждого операнда: ID локальной записи и её версии → конкретное событие read → возвращённое значение → операнд действия. Наблюдательский журнал не должен поставлять значение исполнителю. PASS содержательного пути требует и соответствия этой трассы, и различающих вмешательств. Если XOR уже задан как функция прочитанного значения, его смена — ожидаемая верификация; научный результат ограничен установленным причинным маршрутом и границей продолжения.

## Гипотезы и различающие исходы
| ID | Утверждение | Прогноз / опровержение |
|---|---|---|
| H-M | Локальная память причинно используется D | Ответ следует M_D в противоречивых парах; Δ_P=0 в заявленной области; provenance проходит. Следование payload опровергает заявленный путь |

## U010-B/C/D
B: t_write < t_source_off < t_read. После записи источник выключен, pending и остаточный payload недоступны. Задержки и класс повреждений объявляются заранее. Не называть долю по перечисленным случаям физической вероятностью без заданной меры.

C: сохранить creator/ID/версии/партии ресурсов, события рождения, переноса, использования и retire. При производстве четырёх аппаратов и передаче двух явно фиксировать судьбу оставшейся пары. Само наличие генеалогии не объясняет физический механизм производства.

D: заранее задать V_safe, целевое событие следующей задачи, границу системы, горизонт H, риск ε, снабжение и W(z). Для фактически выбранного контроллера проверять его политику π0. Утверждение «существует π» сильнее проверки π0 и требует отдельного поиска. Робастный вариант: существует одна допустимая причинная политика, обеспечивающая предел риска для всех допустимых возмущений; нельзя выбирать политику после знания будущего возмущения.
Для детерминированного робастного удержания: V0=V_safe; V(n+1)={z∈V_safe: существует допустимое a, для всех w∈W(z,a), F(z,a,w)∈Vn}. При фиксированном контроллере a=π0(z). Это удержание безопасности, ещё не достижение следующей функции; достижение проверяется отдельно либо через расширенное состояние с флагом цели и временем.
Стохастическая версия требует динамической оценки вероятности, а не механической подстановки ε в эту рекурсию. Полный конечный перебор даёт точный результат для перечисленного ансамбля; повторение детерминированного случая не создаёт статистических интервалов. Различать остаточную, восстановленную и поддерживаемую внешним снабжением готовность. Никакого вывода о бесконечном воспроизводстве.

## H-Q: минимальное состояние настоящего
Определять профиль как индексированное семейство u↦Law(полной наблюдаемой истории | z,do(u)), а не неупорядоченное множество распределений: иначе перестановка соответствия между вмешательствами потеряет различимость.
q достаточно, если q(z1)=q(z2) влечёт равенство профилей. Поэтому разбиение q может быть строго мельче профильного; совпадение разбиений — минимальная достаточность относительно U/O/H.
M_D отдельно может оказаться достаточной в срезе фиксированных аппаратов и ресурсов, но недостаточной на полном допустимом пространстве. Зафиксировать этот домен заранее. При численных допусках близость не обязательно транзитивна: нельзя объявлять её отношением эквивалентности без отдельного правила кластеризации и границы ошибки.
Первый аналитический артефакт — перечень конечных состояний/вмешательств, таблица профилей, проверка достаточности M_D и расширенного q, пары контрпримеров. Стоимость пока не оценена; «дёшево и точно» не гарантируется только словом «конечная».
