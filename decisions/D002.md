# D002: Внешние источники и публичная инфраструктура без автоматического научного принятия

Область: infrastructure. Статус: RATIFIED.

Как применить новые отзывы к уже публичному vm-lab и связать проверку внешнего кода с исходными предпосылками?

[Все связи решения](../analysis/REGISTRY_LINKS/INDEX.md#decision-d002)

## Альтернативы

- A — SELECTED: Дополнить существующий SOURCE_INDEX, проверять контракты, наблюдать upstream, публиковать подписанную упаковку и технические проверки.
- B — REJECTED: Автоматически поднимать научные статусы или присваивать ACM badges по успешной сборке.
- C — SUPERSEDED_CONTEXT: Предположение D001 о частном репозитории перестало действовать: владелец сделал vm-lab публичным до этого поручения. Историческое решение сохранено.
- D — DEFERRED_ACCESS: Серверные rulesets/Projects/Discussions требуют отсутствующих административных методов или явно доступного токена; конфигурации готовы.

[Источник принятия](../infra/reviews/EXTERNAL_20261112/AUTHORIZATION.md)

## Пересмотр

- Административные API доступны для применения готового плана
- Принят конкретный контроль внешней модели с допуском и бюджетом
- Создан внешний архив с проверенным DOI/SWHID
