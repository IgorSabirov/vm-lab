# E001X_CONT — продолжение через GitHub

Подготовлено 28 октября 2026 года. Заявка на ВМ **не отправлена**.
Планируемый уникальный номер: `E001X_CONT_GH_v001_r001`.
Перед исполнением фиксируется полный SHA коммита этой версии;
ВМ получает только номер запуска и SHA. Научные результаты этой версии ещё отсутствуют.

## Один вопрос

Пройдут ли четыре фазовые траектории QQ/QP, не прошедшие прежний критерий
стационарности при T=100, тот же критерий при T=500?
Каждая непройденная траектория продолжается до T=1000; дальше остановка независимо
от результата. Остальные траектории до T=1000 не продолжаются. Ранней остановки
до T=500 нет. SQRT, J=0 и E002 не входят в этот запуск.

Полные параметры, четыре исходных пути и SHA256, прогнозы и ограничения:
[`config.json`](config.json). Модель: [`cont/model.py`](cont/model.py).
Модель и 164 наблюдаемые перенесены из подготовленного CONT без изменения
операторов: AST всех 15 перенесённых функций совпадает с прежним исходником.
SHA прежнего исходника и протокола сохранены в `legacy_provenance`;
старый код на ВМ для исполнения больше не требуется.

## Входы и неизменность

Используются четыре существующие матрицы при T=100: C006, C008 предыдущего
расширенного E001, QP_phi1 и QP_phi3 из E001X. Они остаются на ВМ.
Программа перед вычислением читает только эти закреплённые контрольные точки
через `VM_WORK`, проверяет SHA256, форму 216×216, время, номер исходной
траектории и фазу. Исходные файлы не изменяются. При отсутствии файла либо
несовпадении проверки расчёт завершается ошибкой с отчётом через GitHub.

При этой подготовке реальные входные матрицы на ВМ не открывались.
Их текущая доступность в новой связке будет установлена предзапусковой
проверкой самой задачи; сохранённые ранее хеши не заменяют эту проверку.

## Ожидания до запуска

Технический положительный тест: синтетическая матрица с правильным хешем,
короткие горизонты 101/102 → завершение с кодом 0, сохранённые матрицы и
полный проверяемый отчёт в удалённом Git. Непрохождение стационарности на
таком коротком окне ожидаемо и не является ошибкой интегратора.

Технический отрицательный тест: неверный SHA256 входа → код 1, ошибка
контрольной точки в опубликованном отчёте, продолжение не начинается.

Научный прогноз: все четыре траектории проходят к T=500. Относительное
отличие конечного потока от сохранённой смеси T100 ожидается порядка 1e-5.
Это прогнозы, а не условия успешного исполнения. FAIL при T=1000 —
допустимый научный результат. Полный ранжир PP/PQ/QQ/QP здесь не проверяется:
PP/PQ и сами смеси до общего нового горизонта не продолжаются.

## Проверки и сохранение

RK4, dt=0.01. Перед длинным расчётом на каждом входе проверяются операторы,
прямой и разреженный генераторы, один интервал против `expm_multiply` и dt/2.
Норма, эрмитичность и конечность проверяются каждый интервал 1;
положительность — каждый интервал 5. Численные допуски заданы в config.

Окно стационарности — последние 10 единиц времени. Одновременно требуются:

- максимум `||Lρ||F / ||ρ||F ≤ 1e-6`;
- относительный размах потока `≤ 1e-4`;
- относительное изменение ρ между концами окна `≤ 1e-5`.

Это конечновременная диагностика, не доказательство единственности стационара.
Ток образования связей R↔L отличается от транспорта узловых возбуждений.
Для транспорта сохраняются hop/form/idle и баланс с изменением запаса n₂.
Интегральные вклады имеют знак; остаток квадратуры не подменяет стационарность.

`full/`: все 164 скалярные наблюдаемые с интервалом 0.2; полная ρ с интервалом
1; исходный и конечный снимки; диагностика, контрольные суммы, конфигурация.
До 3604 матриц для четырёх траекторий до T=1000: около 2.7 ГБ без сжатия,
плюс ряды и служебные файлы. Сжатие уменьшает объём, но коэффициент заранее
не гарантирован. При свободном месте ниже 1.5 ГБ задача останавливается с
сохранением уже записанного. Автоматического продолжения после перезагрузки нет.

## Заранее определённый отчёт GitHub

| Файл | Содержимое |
|---|---|
| `README.md` | Вопрос, ответ, таблица конечных потоков, стационарность, сравнение с прогнозом, ограничения |
| `metrics.json` | Все конечные и выбранные временные показатели, интегральные балансы, предзапусковые проверки, статистика каждого ряда |
| `checks.json` | Фактические значения и допуски; исполнение, численная корректность и научные критерии разделены |
| `series/<case>.csv` | Все 164 наблюдаемые с интервалом 1, начало и последний записанный отсчёт |
| `extrema/<case>.csv` | Для каждого окна 10 и каждой наблюдаемой: число исходных записей, первый/последний, min/max с временами, среднее, стандартное отклонение |
| `diagnostics/<case>.csv` | Норма, эрмитичность, положительность в проверенные моменты, RHS и узловая когерентность |
| `data_manifest.json` | Пути, размеры, форматы и SHA256 всех полных файлов; входы, покрытие, метод отбора и потери детализации |

Каждая исходная скалярная запись входит ровно в один интервал экстремумов.
Пик между целочисленными опубликованными отсчётами не исчезает из extrema.
Порядок событий и корреляции внутри интервалов требуют полных рядов;
между исходными отсчётами 0.2 ничего не обещается. Все опубликованные числа
CSV записываются с 17 значащими цифрами.

Задача ограничивает report: 500 файлов, 8 МиБ на файл, 30 МиБ суммарно.
Ещё 2 МиБ оставлены службе для журнала и метаданных. Превышение — явная ошибка,
не тихое сокращение. Полные матрицы не выгружаются. Отчёты ошибок не считаются
успешным расчётом; успешно посчитанное отсутствие стационарности сохраняется.

В текущей службе **нет промежуточной публикации прогресса в GitHub**.
Внутренние checkpoint/heartbeat не являются разрешённым каналом чтения статуса.
До появления итогового отчёта через GitHub нельзя сообщить процент выполнения
или отличить продолжающийся расчёт от задержки публикации.

## Проверка подготовки

Команда: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m unittest discover -s infra -p 'test_*.py' -v`.

25 из 25 локальных тестов прошли: прежние 20 проверок связки и 5 проверок CONT.
Новые проверки используют синтетические данные, настоящий локальный Git и
копию worker 4.0. Приёмщик читает опубликованные файлы только из временного
удалённого репозитория. Реальный научный запуск на ВМ этим не заменяется.

Максимальный по длительности синтетический отчёт: 4 × 4501 исходных записей,
164 наблюдаемые. Получено 27 638 633 байта; крупнейший файл 3 464 770 байт.
В тесте оставлен дополнительный запас 2 МиБ на каталог полных матриц и
диагностику. Редкий пик при t=100.4 сохраняется с точным временем в extrema,
хотя отсутствует в целочисленном series. Неверный хеш входа даёт проверяемый
отчёт ошибки и код 1.

Два ранее выполненных живых испытания транспорта описаны в
[`VALIDATION.md`](VALIDATION.md). Они не являются результатами CONT.
Исходный демонстрационный расчёт сохранён в `infra/fixtures/demo_*` для
прежних тестов. Действующие службы, очередь и worker при подготовке не менялись.

После запуска результат принимается только через `infra/github_result_reader.py`
по одному закреплённому коммиту отчёта с проверкой номера, исходной версии,
кода завершения, полноты, размеров и хешей. Окончательное решение — за пользователем.
