# R130: что было посчитано локально, что передано Copilot и что он выполнил

Дата проверки: 17 ноября 2026. Основание: прямое поручение владельца сравнить
собственный расчёт GPT с переданным Copilot заданием. Новый научный прогон не выполнялся.

**Вывод:** передан и заново выполнен готовый исправленный расчётный пакет из архива.
Его код, параметры, случаи и горизонты не сокращены. Все 91 сырых файла совпали
после декомпрессии. При этом весь архив из 161 файла не передавался целиком:
40 файлов истории, упаковки, реестра, библиографии и локальных запускателей
не включены в данный handoff. Copilot исполнил фиксированный запускатель;
самостоятельного исправления кода им в этом запуске не было.

## 3. Что именно я отобрал из 161 файла

Изначально переданы **11 входных файлов и 14 прежних документов для сверки**
(10 JSON результатов и 4 текстовых отчёта), а также отдельно сформированный
манифест хешей 91 raw-файла. Старые raw не подкладывались в рабочий каталог.
Запускатель копировал только `source/` в новый `analysis/`; `--resume` не использовался.

## 5. Важное различие истории исполнения

Локальный архив — итог **первой попытки и продолжения**. В сохранённом `ATTEMPT1.json`
указано: прежняя проверка требовала положительный постоянный обратный наклон на
последних 512 шагах уже к t=4096. Для `approaching_L128_backward` она остановила
исполнение; на t=4096 L=90, слияния ещё продолжались. Записано 15 завершённых сводок.

До передачи Copilot эта проверка была исправлена: транзиент сохраняется как
наблюдение, исходный горизонт 4096 не удаляется, а две заранее названные редкие
двухчастичные траектории дополнительно считаются до 16384. Это изменение явно
содержится в архивных PLAN, ATTEMPT1 и коде. Copilot получил **эту конечную версию**
и выполнил весь её корпус с нуля. Он не повторял прежнюю ошибочную остановку.
Совпадение 91 raw-файла подтверждает сохранение вычисленных данных; оно не доказывает
тождество всех версий кода, которыми когда-либо получались части локального архива.

Локальная среда: Python 3.12.14, NumPy 2.3.5, Linux/glibc 2.41.
GitHub: Python 3.12.16, NumPy 2.3.5, Matplotlib 3.10.7, Ubuntu 24.04/glibc 2.39.
Это разные среды, давшие одинаковые проверенные вычислительные данные.

| Измерение | Локально | GitHub |
|---|---:|---:|
| Основной операторный процесс | 7.887060 с | 7.625048 с |
| Научный блок | 55.293527 с суммы успешных фаз с переиспользованием; полный wall прежней неудачной попытки не удостоверен | 49.760633 с чистого процесса |
| Все семь команд, включая две калибровки | Сопоставимой полной квитанции в архиве нет | 63.626091 с |

Исторические строки `platform` в PLAN и `timing_note` внутри научного RESULTS
остались в неизменённом коде. В новом исполнении такой текст не является достоверным
паспортом среды или признаком resume. Авторитетна внешняя
[EXECUTION_RECEIPT.json](../results/44082471150/EXECUTION_RECEIPT.json), где `resume=false`
и записаны фактические версии/команды/времена. Это недостаток ясности метаданных;
при аудите его надо называть, а не считать эти исторические строки текущим фактом.

## 6. Что делал Copilot и где заканчивается вывод

Его фактический prompt предписывал вызвать `r130.execute` один раз и читать
`r130.status`. Зафиксированы один вызов execute и три status; семь команд завершились
с exit code 0. Научные исходники изменять запрещалось, shell/edit/browsing/delegation
не предоставлялись. Подготовку и технические исправления запускателя делал GPT
до успешного исполнения. Публиковал результат отдельный job GitHub Actions.

Поэтому данный опыт подтверждает маршрут «GPT готовит → Copilot вызывает запуск
→ Actions сохраняет → GPT сверяет». Он **не проверял** общую возможность Copilot
самостоятельно чинить произвольный научный код по ходу работы.

Машинный статус `COMPLETE_REVIEW_DIFFERENCES` сохранён. Подтверждено воспроизведение
конкретного подготовленного корпуса, включая его отрицательные контроли и оговорки.
Это не независимая реализация модели, не доказательство бесконечной асимптотики,
не закрытие всего R130 и не автоматическая научная приёмка владельца.

Мои прежние формулировки «на GitHub есть всё» и «R130 завершён» были шире этого
проверенного результата. Правильный отчёт должен сразу показывать отбор файлов,
версию исполняемого кода, изменение критериев между попытками и различия метаданных.

## 7. Как повторить именно аудит

[verify_handoff.py](verify_handoff.py) только читает два ZIP и сравнивает данные;
он не запускает архивный научный код. Внешняя библиотека Pillow нужна для сравнения PNG.
API-снимки GitHub сохранены в `GITHUB_TREES.json` и `GITHUB_EVIDENCE.json`.

```sh
python verify_handoff.py LOCAL_ARCHIVE.zip GITHUB_ACTIONS_ARTIFACT.zip --evidence-dir . --output audit-output
```

Полная машинная квитанция проверки: [AUDIT.json](AUDIT.json).
Если Actions artifact истечёт, те же 144 файла остаются в Git на указанном выше
commit; восстановленный ZIP может иметь другой хеш контейнера, но сравнение файлов
с закреплёнными Git blob SHA остаётся применимым.
