# SQRT: расчёт времени перед основным запуском

Источник: [калибровка в GitHub](https://github.com/IgorSabirov/vm-lab/tree/8f49b4bb3c2f31c58b36c6e2e79d37e7e6fa3c9e/results/E001X_SQRT_CAL_v001_r001).

Калибровка: прогноз 100 с, диапазон 40–160 с; полное время процесса 80.090735 с. PASS. Очередь 0.132276 с отдельно.
Проверены размеры/SHA256 всех 30 опубликованных файлов, 63 проверки пройдены. Независимо пересчитаны опубликованные экстремумы, концы, балансы, сетка снимков и объём: 24 случая, 24000 основных шагов. Ошибок экспорта и инвентаризации нет.

## Основной запуск E001X_SQRT_GH_v001_r001

- 48 траекторий, 1080000 основных RK4-шагов, 9648 матриц, 48048 записей по 164 наблюдаемых.
- Подготовка и preflight: 18.686 с.
- Полные циклы траекторий с проверками и записью: 2704.269 с.
- Проверка сохранённых снимков: 0.608 с.
- Формирование отчёта: бюджет 10 с.
- **Прогноз: 2733.563 с = 45.56 мин.**
- **Допустимый диапазон ±30%: 31.89–59.23 мин.**

Слагаемые для каждого случая и допущения зафиксированы в config.json. Основной код не меняется после калибровки; различаются режим, случаи и прогноз. Время не добивается ожиданием.

Окончательная сверка идёт по run.json после выхода процесса. Внутренний runtime_gate отмечает, что финальные записи отчёта/выход интерпретатора измеряются служебным отчётом. Выход за диапазон требует разбора до научного вывода.

## Граница проверки

Локальный стенд: 4 теста, включая шесть коротких фазовых/смешанных траекторий, полный цикл генерации отчёта и 5 преднамеренных искажений (поток, потеря случая, ложный PASS, размер манифеста, версия). Это известные заранее мутации, не слепая независимая серия. Синтетическая проверка размера RESULT.md для 48 случаев дала 15350 байт; фактический размер проверяется на ВМ.

При чтении файла GitHub больше 1 МиБ Contents API может вернуть пустое content. Такой файл надо получать по git blob SHA через fetch_blob и затем проверять SHA256/размер; пустое содержимое не принимается. Обнаружено на metrics.json калибровки и успешно проверено после получения blob.
