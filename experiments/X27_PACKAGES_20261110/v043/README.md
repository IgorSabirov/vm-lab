# X27_U010_V03 — Causal Continuity

**Executable reference package:** `v0.4.3-regression-repair-candidate`  
**Protocol state:** `DESIGN_DRAFT / NOT_FROZEN / MAIN_RUN_NOT_EXECUTED`  
**Model class:** finite, deterministic, exact arithmetic where applicable  
**Scope:** X27-A and X27-B-LITE only. X27-B-FULL and X28 are not implemented here.

This repository contains the runnable finite-state model, its resource ledger, exact contrast estimators, H-Q partition refinement, positive/negative controls and software tests. It does **not** report a physical experiment or claim that a causal mechanism exists in a real system.

## 2. What is implemented

### X27-A

- Full `M_task × P_res` 2×2 matrix with `a_P=1` and `A=A1`.
- Valid `m` and `Tm` records differing in one semantic bit; checksum corruption is a separate control.
- Main-memory functional following and causal trace-order checks.
- Exact total-variation distances of the full joint outcome profile.
- Payload-bypass positive control.
- `A0/A1/A2` apparatus comparison, with a separately declared calibration object, explicit full-profile TV contrasts (`A1–A0`, `A2–A0`, `A1–A2`) and apparatus-use event traces.
- `H-A-token` remains `NOT_CLAIMED` in the baseline because token identity does not affect the default transition kernel.
- `H-MA` mixed-difference norm as an independent factorial hypothesis.

### X27-B-LITE

- `R0`, `R_ext` and `R_int` arms.
- Explicit stages `σ=0,…,7` and independent discrete time `t`.
- Task 2 repeats the original `M_task` record; it does not create a new record.
- Fixed-protocol R1 and causal-instruction R2 are separate modes:
  - `causal_prod_read=False`: repair uses the frozen default `r0` protocol and does not read `M_prod`. This permits an R1 test without assuming R2.
  - `causal_prod_read=True`: D reads `M_prod`; `r0/r1` selects the repair protocol and is traced through to the repair action. This is the R2 contrast.
- `R_ext` applies the specified `(1,1,0,0)` injection, then the frozen default `r0` repair; the external-donor flag is retained.
- Nominal readiness is calculated under `ω₀`; robust readiness separately evaluates `ω_delay`, `ω_loss_E`, and `ω_loss_M` from independent copies of the same stage-4 snapshot.
- Task 2 execution is run separately from readiness estimation. The predictor cannot mutate the physical state because the state and resource structures are immutable; a state digest is also checked before and after prediction.

### Exact finite analyses

- `G0`: exact controlled reachable closure for the declared intervention family, with a two-intervention depth limit. X27-B-LITE closure includes all three restoration arms and all four disturbance contexts. The report stores the exact closure count and a SHA-256 digest of sorted state hashes, rather than embedding thousands of raw hashes; closure is deterministically regenerated from the committed kernel.
- `H-Q`: exact partition refinement on the finite controlled state graph. Stages outside the decision region remain operational helper states; the reported equivalence classes are restricted to decision stages `σ∈{1,2,5,6}`. Terminal states are outcome leaves, not members of the partition domain. In B-LITE, the pre-execution `(V_nom,V_rob)` diagnostic output is included in the future signature. The legacy B-LITE graph is explicitly labelled `LEGACY_R2_LIKE_CAUSAL_M_PROD_READ`: `continue` evaluates readiness with `causal_prod_read=True` and the graph permits `M_prod` interventions. Its old class count is a scoped reproduction only, not an R1 result, not a frozen H-Q result, and not transferable to v0.5.
- The partition routine accepts deterministic transitions or exact finite transition laws whose probability masses are non-negative `int`/`Fraction` values summing exactly to one. `float`, `bool`, negative, empty, and non-normalized laws are rejected. The current experiment kernel is deterministic.
- `E2`: six evaluator checks, including exact factorial design rank, null/positive controls, exact unbinned resolution and independent direct TV calculation.
- `PC1–PC9` and `NC1–NC14` software controls, including nested-provenance purity checks.

## 3. Executable finite-model conventions in this implementation

The executable parameter manifest is `spec/model_manifest.json`. The principal numerical conventions are:

| Operation | Cost `(E,M,W,U)` | Byproduct `(E,M,W,U)` |
|---|---:|---:|
| Read Task 1 / Task 2 | `(0,0,0,0)` | `(0,0,0,0)` |
| Task 1 | `(1,0,0,0)` | `(0,0,1,0)` |
| Task 2 | `(1,0,0,0)` | `(0,0,1,0)` |
| Repair `r0` | `(1,1,0,0)` | `(0,0,1,0)` |
| Repair `r1` | `(1,1,0,0)` | `(0,0,1,1)` |
| External injection | inflow `(1,1,0,0)` | — |

All resource capacities remain 3 in this regression-only version and the initial D stock is `(3,2,0,0)`. The component capacity `(5,3,3,3)` and dose sweep belong to the separate v0.5 redesign and are deliberately not implemented here. The order is inflow → capacity/spill → atomic cost check → deduction → byproduct → capacity/spill. A cost failure does not partially deduct resources or create byproducts. An already committed inflow remains a separately recorded event. Every operation also emits a per-operation ledger event containing its pre-state, inflow, cost, byproduct, post-state, both spill vectors and exhaustion status; each disturbance loss records its before/after vector and applicability.

The checksum convention is fixed here as `h(s)=1-s`. Task output is the semantic bit read from `M_task`. A successful Task 1 wears the apparatus; a successful repair restores its health. These are concrete executable assumptions, not deductions from a more general physical theory.

## 5. Producer C boundary

This package implements the agreed variant B: production and transfer by C are trusted exogenous prehistory. The trace records object-specific memory, payload and apparatus provenance. Only a C-created A1 receives `C_produce_event_exogenous` and `C_apparatus_transfer_event_exogenous`; A2 is attributed to the test fixture; A0 is recorded as absent. Foreign memory creators are not logged as C writes. `production_and_transfer_simulated=false` remains explicit. Their production costs are not charged against D's post-start autonomy.

Allowed conclusion: D uses pre-transferred content and apparatus with declared provenance in this finite model.  
Not allowed: this experiment simulates or proves C's production and transfer mechanism.

## 6. Readiness-estimator isolation

The regression repair is implemented at two levels:

1. `State`, `ResourceVector`, `Apparatus`, records and operations are immutable dataclasses; transitions return new states.
2. `estimate_readiness` deep-copies the stage-4 snapshot per scenario, evaluates all scenarios before aggregation, repeats the scenario set in reverse order, and compares state hashes before and after.

`NC10` deliberately injects a top-level illicit mutation. `NC13` mutates nested provenance/identity fields of each state record and apparatus on disposable stage-4 snapshots; every mutation must produce `RUN_INVALID_SIDE_CHANNEL_LEAK`. `NC11` checks order independence, `NC12` requires all three stress results, and `NC14` distinguishes checksum integrity errors from genuinely absent read events.

## 7. v0.4.3 regression repairs (no v0.5 redesign)

- F1: `estimate_readiness` requires the exact three-member stress set; empty, duplicate, incomplete, and extra scenarios raise instead of allowing vacuous `all(())`.
- F2: state digest serializes every nested dataclass field recursively, including record creator IDs, record IDs and versions.
- F3: token specificity is reported in both directions (`token-original` and `token-substitute`) and separately from original-A1 necessity.
- F4/F15 estimator contract: TV and transition laws accept only non-negative `int`/`Fraction` masses, require exact normalization, and reject floats/bools.
- F5: corrupted Task-1 records preserve `INTEGRITY_ERROR`; absent read events remain `MISSING_READ_EVENT`.
- F6: delay start/end are explicit events; the Task-2 read timestamp follows delay completion.
- F7: PC7 computes TV over the full R2 joint profile and checks it against an independent direct-sum implementation.
- F8: exogenous provenance is object-specific for C-created A1, fixture-provided A2 and absent A0.
- F9/F10: H-Q output separates `O_D`, `O_eval` and `J_trace`, and labels the legacy B-LITE result as R2-like and not transferable to R1. The historical 11/79 counts are not accepted as frozen H-Q results.
- NC13: nested-provenance/state-identity mutations are detected by the stage-4 purity guard. NC14 separately tests integrity-error versus missing-read status.

The redesign items F11–F14 and new A2 calibration design remain outside this v0.4.3 branch. In particular, this branch retains the old binary apparatus health and scalar capacity 3; no v0.5 health/load or component-capacity semantics are backported.

## 8. What remains open before DESIGN_FROZEN

This package is a reference implementation and technical diagnostic, not a freeze package. Before freezing, the protocol owner must accept the concrete conventions in `spec/model_manifest.json`, then the specification and kernel hashes must be fixed together. In particular:

- `h(s)=1-s` and the operational meaning of the binary task result are implementation choices.
- The costs of C's write/production/transfer remain outside scope under provenance variant B.
- `R_ext` is intentionally resource-advantaged and is not a cost-matched comparison with `R_int`.
- The default H-A-token mechanism is absent; baseline status remains `NOT_CLAIMED`.
- The model is deterministic; stochastic probabilities, tolerances, MDE and Monte Carlo power analysis are not activated.
- The exact H-Q implementation is stage-local: a `do(...)` action is available at its declared eligible stage, with at most two such actions on a path. It is not a queued command sent earlier and held pending. Nondecision stages `σ∈{0,3,4}` are operational helper nodes for exact refinement; the historical partition projection reports `σ∈{1,2,5,6}`. Terminal outcomes are compared as output leaves, never as partition members. The historical 11/79 numbers are scoped reproductions only and are not frozen results; the B-LITE result is R2-like because `causal_prod_read=True` is explicit in `continue` and M_prod interventions are allowed. Separate R1/R2 observables and partitions belong to the v0.5 redesign.
- This implementation does not include X27-B-FULL recycling, resource reproduction, D2, new-record creation/R063, or X28.

Therefore the software checks do **not** authorize G7. Current protocol status stays `NOT_FROZEN / MAIN_RUN_NOT_EXECUTED`.
