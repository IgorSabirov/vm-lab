**Executable reference package:** `v0.4.2-hotfix-reference-kernel`  
**Protocol state:** `DESIGN_DRAFT / NOT_FROZEN / MAIN_RUN_NOT_EXECUTED`

## 2. What is implemented

### X27-A

- Full `M_task × P_res` 2×2 matrix with `a_P=1` and `A=A1`.
- Valid `m` and `Tm` records differing in one semantic bit; checksum corruption is a separate control.
- Main-memory functional following and causal trace-order checks.
- Exact total-variation distances of the full joint outcome profile.
- Payload-bypass positive control.
- `A0/A1/A2` apparatus comparison, with a separately declared calibration object, explicit full-profile TV contrasts (`A1–A0`, `A2–A0`, `A1–A2`) and apparatus-use event traces.
- `H-A-token` remains `NOT_CLAIMED` in the baseline because token identity does not affect the default transition kernel.
- `H-MA` mixed-difference norm as an independent factorial hypothesis.

### X27-B-LITE

- `R0`, `R_ext` and `R_int` arms.
- Explicit stages `σ=0,…,7` and independent discrete time `t`.
- Task 2 repeats the original `M_task` record; it does not create a new record.
- Fixed-protocol R1 and causal-instruction R2 are separate modes:
  - `causal_prod_read=False`: repair uses the frozen default `r0` protocol and does not read `M_prod`. This permits an R1 test without assuming R2.
  - `causal_prod_read=True`: D reads `M_prod`; `r0/r1` selects the repair protocol and is traced through to the repair action. This is the R2 contrast.
- `R_ext` applies the specified `(1,1,0,0)` injection, then the frozen default `r0` repair; the external-donor flag is retained.
- Nominal readiness is calculated under `ω₀`; robust readiness separately evaluates `ω_delay`, `ω_loss_E`, and `ω_loss_M` from independent copies of the same stage-4 snapshot.
- Task 2 execution is run separately from readiness estimation. The predictor cannot mutate the physical state because the state and resource structures are immutable; a state digest is also checked before and after prediction.

### Exact finite analyses

- `G0`: exact controlled reachable closure for the declared intervention family, with a two-intervention depth limit. X27-B-LITE closure includes all three restoration arms and all four disturbance contexts. The report stores the exact closure count and a SHA-256 digest of sorted state hashes, rather than embedding thousands of raw hashes; closure is deterministically regenerated from the committed kernel.
- `H-Q`: exact partition refinement on the finite controlled state graph. Stages outside the decision region remain operational helper states; the reported equivalence classes are restricted to decision stages `σ∈{1,2,5,6}`. Terminal states are outcome leaves, not members of the partition domain. In B-LITE, the pre-execution `(V_nom,V_rob)` diagnostic output is included in the future signature.
- The partition routine accepts either deterministic transitions or exact finite transition laws whose probabilities are `Fraction`s. The current experiment kernel is deterministic.
- `E2`: six evaluator checks, including exact factorial design rank, null/positive controls, exact unbinned resolution and independent direct TV calculation.
- `PC1–PC9` and `NC1–NC12` software controls.

## 3. Executable finite-model conventions in this implementation

The executable parameter manifest is `spec/model_manifest.json`. The principal numerical conventions are:

| Operation | Cost `(E,M,W,U)` | Byproduct `(E,M,W,U)` |
|---|---:|---:|
| Read Task 1 / Task 2 | `(0,0,0,0)` | `(0,0,0,0)` |
| Task 1 | `(1,0,0,0)` | `(0,0,1,0)` |
| Task 2 | `(1,0,0,0)` | `(0,0,1,0)` |
| Repair `r0` | `(1,1,0,0)` | `(0,0,1,0)` |
| Repair `r1` | `(1,1,0,0)` | `(0,0,1,1)` |
| External injection | inflow `(1,1,0,0)` | — |

All resource capacities are 3 and the initial D stock is `(3,2,0,0)`. The order is inflow → capacity/spill → atomic cost check → deduction → byproduct → capacity/spill. A cost failure does not partially deduct resources or create byproducts. An already committed inflow remains a separately recorded event. Every operation also emits a per-operation ledger event containing its pre-state, inflow, cost, byproduct, post-state, both spill vectors and exhaustion status; each disturbance loss records its before/after vector and applicability.

The checksum convention is fixed here as `h(s)=1-s`. Task output is the semantic bit read from `M_task`. A successful Task 1 wears the apparatus; a successful repair restores its health. These are concrete executable assumptions, not deductions from a more general physical theory.

## 5. Producer C boundary

This package implements the agreed variant B: production and transfer by C are trusted exogenous prehistory. The trace records `C_write_event_exogenous`, `C_produce_event_exogenous`, `C_transfer_event_exogenous`, and `D_receive_event_exogenous`; `production_and_transfer_simulated=false` is explicit. Their production costs are not charged against D's post-start autonomy.

Allowed conclusion: D uses pre-transferred content and apparatus with declared provenance in this finite model.  
Not allowed: this experiment simulates or proves C's production and transfer mechanism.

## 6. Readiness-estimator isolation

The hotfix is implemented at two levels:

1. `State`, `ResourceVector`, `Apparatus`, records and operations are immutable dataclasses. Transitions return new states.
2. `estimate_readiness` deep-copies the stage-4 snapshot per scenario, evaluates all scenarios before aggregation, repeats the scenario set in reverse order, and compares state hashes before and after estimation.

`NC10` deliberately injects an illicit mutation using `object.__setattr__` on a disposable frozen-state instance; the digest guard must return `RUN_INVALID_SIDE_CHANNEL_LEAK`. `NC11` checks order independence and `NC12` requires all three stress results even when an earlier scenario fails.

## 7. What remains open before DESIGN_FROZEN

This package is a reference implementation and technical diagnostic, not a freeze package. Before freezing, the protocol owner must accept the concrete conventions in `spec/model_manifest.json`, then the specification and kernel hashes must be fixed together. In particular:

- `h(s)=1-s` and the operational meaning of the binary task result are implementation choices.
- The costs of C's write/production/transfer remain outside scope under provenance variant B.
- `R_ext` is intentionally resource-advantaged and is not a cost-matched comparison with `R_int`.
- The default H-A-token mechanism is absent; baseline status remains `NOT_CLAIMED`.
- The model is deterministic; stochastic probabilities, tolerances, MDE and Monte Carlo power analysis are not activated.
- The exact H-Q implementation is stage-local: a `do(...)` action is available at its declared eligible stage, with at most two such actions on a path. It is not a queued command sent earlier and held pending. Nondecision stages `σ∈{0,3,4}` are operational helper nodes for exact refinement; only `σ∈{1,2,5,6}` nodes are published as predictive classes. Terminal outcomes are compared as output leaves, never as partition members. The earlier all-node class counts (23/160) are superseded by this decision-domain calculation.
- This implementation does not include X27-B-FULL recycling, resource reproduction, D2, new-record creation/R063, or X28.

Therefore the software checks do **not** authorize G7. Current protocol status stays `NOT_FROZEN / MAIN_RUN_NOT_EXECUTED`.
