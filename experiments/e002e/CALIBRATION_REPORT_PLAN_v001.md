# Проверка финального отчёта и бюджет

После публикации E002e_FINAL_CAL_v001_r001 прочитать весь report на одном
GitHub commit, проверить размер/SHA каждого файла и привязку source/run.
Затем одна офлайн-операция: сверить время166с [130;240],42теста,6полных и
10малых случаев,36статических и4частотных решений с уточнением,71500QRTшагов;
повторить QS/RR baseline-сверки по прежним допускам, вычислить бюджеты.
Прогноз этой локальной операции0,3с [0,05;2]; только JSON и небольшие массивы,
без генераторов, факторизаций и эволюции. Сохранить фактическое время отдельно.

Бюджет определяется числом задач inventory × измеренные фазы по моделям.
NESS включает сборку, оба фактора, оба решения/quality и condition. Static и
frequency включают оба метода. QRT — число реальных блоковых шагов, по3входа
на блок. Для QS используется полный H100; RR/IC H1 экстраполируется по шагам,
что явно отмечается как ограничение. I/O и отчёт добавляются один раз отдельно.
G использует самый медленный измеренный представитель соответствующей
размерности/маски/ветви с запасом на condition/экспорт. F2 не рассчитывается;
его стоимость — экстраполяция по типу модели, запрещено калибровать на heldout.
Пределы времени инженерные, не вероятностная гарантия; точность не ослабляется.

Память: максимумы RSS, sampled VmSize, одновременно живых факторов; прогноз
дополнительного пика с коэффициентом2, минимум1ГиБ, запас1ГиБ. Это
консервативное сравнение с текущими8ГиБ RLIMIT_AS/host available, не знание
невидимого ancestor cgroup. Точный доступный ресурс пересчитывается при запуске.
Все42теста и физические проверки должны пройти. QRT∞ остаётся TAIL_UNRESOLVED;
ширина полной модели не получает измеренного значения из калибровки.

После формирования проверяются production preflight для G и baseline на
зафиксированном паспорте (dry check, без вычислений/заявок), и отказ F2 без
предсказаний. Прогноз этого малого процесса0,3с [0,05;2]. Код/проверки/бюджет
и итоговый компактный RESULT сохраняются в GitHub. Производственная очередь
остаётся пустой; результат научно принимает пользователь.
