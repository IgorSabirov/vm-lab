Порядок пользователя: сборка → ревизия соседями → исправления → дымовые → ВМ.

Это исполняемый кандидат одного пути: источник → доставка записи → локальная
память/чтение → производство двух материальных аппаратов → списание наследованного
аппарата → оплаченный контакт → восстановление функции → передача записи и одного
аппарата следующему носителю. Донор конечный, ресурс прибывает после запроса с
конечной скоростью. Следующий носитель повторяет путь на собственном повреждённом
состоянии. Отрицательные контроли действуют в том же исполнителе.

Пакет реализует ограниченный класс из общей [постановки](../../analysis/INTEGRATED_EXPERIMENT_20261107/EXPERIMENT_DESIGN.md).
Он не объявляет всю постановку выполненной. Точные границы каждого X01–X16:
[IMPLEMENTATION_MAP.json](preregistration/IMPLEMENTATION_MAP.json).

## Правила кандидата, которые нельзя спрятать в результат

Геометрия 1+1 Минковского, места потенциальных носителей, адреса, собственные часы,
правило синтеза и интерфейсы даны. Аппарат A одновременно читатель, писатель и
катализатор. При A и прочитанном `11` два прекурсора и два кредита превращаются
в два новых A; исходный A затем списывается в материальный отход. Это явно
предложенный закон, не вывод из V1 и не реконструкция биохимии. Отдельные Aw/Ar
и появление первого A без катализатора не реализованы. Контроль без семени
предсказывает bootstrap-барьер именно этого закона.

Контакт — материальный локальный рабочий узел, собранный с расходом прекурсора,
кредита и собственного времени. Полная матрица соседства не восстанавливается.
Адрес следующего носителя задан. Таким способом нельзя закрыть происхождение
пространства, шаблона или наследование топологии.

Топливные кредиты и материальные единицы имеют отдельные точные балансы:
локальный запас + донор + транзит + израсходованный/недоступный остаток + отходы.
Кредиты не джоули. Работа импульса и измерения не выведена из гамильтониана всего
целого; термодинамическое замыкание не заявлено. Стирание не добавляется второй
«информационной ценой» к теплу/работе. Ветка `erase_record` изымает доступную
запись в недоступное окружение и не моделирует физический reset.

Все ветви с требованием общей базы имеют равные начальные суммы. Неиспользованный
лимит выключенного производства/ремонта переводится в недоступный остаток.
Прочие отключённые действия могут оставить неистраченные локальные кредиты;
это отражено в полном профиле и не скрыто. Изменение объёма донора — отдельная
дозовая интервенция, а не сравнение при одном бюджете.

Транспорт надёжный, сообщения уникальны, два слота рабочей памяти, конечные
локальные запасы и резервирование места. Это выбранный используемый подслучай,
**не исправленная вся R125 multi-token/lease/cancel/loss спецификация**.
Нет криптографии, произвольных фрагментов, отказов и транзакционных возвратов.

## Волновая память в том же пути

`memory.py` задаёт конечный эрмитов H: две ортогональные информационные дорожки,
в каждой bright/dark и n конечных мод окружения. Состояние — матрица плотности;
ожидание унитарно, чтение — трёхисходный CP-инструмент с условным состоянием.
Окружение не сбрасывается между ожиданием и чтением одной записи. Для каждого
нового места записи подготовлен отдельный конечный модуль: эта подготовка
остаётся импортом, а не бесплатным воспроизводством памяти.

При нулевой расстройке dark изолирован. `finite_static` пишет в bright без
загрузочного импульса; `finite_dark` применяет объявленный bright↔dark импульс,
оплачиваемый дополнительным кредитом. Неизвестное квантовое состояние не
копируется: передаются результаты чтения ортогонального классического содержания.
Две записи моделируются независимыми квантовыми модулями; совместная
многочастичная запутанность между носителями не реализована.

Это конечная волновая модель, **не установленный BIC континуума и не носитель
C021/R097**. Перебор 4/8/16/32 мод — диагностическая зависимость от конечного
окружения; без анализа предела название BIC не присваивается. Спектральная
операторная мера реализована отдельно в `memory.response`; один H,V сохраняется
при изменении передачи аппарата. Это конкретная проекция, не общий I_C.

## Причинность и часы

Диспетчер знает мировые линии для доставки и полное состояние для аудита.
Локальные правила получают только одну Cell, доставленные записи и её ресурс.
Донор расходуется при физическом приходе запроса, не при постановке запроса
в очередь. Исследовательский журнал не является входом контроллера.

Нормировка c=1. Сроки местных действий заданы собственным временем. Меняется
физическая скорость потомков, отдельно переставляются владельцы событий при
одном координатном времени. Последнее — ограниченный тест независимого порядка,
не доказательство произвольной рефолиации. В `kinematics.py` есть рациональная
проверка интервала и преобразование Лоренца; весь движок не объявляется общей
ковариантной полевой теорией. Будущая граница не доступна контроллеру. PW нет.

## Команды для внешнего ревьюера

Из корня фиксированного checkout:

```bash
cd experiments/now_integrated_v1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run.py --phase reviewer --reviewer-name NAME --source-commit FULL_40_HEX_COMMIT --output /path/to/review-output
```

Здесь `NAME`, полный commit и путь заменяются фактическими значениями. Установка
зависимостей — в окружении ревьюера, не из изолированной VM-задачи без сети.
Автор эти команды **не выполнял**. `reviewer` сохраняет диагностический статус,
не разрешает основной запуск и не выдаёт принятие от имени пользователя.
Не добавлен GitHub Actions workflow: публикация исходников не запускает тесты.

Для будущего smoke нужен receipt принятой ревизии с digest исходников/научных
конфигураций/тестов и ссылками на отзыв и решение пользователя. Шаблон ниже
не является принятием. После исправлений зафиксировать окончательный протокол,
его digest и принятие; затем дымовой и калибровка должны относиться к этому же
digest. Если изменились параметры, старые результаты не переносятся молча.

```json
{"status":"pending","source_digest":null,"review_reference":null,"user_decision_reference":null}
```

Основной запуск блокируется пока `freeze_state != FROZEN_AFTER_REVIEW`, нет
подходящей дымовой проверки, измеренной калибровки целевой ВМ и прогноза ресурсов.
Код не устанавливает ПО ВМ, не ремонтирует подключение и не вызывает submit.
Маршрут доставки фиксированного GitHub-пакета и возврата артефактов проверяется
после ревизии: рабочий MCP не удостоверяет работу прежнего сервиса публикации.

## Объём и артефакты будущего исполнения

Основной предложенный объём: 46 конфигураций, 10777 траекторий. Для 25 строго
детерминированных классических конфигураций — по одному исполнению; для остальных
21 конфигурации — по 512 seed. Повторять неизменный детерминированный исход
сотни раз не требуется.
Это проект объёма, не прогноз длительности. Ограничения предложения: один
процесс, до 3600 s, 4096 MiB RSS и 1024 MiB результатов. Калибровка должна
измерить все численно различные backend/размеры и худший активный путь; если
прогноз не укладывается, объём пересматривается до submit. Пока затрат ВМ нет.
Ревизор должен проверить дальнейшее сокращение тождественных клеток и точное
суммирование там, где это допустимо, до окончательной фиксации.

Сохраняются `SOURCE`, `ENVIRONMENT`, `CHECKPOINT`, `TRAJECTORIES`, `METRICS`, `RESPONSE`,
`ANCESTOR_RETURN`, `RUN`; при сбое — `FAILED`. Полный снимок включает очереди,
транзит, отходы, аппараты и квантовые состояния. Resume сверяет fingerprint.
Подробные трассы только для seed=0 каждой клетки; остальные полные конечные
профили и хеши сохраняются. Время восстановленного сегмента помечается отдельно
и не должно использоваться как время целой задачи при калибровке.

`technical_pass` значит завершение ограниченных задач с внутренними инвариантами,
не принятие науки или закрытие L-связей. Скрипт не пишет новые R и не повышает
статусы реестра. Статистические интервалы условны на модели независимых seed;
SHA256-адресация сама по себе не доказывает статистическую независимость.
Истинность общего замыкания V не выводится из конечных трасс.

Генеалогия оценивается по [предварительным обещаниям](ANCESTOR_FORECAST.md).
Все исходные 125 записи рассмотрены, но только явно названные проверки
совместимости являются прямыми обещаниями кандидата. Остальные — сохранённые
границы и долги, не 125 экспериментальных подтверждений.
