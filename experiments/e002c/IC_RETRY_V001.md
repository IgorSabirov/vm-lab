# Одобренный повтор IC-1 и отдельная проба освобождения

Пользователь 30 октября одобрил повторный поиск с проверяемым охватом и запросил
время жизни изолированных компонент. Старые отчёты и решение об исходном кандидате
не меняются. База — код ae867241bc94ee6e2ce36ade26131ab28bcc939d,
отчёт 7fd36d60044b436484e81a5e92a80163c4688b45, разбор 06b8cdbf2a7afefbd526ab77d2857a660ae5ecaa.

## Сначала короткий замер на ВМ

`E002c_IC_RETRY_CAL_v001_r001`: IC-1, Phi=epsilon=0, gamma=.05, dt=.02.
Три траектории: T20 с прежним выбранным alpha; T20 с 4×seed; T200 с прежним alpha.
Итого 12000 RK4-шагов, 48000 RHS, 1203 скалярных записи, 123 диагностики,
25 снапшотов плюс 3 конечных состояния. Стационарность T20 не требуется для приёмки
замера. Физические проверки, полный объём и отсутствие краха обязательны.

В том же коротком задании — новая source-off проба ниже: две модели, четыре
начальных состояния на модель, две разреженные факторизации 6561×6561 с двумя
правыми частями каждая; два expm_multiply на четырёх столбцах, t=0:2:400.
Всего 1608 отсчётов вероятности выживания и столько же изоляционного веса.

Предварительный прогноз **34 с, диапазон 0–94 с**. Это ещё не калиброванный новый
цикл. Источник оценки: E002c_CAL_v003_r001 (код d07886660ce3e5b85ca17b17fb9d7913d5f13548),
IC шаг .00151026709 с, диагностика .01778874914 с; сумма 12000 шагов и 123 диагностик
даёт 20.31 с. Около 3 с на прежние подготовку/скаляры/запись; отдельно 8 с на
новый разреженный solve/expm (локальная проба 200 единиц ~1.2 с QS, ~.94 с RR;
ВМ не предполагается равной локальной машине), остаток ~3 с на отчёт и хеширование.
Применён базовый допуск max(30%,60 с), без заднего изменения границ.
Точное внешнее время берётся из job.finished−job.started; очередь/публикация отдельно.

После проверки замера отдельный коммит фиксирует формулу длительности повторного
поиска. Код ядра после замера не меняется; kernel_sha256 и версии numpy/scipy
проверяются перед поиском. Одобрение повторного поиска пользователем уже получено.

## Проверяемый охват IC-1

Те же три alpha01/12/02 в [1e-4,2], тот же условный feed, шесть целей
pL01/12/02 и ell01/12/02 из data/e002b_targets.json. Hop отсутствует в objective.
Seed=ell/(.5*pR); старты .25,1,4 × seed, как прежде.

Каждый старт сначала выполняет семь точек: центр и ±log(2) по каждой из трёх
координат, с ограничением объявленным прямоугольником. Это обязательное конечное
покрытие всех осей, независимо от дальнейшей работы оптимизатора. Затем от лучшей
валидной точки звезды — scipy least_squares TRF, 2-point Jacobian, diff_step=.001,
max_nfev=10, ftol=xtol=gtol=1e-5. Все вызовы residual, включая численный Jacobian,
считаются отдельно; жёсткий предел 47 на старт, **141 на поиск**. Кэш точных alpha
разделяет calls, computations, cache_hits. Оптимизатор не запускается, если все
семь точек старта невалидны. Это явно публикуется, а не называется сходимостью.

Каждое вычисление: IC T200 dt.02 без autoextend, 10000 шагов; нестационарная или
нефизическая точка не допускается к выбору. Выбор среди всех валидных: min max
относительной ошибки, затем сумма квадратов, затем лексикографический alpha.
Selected alpha сохраняется и хешируется до проверки транспортного результата.
Публикуются каждая точка/шесть значений/ошибки/валидность, диапазоны и число
уникальных значений каждой координаты на каждом старте, OptimizeResult status,
success, message, nfev, njev, optimality, cost, active_mask. Отсутствие подходящей
точки в этом конечном поиске не доказывает глобальную невозможность IC-1.

Выбранный кандидат проверяется при dt.01/.005, T200, совместное продление до T400
по прежнему критерию. Для структурного PASS нужны все шесть ошибок ≤1%, dt PASS,
физические и стационарные проверки. Валидация стоит 60000 шагов, либо 120000 при
продлении. Если структурный PASS, базовый h сравнивается с ранее проверенным
QS_P05_dt005 только при сопоставимых горизонтах/стационарности/refinement. Прежний
отчёт QS проверяется по закреплённому SHA256. Не запускаются заново 72 QS/RR или
24 условные IC-траектории: разрешённый объём этого задания — поиск и его валидация.

Потолок: 141 fit-траектория + 2 validation, **1.53 млн шагов** с продлением.
Рабочая оценка по старой калибровке — до ~50 минут; это НЕ окончательный прогноз
основного задания. Он будет закреплён по новому замеру до постановки в очередь.
Свободный диск ≥4.5 GiB, резерв 1.5 GiB, full ≤3 GiB, report ≤30 MiB. Все
полные fit-ряды остаются на ВМ; GitHub получает все структурные точки/сводки,
полные объяснения отказов, сравнительные таблицы, validation NPZ и манифест.

## Что именно означает время освобождения

Из двух исходных full/{QS,RR_QS}_P05_dt005/final.npz берётся состояние t=200,
сверенное по размеру и SHA256 с закреплённым GitHub data_manifest. Для каждой
маски 0,1,2,4 подготавливается P_iso,m rho P_iso,m / Tr(P_iso,m rho).
P_iso определяется тем же билдером. Он лежит только в секторе одного возбуждения.

Удаляется **только source_0** (kappa_in=.5 → 0); прочие гамильтониан и каналы
сохраняются. Это явное новое контрольное условие, не исходный NESS. Оно позволяет
однозначно проследить одно подготовленное возбуждение без добавления второго.
Изолированные компоненты могут сменять маски и повторно входить в изоляцию.

Сектор одного возбуждения имеет размер 81; его генератор A учитывает потерю в
вакуум через sink_2. tau_abs=integral S(t)dt до бесконечности вычисляется решением
A†T=−I. tau_iso=integral Tr(P_iso rho(t))dt вычисляется тем же способом. Это
накопленное время изоляции с повторными входами, не первое время выхода из маски.
Проверяются: совпадение A с ограничением полного source-off Liouvillian,
остатки solve, эрмитовость/положительность T, T_iso и T−T_iso, нормировка S(0),
монотонность S, конечная PSD, численное интегрирование сетки с точным остатком
хвоста. Публикуются tau_abs, tau_iso, tau_transport, S(200), S(400), остаток
интеграла после 400, исходный условный вес и все численные невязки.

Ряды не прореживаются: 201 точка на каждое из восьми состояний. Итог содержит
все маски/модели, не только быстрые. Никакая новая физическая гипотеза о временах
не присваивается исходному continuously pumped NESS без отдельного определения.
Полные исходные плотности остаются на ВМ; отчёт содержит их хеши, не матрицы.

## Второй короткий замер: исправление интегральной проверки

Первый запуск E002c_IC_RETRY_CAL_v001_r001 (код 8352ddb5f2ced04e7cc03e5f5c4a64d5519c99f8,
отчёт ae9152480a49286f414eea096672a627687a2e87) завершился FAILED. Внешнее время
27.283733 с лежит внутри первоначальных 0–94 с, но полный объём не выполнен:
3/3 IC-траектории, 12000 шагов и все 1203/123/25 записи выполнены; source-off
блок остановлен при сравнении Simpson на сетке dt=2 с точным интегралом.
Первый статус REVIEW_REQUIRED сохраняется. Приёмка его научного результата
не запрашивается. Нельзя использовать его как успешный полный замер.

Гипотеза ошибки — сетка вывода недостаточна для квадратуры быстро меняющегося
изоляционного веса. Проверка меняется содержательно, не расширением .02:
независимо считаем интеграл как дополнительные переменные расширенного ОДУ
[[A,0],[O†,0]], через отдельный expm_multiply, и прибавляем точный хвост после400.
Новые заранее фиксированные допуски: абсолютный остаток интеграла ≤1e-7,
расхождение конечного состояния двух способов expm ≤1e-9. Старые ошибки Simpson
по обоим наблюдаемым и всем маскам публикуются численно, вместе с прежним .02
и флагом прежней проверки. Это позволит проверить гипотезу по новому отчёту.
Оператор A, начальные состояния и solve для самого tau не меняются.

E002c_IC_RETRY_CAL_v002_r001 повторяет все три IC-траектории, поэтому после
изменения kernel есть новый собственный замер. Добавлены две расширенные
экспоненты до400, с четырьмя начальными столбцами. Прогноз **37 с, диапазон0–97 с**.
Основа: измеренные 23.513 с трёх IC-траекторий + примерно3 с QS-ряда (первый
процесс до отказа), 2.5 с RR-ряда, 7 с двух новых экспонент, 1 с отчёта.
Это предварительный прогноз до повторного замера, базовый допуск max(30%,60 с).
