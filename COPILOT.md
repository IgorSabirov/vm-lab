# Copilot: подключение и ожидание ответа

Репозиторий: `IgorSabirov/vm-lab`. Рабочий канал — GitHub Copilot CLI,
проверенная версия **1.0.105**. Подключение к аккаунту `IgorSabirov` и ответ
на бесплатном тарифе проверены 30 октября 2026 года. Для этого канала
не требуется назначать issue облачному агенту Copilot.

Copilot привлекается для второго взгляда на код: поиск ошибок, проверка
краевых случаев, предложение оптимизаций и способов их измерить. Научную
корректность и эффект оптимизаций проверяем отдельно. Приёмщик — пользователь.
Успешная проверка связи сама по себе не доказывает пользу для проекта.

## Обязательное правило ожидания

Последнее указание пользователя от 30 октября 2026:

> Забивай в методику ожидание без обрыва сессии с твоей стороны.
> Я буду учитывать время.

После запуска авторизации или вопроса **не завершать ход ассистента, пока
процесс работает**. Продолжать ожидание через инструмент терминала в том же
ходе, сообщая пользователю состояние не реже раза в минуту. Возврат
инструмента с идентификатором работающего процесса означает необходимость
дальнейшего опроса, а не завершение команды.

Для `ping` и `ask` тайм-аут по умолчанию отсутствует. Не прерывать запрос
лишь потому, что он длится дольше ожидаемого. Параметр `--timeout` оставлен
для явно согласованного ограничения; самостоятельно его не добавлять.
Остановка по просьбе пользователя сохраняется. Ограничения самого сервиса,
истечение кода авторизации и аварии среды возможны: сообщать точный сбой,
а не объявлять задачу выполненной или обещать невыполняемую работу в фоне.

Надпись ChatGPT «Соединение прервано. Ожидание полного ответа» сама по себе
не доказывает остановку CLI. После восстановления сначала проверить прежний
процесс по его идентификатору и забрать результат. Не дублировать вопрос и
авторизацию вслепую. Если процесс утрачен, явно сообщить, что его результат
не восстановлен, и только затем решать вопрос о новом запросе.

Каждый новый вопрос запускается **новым процессом** с актуальным окружением
и сохранённой авторизацией. Завершать ответ пользователю можно после получения
вывода и кода завершения. Предложения Copilot обсуждаются и проверяются;
они не применяются автоматически.

## Холодный старт

1. Прочитать `AGENTS.md` и этот файл из актуального `main`, закрепить SHA.
   Получить `infra/copilot_bridge.py` с того же SHA. Если локальной копии нет,
   сохранить файл через доступный GitHub-коннектор; нельзя полагаться на
   прежние временные каталоги или идентификаторы процессов.
2. В среде нужны Linux/macOS, Python 3 и Node.js с npm. Установщик сохраняет
   закреплённую версию CLI вне репозитория:

   ```sh
   python3 infra/copilot_bridge.py install
   python3 infra/copilot_bridge.py doctor
   python3 infra/copilot_bridge.py ping
   ```

3. Дождаться завершения каждой команды. `doctor` только диагностирует.
   Наличие config и HTTP 200 не подтверждают доступ к модели. `ping` посылает
   новый случайный маркер и принимает успех только при точном ответе,
   непустом выводе и коде завершения 0.
4. При `ping: OK` использовать уже сохранённый вход. Не начинать новую
   авторизацию при каждом вопросе. Если ошибка явно указывает на отсутствие
   или истечение входа, выполнить процедуру ниже. При иной ошибке сначала
   разбирать её по таблице, а не заставлять пользователя снова входить.

CLI ищется по `--cli`, затем `VM_LAB_COPILOT_CLI`, затем в
`~/.cache/vm-lab/copilot-cli/1.0.105/node_modules/.bin/copilot`, затем в PATH.
Несовпадение версии останавливает работу. Автообновление отключено;
обновление версии требует проверки флагов, тестов и живого `ping`.
Технические проверки версии и установки имеют отдельные пределы ожидания;
на запрос модели и интерактивный вход они не распространяются.

## Авторизация, только когда она нужна

```sh
python3 infra/copilot_bridge.py login
```

Запускать с интерактивным терминалом. Передать пользователю выданные CLI
адрес и одноразовый код **в промежуточном сообщении**, оставив команду и ход
ассистента активными. Пользователь подтверждает вход; ассистент продолжает
опрос того же процесса до результата и затем запускает `ping` новым процессом.
Нельзя отправить код финальным ответом и рассчитывать, что ожидающий OAuth
процесс гарантированно переживёт границу хода.

CLI хранит авторизацию в своём профиле. При недоступном системном keychain
он может предложить незашифрованный config. В доверенной среде допустим этот
вариант: скрипт выставляет права каталога 0700 и файла 0600. Стандартное место —
`~/.copilot/config.json`; при заданном `COPILOT_HOME` используется этот каталог.
Не читать и не публиковать содержимое config, токены или дампы окружения.
Скрипт не копирует авторизацию в репозиторий. Токены из переменных
`COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN` исключены из дочернего
окружения, чтобы чужая настройка не перекрыла сохранённый вход CLI.

Холодное чтение методики восстанавливает порядок подключения, а не секрет.
Если среда полностью пересоздана и авторизация утрачена, потребуется новый
device login с подтверждением пользователя. Сохранять токен в Git ради
автоматического входа нельзя.

## Вопрос о коде

Подготовить UTF-8 файл с вопросом, релевантным фрагментом кода, его SHA,
ожидаемым поведением и ограничениями. Содержимое этого файла отправляется
Copilot. До передачи убрать секреты; встроенный фильтр известных форматов
GitHub-токенов не заменяет проверку содержимого.

```sh
python3 infra/copilot_bridge.py ask --prompt-file /path/to/question.txt
```

Путь к файлу должен существовать в текущей среде. Лимит входа — 128 КиБ.
Передача выполняется списком аргументов без shell-интерполяции. Запрос
работает в пустом временном каталоге, без встроенных MCP, пользовательских
инструкций и разрешённых инструментов. Код передаёт ассистент явно;
доступ к приватному репозиторию по одной ссылке не предполагается.
Используется `--model auto` и `--max-ai-credits 30` — минимальный принимаемый
предел этой версии CLI. Это верхняя граница расхода запроса, не его измеренная
стоимость. Скрипт не оформляет подписку и не покупает дополнительные кредиты.

Результат — JSON: `status`, `answer`, `error`, `returncode`,
`elapsed_seconds`, `cli_version`, `prompt_sha256`. У `ask: OK` проверяется
получение ответа, а содержательную корректность проверяет ассистент отдельно.
Для оценки пользы нужен отдельный опыт на ранее найденной ошибке, с исходным
ошибочным кодом и заранее известным критерием; проверка соединения его не заменяет.

## Ошибки и действия

| Наблюдение | Действие |
|---|---|
| `CLI_MISSING` / `CLI_VERSION_MISMATCH` | Установить закреплённую версию; проверить явно заданный путь. |
| `AUTH_REQUIRED` | Проверить описание ошибки; выполнить device login и новый `ping`. |
| `POLICY_BLOCKED` или отказ самого инструмента терминала | Зафиксировать точный текст, проверить сеть свежим `doctor`. Не считать это доказательством плохого токена или выключенного переключателя пользователя. |
| `LIMIT_REACHED` | Сообщить ограничение сервиса; не покупать доступ и не зацикливать повторы. |
| `TIMEOUT` | Применяется только при явно заданном `--timeout`; запрос остановлен, успех не подтверждён. |
| `EMPTY_RESPONSE` / `UNEXPECTED_RESPONSE` | Связь не подтверждена ожидаемым ответом; проверить вывод, не подменять старым результатом. |
| `REQUEST_FAILED` / `LOCAL_ERROR` | Читать конкретную ошибку; не классифицировать любую ошибку как проблему авторизации. |

Прокси, TLS и сетевую политику не отключать. Скрипт наследует текущее
окружение при каждом запуске, не сохраняет адреса прокси и не восстанавливает
их из старых сеансов. Классификатор распознаёт известные сообщения, но не
заменяет диагностику. Если отказ произошёл вне скрипта, JSON может отсутствовать.

## Что установлено при разборе 30 октября 2026

Ранее ожидающие OAuth-процессы пытались продолжить после завершения хода
ассистента. Инструмент возвращал `Network access ... was blocked by policy`.
При этом настройка публичного интернета у пользователя уже была включена,
а свежие HTTP-проверки GitHub возвращали 200. Поэтому объяснение «пользователь
выключил интернет» не соответствовало наблюдениям.

После изменения порядка — показать device code в промежуточном сообщении,
дождаться авторизации в том же ходе — CLI сообщил успешный вход. Отдельный
вопрос получил ответ. В следующем ходе свежий процесс вернул `RECONNECT_OK`
без новой авторизации. Скрипт из этого репозитория затем подтвердил связь
новым случайным маркером.

Во время последующей проверки пользователь увидел сообщение ChatGPT о
прерванном соединении. Проверка ранее запущенного процесса вернула готовый
ответ Copilot, код 0, 15.171 с, без тайм-аута. В этом случае разрыв отображения
ответа не означал потери результата CLI. Это отдельное наблюдение; его нельзя
автоматически переносить на прежние ошибки OAuth.

Подтверждён рабочий порядок и место прежнего сбоя: продолжение оставленного
OAuth-процесса через границу хода. Внутренняя причина отказа инфраструктуры
не установлена; зависимость сетевого окружения от срока жизни хода — гипотеза,
а не доказанный диагноз. Методика не обещает защиту от аварии платформы.

```sh
python3 -m unittest discover -s infra -p 'test_copilot_bridge.py' -v
```
