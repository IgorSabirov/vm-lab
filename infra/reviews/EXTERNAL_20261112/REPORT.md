<a id="method"></a>
## Проверенные поправки к мнению соседей

1. **ACM-термины в отзыве переставлены.** В действующей версии 1.1 повтор той же
   командой — repeatability; другая команда с авторскими артефактами — reproducibility;
   независимые артефакты другой команды — replicability. Поэтому исполнение авторских
   тестов нашей командой не следует автоматически называть repeatability. Отношение
   команд, кода и среды сохраняем отдельно. Бейджи ACM не присваиваем себе.
2. **«Пререгистрации нет» неверно.** В проекте уже есть NOW/X27 preregistration,
   ANCESTOR_CONTRACTS, точный RUN_PLAN и бюджет. Доработка расширяет их дисциплину
   на внешние источники. W3C `hadPlan` описывает связь с планом, но само по себе не
   запрещает подмену плана. Нужны фиксированный commit, хеш и квитанция до исполнения.
3. **Дымовой ≠ автоматически exploratory.** Техническая проверка и разведочный
   научный анализ имеют разные цели. В контракте есть три режима; уже изученные
   исходы нельзя переименовать в новые подтверждающие данные.
4. **Registered Reports — внешний издательский формат.** Его Stage 2 также проверяет
   качество исполнения и обоснованность выводов, а не только формальное следование
   инструкции. Внутренний GitHub PR не объявляется принятым Registered Report.
5. **Research compendium — практика, не единый обязательный стандарт каталогов.**
   Принят минимальный самодостаточный пакет с явным составом и точкой воспроизведения.
6. **Многовариантный анализ нужен по задаче.** Объявляем точки выбора и разумные
   альтернативы. Не назначаем полный multiverse и статистическую мощность для
   каждого точного конечного вычисления.
7. **Подпись не удостоверяет чужое исполнение.** GitHub подписывает конкретную
   деятельность упаковки. Переданные с ВМ данные остаются связанными со своей
   квитанцией; подпись загрузчика не превращается в attestation вычисления на ВМ.
8. **GitHub API admin и инструменты — разные вещи.** Наличие права в метаданных
   не создаёт отсутствующий метод коннектора и не выдаёт токен CLI. Публичность
   не подписывает нас на webhook произвольного чужого репозитория: используется опрос.

Первичные источники: [ACM 1.1](https://www.acm.org/publications/policies/artifact-review-and-badging-current),
[COS Registered Reports](https://www.cos.io/initiatives/registered-reports),
[W3C PROV-O](https://www.w3.org/TR/prov-o/#hadPlan),
[GitHub attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).
Библиография соседа не считается целиком независимо проверенной; решения выше
опираются на перечисленные первичные документы и файлы текущего репозитория.

## Научные границы и адрес возврата

R126: точная реконструкция ADD и авторское соответствие остаются разными утверждениями.
R127: совместное наличие компонентов не доказывает совместимость их физических законов.
R128/U010: различимость и воспроизведение профиля не доказывают происхождение аппарата.
R129: результат ограничен заданными узлами, законом, затравкой и ёмкостью; точное решение
генератора не является шумной оценкой Монте-Карло.

IsingCauset/CDT сохраняются кандидатами для переноса/проверки подготовки носителя.
QSC, BFSS/BMN, Gordion и LargeN-YM зарегистрированы как источники для рассмотрения;
регистрация не принимает их в NOW и не ставит новый научный запуск.
Для IsingCauset явны предел j=0 при фиксированном N, различие меры и причинного закона,
а также отсутствие отождествления MC-времени с физическим. Контракт должен показать,
какая заданная предпосылка стала результатом динамики, и перечислить оставшиеся входы.
N02/N06, F02/F05 и U010 сохраняют свои состояния. Никаких новых физических PASS.

<a id="access"></a>
## Что нельзя считать уже включённым

Rulesets, Projects V2 и Discussions: файлы настройки подготовлены; коннектор не
предоставляет требуемые административные мутации. Это остаток доступа, не запрос
нового разрешения на уже порученную работу. `python tools/github_setup.py repository`
и `project` показывают планы; `--apply` использует явно предоставленный GH_TOKEN.
Скрипт не ищет и не извлекает токены. Built-in auto-add и категории Discussions
пока описаны для UI; они не считаются созданными. Запрос единственного владельца
одобрить собственный PR не навязывается как обязательный GitHub review.

OIDC используется для GitHub attestations. Федерация с провайдером пользовательской
ВМ, выдача облачных полномочий и self-hosted runner не настраивались. Для внешнего
архива требуется фактическая публикация принятой версии и её лицензионные условия.
Наличие поля DOI или SWHID не является свидетельством архивирования.

## Проверки

Локальный план: целевые проверки и один полный Development набор, ожидаемо менее
300 s, предел 600 s. Новые научные прогоны и ВМ не запускаются. Результаты и команды
сохранены в [VALIDATION.json](VALIDATION.json): 368 проверок, 72.704 s для шести наборов.
Две численные конфигурации дали максимальную ошибку 4.440892098500626e-16 при
допуске 1e-12. GitHub CI проверяется отдельно перед слиянием.
