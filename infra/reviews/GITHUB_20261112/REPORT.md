## Что исправлено при проверке

Старый транспортный тест использовал меняющийся производственный run.py/config.json. Теперь он вызывает реальную функцию reporting.write_report на ограниченном тестовом наборе. Это сохраняет проверку полноты доставки и не запускает текущую научную конфигурацию.

У проверки окружения E002 обнаружено требование фактически ограниченного адресного пространства, если cgroup не виден. CI-runner задаёт дочернему тестовому процессу реальный предел ≤8 GiB; научная проверка не ослаблена. Исходники математических моделей не изменены.

Генератор сохраняет CCC_TL_20261112, добавляет самостоятельный METHOD_20261112 и его границы. N02/N06 связаны с R129 как `updates_not_closes`. Deep links ведут в конкретные карточки. Входящие ссылки вычисляются из единственного графа.

## Что не принято или пока не включено

1. Превращать Issue Done, CI PASS или merged PR в научный успех — отклонено.
2. Пересоздавать все R как Issues — отклонено; Issues только для ближайшей работы.
3. Раскрыть частный репозиторий ради защиты ветки — отклонено. API rulesets вернул 403 с требованием Pro или публичности. Защита main на сервере не включена; merge-gate пока проверка, а не обязательное ограничение ветки.
4. Projects V2 не создан: коннектор не предоставляет эту операцию, `gh` не авторизован, браузер показывает logged-out GitHub и 404 частного репозитория. Схема полей готова. Это конкретное ограничение доступа, не отсутствие полномочий пользователя.
5. Автономные Agentic Workflows существуют ([GA 28 октября 2026](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/)), но их включение потребовало бы учётных данных/лицензии и бюджета. Детерминированные помощники закрывают текущие операции без этого расхода.
6. Кеширование, публичные Pages, автоматическое развёртывание на ВМ и автоматическое принятие scientific PR не включены.
7. Новый bridge/установщик опубликован как код, но не развёрнут на ВМ. Полное событийное журналирование — отдельная доработка worker, не выполненная этим коммитом.

## Проверки и стоимость

Проверки выполняются локально; предварительная оценка полного набора ≤300 s, менее лимита 600 s. Вычисления — короткие тестовые системы/контроль доставки, не новые научные прогоны. Результаты наборов фиксируются в [VALIDATION.json](VALIDATION.json). CI отдельно повторяет их в GitHub; его статус проверяется перед merge. Ни один тест не запрашивает ВМ.

Actions закреплены полными SHA официальных релизов checkout 7.0.1, setup-python 7.1.0 и github-script 9.0.0; Dependabot предлагает обновления через PR. Скриптовая policy-проверка покрывает явно перечисленные свойства, не заявляется полным security-аудитом. Привилегированные workflows не исполняют код PR, упавшего job или результаты эксперимента.

## Возврат к научному вопросу

Методологический отзыв содержателен как разделение обязательств: след → причинное применение → формирование соответствия → поддержание/передача способности. Он не доказывает происхождения исходных условий. Инфраструктура лишь удерживает различия и происхождение свидетельств. U010 и открытые L не закрываются этой интеграцией.
