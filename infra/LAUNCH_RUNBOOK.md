# Запуск и продолжение без повторного восстановления всей истории

Действующая инструкция, 10 ноября 2026. Адресована ассистенту: пользователь
задаёт научную задачу и существенные решения, а не выполняет за нас подготовку.

## Где выполнять расчёт — указание 10 ноября

До 600 секунд включительно по обоснованному прогнозу — песочница ИИ;
более 600 секунд — ВМ пользователя. Название основного опыта или дымовой
проверки не меняет этого правила. Короткий расчёт не переносить на ВМ только
потому, что в CLI он называется main. Не дробить опыт и не добавлять повторы
для обхода порога. Следующие шаги submit и паспорта целевой ВМ относятся к
работе, которой ВМ действительно требуется. Действующие результаты читать
на месте; это правило не требует переносить или повторять завершённые расчёты.

## Начать с текущего задания

Прочитать [CURRENT_RUN.json](CURRENT_RUN.json), затем проверить указанный job_id
через **VM Compute 81.job_status**. Наличие связи проверить work_status, если
это необходимо. Название подключения не означает текущий IP.

RUNNING/QUEUED → продолжать наблюдение существующего задания. Завершено → читать
предусмотренный отчёт и сверять время. Связь оборвалась → восстановить доступ,
не считать задание остановленным. Старый STOP, README или новая вершина main
не меняют состояние процесса и SHA уже запущенного кода. Новый request_id после
тайм-аута submit не создавать: сначала проверить прежний ID и очередь.

Запись CURRENT_RUN — адрес и датированный снимок, не онлайн-датчик. Источник
фактического состояния — свежий ответ ВМ. Запись содержит научный SHA, хеш
launcher, прогноз, разрешение, пути продолжения и следующее действие. Эти поля
не восстанавливать из памяти и не требовать от пользователя повторить их.

## Что означает поручение

«Запусти согласованный опыт» включает техническую подготовку, исправление
исполнения, нужные проверки, калибровку и основной submit в согласованном
объёме. Не завершать ход одним планом, очередным аудитом или предложением
запустить. «Продолжи» — восстановить последнее подтверждённое состояние.
«Статус» — проверить ВМ. «Сохрани опыт» — исправить повторяемый рабочий путь.

Дымовые служат уточнению и проверке исполнения. Не считать их судом над
гипотезой. Различать: дефект программы, несовпадение времени, научный отрицательный
исход, невыясненный механизм. Реальный дефект исправлять в затронутом месте;
не начинать новый общий аудит без причины. Научный вопрос сразу записывать
в [OPEN_QUESTIONS](../analysis/NOW_RESULTS_SYNTHESIS_20261106/OPEN_QUESTIONS.md)
и рядом с местом возникновения. Вопрос сам по себе не является гейтом.

Пользователь остаётся единственным научным приёмщиком. Новые закон, мера,
носитель или цель требуют его содержательного решения; уже разрешённые
технические действия — повторного разрешения не требуют. Отсутствие ответа
не равно согласию. Продолжать независимую разрешённую работу.

Для NOW 8 ноября пользователь **явно отменил технический аудит, сохранив полный
гейт времени**, и потребовал содержательный прогон 10+ минут машинного времени.
Это записанное разрешение текущего пакета, не автоматическая отмена ревизии
для любых будущих опытов. Не возвращаться за повторным разрешением или
за подтверждением этой отмены к Copilot.

## Маршрут нового согласованного запуска

1. **Переиспользовать.** Проверить текущий job, имеющиеся исходники, паспорт ВМ,
   результаты проверок и калибровки. Читать только относящиеся к задаче файлы.
   История нужна для конкретного неясного перехода, не заново целиком при каждом
   запуске. Сохранённый ответ повторно не добывать.
2. **Зафиксировать работу.** Сохранить цель, C/R/L-родителей, объём, критерии,
   разрешение и пределы в существующем протоколе. NOW: реальные количества
   вычислять `nowexp.runner.workload_inventory`, обновлять PROTOCOL, CASES и
   AMENDMENT согласованно. Не поддерживать независимые ручные числа 326/413/3083.
   Размер сетки определяется полезным вопросом; sleep, пустые повторы и подмена
   физического времени машинным не допускаются.
3. **Исправить и проверить.** Согласованная ревизия либо её явная отмена;
   затронутые тесты и дымовые в песочнице. Для NOW полный recovery smoke уже
   предусмотрен исполнителем. При пройденных проверках и отсутствии изменений
   использовать их; очередная проверка должна иметь конкретную причину.
4. **Закрепить GitHub.** Одним логическим коммитом опубликовать согласованные
   файлы; update_ref с expected_sha. Читать подтверждённое дерево этого SHA.
   Сверить Git blob и SHA256 каждого исходника. Квитанции/отчёты публиковать
   следующим коммитом: самоссылочного хеша источников быть не должно.
5. **Доставить один пакет.** `launch_control.py bundle` собирает сжатый JSON
   из закреплённой квитанции и дерева. Если ровно эта версия уже установлена
   и проверена, использовать её. Иначе один upload и существующий BOOTSTRAP,
   отдельный неизменяемый каталог code. Не переносить 56 файлов по одному,
   не исправлять научный код только на ВМ. Большие файлы читать ограниченными
   порциями без вывода всего содержимого в диалог.
6. **Измерить время.** Использовать применимую калибровку целевой ВМ либо
   выполнить недостающий ограниченный замер. Паспорт CPU/квот/BLAS/потоков,
   RAM, диска и версий обязателен; не пересоздавать его без изменения среды.
   В NOW стоимость считать по измеренным cost_stratum и фактическим задачам.
   `launch_control.py forecast` воспроизводит арифметику, не выдаёт разрешение
   запуска. Обосновать переносимость страт, исходного блока и диапазона;
   учесть I/O ровно один раз. Прогноз закрепить **до** основного submit.
7. **Запустить.** Проверить отсутствие уже принятой заявки, точный SHA,
   полномочие и текущий гейт. Один уникальный request_id. Проверить job_status
   и движение CHECKPOINT. Только после этого говорить «запущен»; QUEUED значит
   «в очереди». Сохранить адрес задания и датированный снимок в CURRENT_RUN.
8. **Получить и вернуть результат.** Сначала сверить план/факт полного времени,
   CPU, выполненной работы и среды, затем интерпретировать. Для текущего MCP
   PROCESS.json появляется после выхода; его отсутствие во время работы нормально.
   Сохранить предусмотренный отчёт по действующему каналу GitHub, прочитать его
   на одном фиксированном ref и вернуть изменения в тот же научный реестр.
   Тяжёлый архив на ВМ не перечитывать без соответствующего поручения.

Полный source_digest NOW включает также документы. Если изменились только
инструкции/статус, установленный неизменный научный SHA продолжает работать;
не переиздавать его квитанции под новой вершиной main. Для исполнения нового
SHA соблюдать контракт исполнителя, не копировать старую аттестацию как новую.

## Фактический урок запуска 8 ноября

У полного пакета 3083 задачи: фактическая длительность процесса 3352,80 с
(55,88 мин) при прогнозе 2368,78 с (39,48 мин). Это +984,02 с / +41,54%;
верхнюю границу 3316,29 с превысили на 36,51 с. Жёсткий cap 3600 с не превышен:
запас 247,20 с. Статус гейта — REVIEW_REQUIRED. Все задачи завершены,
technical_pass=true; этот технический флаг не принимает научный результат.

Разложение по сохранённым task timers:
классический блок — 572,21 с против 438,49 с прогноза;
волновой блок — 2548,58 с против 1702,44 с;
нестратифицированные прежние случаи/контроли — 6,63 с.
Сумма task timers — 3127,41 с; остаток полного wall time — 225,39 с.
Память достигла 578,11 MiB из 4096 MiB; выходы 220,54 MB из 1 GiB.
Среда совпала с паспортом калибровки. Данных об OOM, нехватке диска или смене
среды нет. Время добавилось преимущественно внутри волновых задач, не при ожидании
очереди или сборке архива.

Причина недооценки: в каждом волновом cost_stratum была одна измеренная точка
(detuning 0,07; read_wait 32), а её скорость масштабировали на 11 detunings и
4 waits. В основном Ising/CDT-волны выходили существенно медленнее этих проб:
например, Ising m16 finite_dark — 150,27 с против 63,07 с; отношение 2,38.
Отдельные волновые страты дали 1,5–2,38 от ожидаемого. Сама классификация
потеряла заметные различия по detuning/read_wait; ±40% не покрыл их и оказался
чуть уже факта. Это проверенное объяснение ошибки прогноза; точную зависимость
от отдельных параметров следует использовать в следующей калибровке.

Для следующего аналогичного пакета включать в выбор калибровки края detuning и
read_wait либо разделить их на подстраты, измерить разброс и расширить инженерный
диапазон на его фактических основаниях. Не менять оценку этого завершённого запуска
задним числом. Полные числа и доказательства сохранены в CURRENT_RUN.json.

## Мелочи, уже стоившие времени

| Сбой | Рабочее действие |
| --- | --- |
| Старый STOP/«не запускали» принят за настоящее | CURRENT_RUN + свежий job_status; история отдельно |
| 326 в протоколе, 413 в runner | Единый workload_inventory; исправить декларацию, не отвергать опыт |
| Нет PROCESS при RUNNING | Читать checkpoint; ждать выхода, не перезапускать |
| STATUS.cursor=0 весь прогон | Читать CHECKPOINT, не выдавать стартовый STATUS за прогресс |
| Разрыв submit/чата | Проверить прежний ID и очередь; не создавать вторую заявку |
| Прогноз по случайной быстрой задаче | Калибровка нужных страт + запись/диагностика + предел |
| Слишком короткий фактический прогон | Проверить план/факт объёма и оценку; не дорисовывать минуты |
| Поломка JSON после чтения большого файла | MCP unwrap, isError, ограниченные порции, next_offset; не парсить усечённый JSON |
| Потеря источника/повторный перенос всех файлов | Один закреплённый bundle; сверка хешей; повторное использование копии |
| Изменение IP стало переустановкой/новым ACME | [Существующий reconnect](VM_CONNECTION_RUNBOOK.md); меняется адрес, не архитектура |
| Ошибка приёмки после дорогого расчёта | Сохранить сырые данные; исправлять отчёт офлайн, когда это возможно |
| Тест назван доказательством или запретом науки | Техническая исправность, наблюдение и научный вывод раздельно |
| Пользователь снова объясняет разрешения | Точное решение и область хранятся рядом с запуском; не спрашивать повторно |

При отказе действующего соединения пользоваться готовым reconnect, без новой
ACME-разработки, очистки ВМ и перезапуска worker. Секретные URL/токены не сохранять.
Недоступность связи не доказывает остановку ВМ. Перезапуск ВМ прерывает расчёт.

## Команды помощника (выполняет ассистент)

```bash
python infra/launch_control.py observe --record infra/CURRENT_RUN.json --job /tmp/job.json --checkpoint /tmp/checkpoint.json --observed-at <UTC-время-чтения-ВМ> --output /tmp/observation.json
python infra/launch_control.py bundle --repo /path/to/pinned-checkout --receipt /tmp/SOURCE.json --tree /tmp/tree.json --output /tmp/BUNDLE.json
python infra/launch_control.py forecast --repo /path/to/pinned-checkout --calibration /tmp/CALIBRATION_PROCESS.json --base /tmp/BASE.json --output /tmp/FORECAST_ARITHMETIC.json
python -m unittest discover -s infra -p test_launch_control.py -v
```

BASE содержит `tasks`, `seconds`, `reference` измеренного неизменённого блока.
Входы observe принимают сохранённые MCP-ответы; при завершении добавить
`--process /tmp/PROCESS.json`. Помощник не отправляет задания, не получает
доступ к аккаунтам и не заменяет существующие гейты. Вызовы GitHub/ВМ выполняет
ассистент через подключённые инструменты; перекладывать команды на пользователя
при работающем доступе не нужно.

observed-at — время фактического получения ответов ВМ; его записывает ассистент
при чтении. Повторная обработка старого JSON не является свежей проверкой.
Если время чтения не передано, observed_at_utc остаётся null, отдельно хранится
время обработки. Для блокировки дубля и продолжения нужен свежий статус.
