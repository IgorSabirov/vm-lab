21 ноября 2026. Рабочая задача — улучшение учёта частичных результатов, без нового физического прогона и без изменения научных статусов.

Цель доработки — сохранять достоверную точку продолжения при изменении требований и материалов. Количество записей и уровни исходных свидетельств не увеличиваются.

## Устройство исправления

В существующую карту добавлено `reviewed_criterion` у 80 имеющихся findings. Хеш включает ID и точный текст критерия, ключ поставки, этапы и ветви. Миграция закрепляет исходное требование; результаты, уровни, источники и области findings сохраняются.

Для карты v2 приёмочная запись и отчёты producer/replay содержат `progress_context`. `acceptance_context(plan, task, check)` связывает критерий, `progress_target` и весь явно выбранный набор версий входов. Это консервативная проверка применимости сохранённой приёмки. После пересмотра входа она не переносится автоматически. Полная запись по всем критериям по-прежнему отдельно управляет допустимостью закрытия Issue.

`R135_PIPELINE_STATUS.json` передаёт `criterion_completion_evidence`, точный `source_sha` и канонический `pipeline_sha256`. Доска проверяет их до первой записи. Ручные поля сохраняются; при расхождении видны ручное и вычисленное ближайшие действия. Ошибка синхронизации оставляет квитанцию выполненной части и не объявляется научным опровержением.

`tools/r135_progress_review.py` формирует существующий артефакт сравнения, добавляя отображение «изменённый файл → критерии → адреса для review». Если путь ещё не связан с критериями, он остаётся явным предупреждением. Изменённая запись подтверждает факт рассмотрения адреса, но не научную состоятельность исправления. Редакторские изменения не требуют выдумывать физический результат.

## Проверка

Адресные наборы выполняются командами:

```sh
python -m unittest discover -s tests -p 'test_r135*.py'
python -m unittest discover -s tests -p 'test_project_sync.py'
python tools/r135_pipeline.py --check
git diff --check
```

Регрессии включают проверку реального Git-удаления/переименования, имён файлов с переводом строки, подложенного заголовка Issue, несовпадающих SHA/карт, отказа второй мутации, смены области без findings и попытки обновить контекст только в приёмочной записи, оставив прежние отчёты исполнения. CLI сравнения использует Git-снимки даже при изменённой рабочей копии.

Основной integrity-набор теперь обнаруживает `test_r135*.py`, поэтому проверки прогресса и его сравнения исполняются вместе с исходным контролем поставок.

## Следующий содержательный шаг

Приоритет работы сохраняется за конкретным результатом и его входами. Число критериев-потребителей не означает готовность стольких запусков; физическая обратная связь не превращается в цикл глобальных запретов. Для первой собственной подготовки нужен общий идентификатор через паспорт, фазовые входы, историю и наблюдательные результаты. Текущий уровень `applied` требует идентификатор, но его физическую обоснованность по-прежнему необходимо проверить по первичным артефактам.

Счётчики 6/51/29/0/0 сохраняются. Исправление не повышает R135 или связанные R/U/D. Для включения новой синхронизации необходимы merge проверенного кода в main и успешный live readback; наличие файлов и тестов в draft PR этого факта не заменяет.
