# VM Compute: восстановление HTTPS после смены IP

Статус 2026-11-07: HTTP-версия исполнена на ВМ и не восстановила сертификат.
TLS-версия подготовлена и проверена локально; на пользовательской ВМ ещё не исполнена.
Это восстановление существующей установки, не развёртывание
API и worker с пустой машины.

Исходная неисправность: сертификат истёк и относится к прежнему адресу.
Рабочие API/worker активны. HTTP с пользовательского Mac до ВМ проходит;
доступность с узлов проверки Let's Encrypt ещё не доказана. Предыдущая выдача
через Certbot standalone завершилась `connection: Error getting validation data`.

Повтор через собственный webroot-сервер также завершился ошибкой: соединения
с двух адресов дошли до HTTP-обработчика, но полный запрос не был получен за
10 секунд. Это не доказывает, где именно теряются данные; сетевой фильтр —
гипотеза. Конфигурация и сертификат успешно восстановлены из backup,
API и worker остались активны. Ошибка сохранения отчёта на `/var/log`, который
не проходит строгую проверку владельцев/прав, исправлена переносом отчёта
в уже проверенный закрытый каталог `/var/lib/vm-lab/acme` без ослабления прав.

Следующая попытка запускается с `--tls`: TLS-ALPN-01 через порт 443. Скрипт
получает официальный lego **5.6.0**, проверяет SHA-256 архива по зафиксированным
digest релиза до исполнения; для AMD64:
`f02fc11b6f56b97e387fa7caa0268f86f5a336953b22458e6430e4651fea439a`.
Использует отдельное хранилище `/etc/vm-lab/lego`, без изменения старых ACME
ключей и архивов. Email для нового ACME аккаунта не задаётся; идентификатор
аккаунта `vm-lab-bridge`. Секреты остаются на ВМ.
API останавливается только на попытку выдачи (до 150 секунд), затем запускается
в finally при успехе, ошибке и тайм-ауте. Обработчики HUP/TERM обеспечивают этот
же путь при обычном обрыве SSH; для таймера дополнительный ExecStopPost
запускает API после остановки службы. Worker и SSH не останавливаются.
Сам факт поддержки ALPN не гарантирует доступность с узлов CA: результат ещё
не получен. Установщик не объявляет локальный тест внешним подключением.

## Что делает recover_vm_bridge.py

1. Читает актуальный IPv4 из метаданных Yandex Cloud и проверяет DNS sslip.io.
2. Сохраняет конфигурацию, развёрнутый сертификат и ключ, параметры продления
   в закрытую резервную копию `/var/backups/vm-lab-bridge-*`.
3. В исходном HTTP-режиме использует Certbot **webroot** и ограниченный HTTP-01
   обработчик на порту 80. Он отдаёт только challenge-файлы. В журнал попадают
   пришедшие запросы проверки. Одна попытка выдачи, максимум 150 секунд;
   повторной выдачи нет, если текущий сертификат подходит и живёт более 48 часов.
4. Сохраняет старый токен и остальные параметры `server.json`, меняет public_ip,
   развёртывает сертификат (HTTP: существующий deploy_cert.py; TLS: проверенная
   пара из lego с сохранением владельца и прав файлов), проверяет TLS с проверкой имени
   и доверия, MCP initialize и tools/list через локальный HTTPS-слушатель.
5. Устанавливает собственную службу и таймер: через 2 минуты после старта
   таймера (включая загрузку ВМ) и затем раз в 12 часов. Старый таймер Certbot
   отключается только после успешной проверки и установки нового.
6. При ошибке возвращает сохранённые настройки и развёрнутый сертификат.
   Новые сертификаты, уже выпущенные центром, не отзываются. Архивы ACME не
   удаляются; собственные изменения файла renewal/vm-lab.conf откатываются.

Не изменяет исходники API/worker, рабочие данные, задания, результаты, GitHub
ключи и firewall. API кратковременно перезапускается, worker не перезапускается.
Новый IP означает новый URL плагина: таймер не может менять настройки ChatGPT.
Статический IP скрипту не нужен. Общий сетевой запрет доступа от CA скрипт
не обходит; при таком исходе выдаёт собранный отчёт вместо ложного успеха.

## Запуск

Остановить старый диагностический HTTP-пробник или ожидающий ввода Certbot
через Ctrl+C в его терминале. В SSH-сессии ВМ:

```bash
sudo python3 -I /path/to/recover_vm_bridge.py --tls
```

После `BRIDGE_LOCAL_OK` скрипт выведет URL с сохранённым токеном для поля
сервера MCP. Его нельзя публиковать. Проверка соединения из ChatGPT остаётся
необходимой: локальный тест не доказывает внешнюю доступность.

Журнал без токена: `/var/lib/vm-lab/acme/bridge-recovery.log`.
Фактическая длительность зависит от DNS, сети и CA; локальные операции малы,
выдача ограничена 150 секундами, загрузка lego — 90 секундами,
systemd обслуживание — 420 секундами. Новый таймер сохраняет выбранный --tls.
Сбой не означает успешного восстановления. Для ручного восстановления backup
содержит manifest.json с исходными путями, владельцами, режимами и копиями.

## Проверки

```bash
python3 -m unittest -v infra/test_recover_vm_bridge.py
```

Пять тестов пройдены в локальной среде:
сохранение токена и отказ при неоднозначности; реальная HTTP-выдача challenge
с запретом посторонних путей/симлинков; откат заменённого и нового файла;
реальный локальный TLS и MCP JSON/SSE, включая отказ на неверное имя сертификата.
добавлена проверка запуска API после ошибки CA и тайм-аута TLS-выдачи, worker
не затрагивается. Это имитация отказов, не успешная выдача реального сертификата.
Управление systemd в новой TLS-ветке и публичная выдача ещё не проверены на ВМ.
Тест файлового отката подменяет root-only проверки владельцев и fchown, поскольку
песочница не является целевой root-средой. Секретов в этом комплекте нет.
