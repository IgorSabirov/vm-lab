# Подключение VM Compute, 27 октября — 7 ноября 2026

Назначение архива: повторять рабочий способ с новым IP, не заново разрабатывать
мост. Сохранено по прямому запросу пользователя «Сохрани на хабе все танцы
с бубнами чтоб в следующий раз тебе нужно было только айпи поменять».
Практический вход: [VM_CONNECTION_RUNBOOK.md](../../VM_CONNECTION_RUNBOOK.md).
Установка уже работает; этот архив не является командой переустановить её.

## Итог и границы знания

7 ноября сертификат для `vm-158-160-159-114.sslip.io` и `158.160.159.114`
получен существующим Certbot через standalone HTTP-01 на самой ВМ.
Действителен до 13 ноября. Deploy hook, HTTPS, MCP, worker и включение таймера
прошли проверку в пользовательском терминале. Затем ассистент вызвал
`VM Compute 81.work_status`: worker responsive=true, active_job=null,
установочный self-test completed/exit_code=0. Научных заданий эта проверка
не запускала. Это не проверка старого GitHub sync или научных результатов.

На прежнем IP `158.160.130.220` не помогли ни повторный HTTP-01,
ни корректно сформированный TLS-ALPN-01, ни свежая установка API/worker.
Успех пришёл после смены динамического IP при том же ID ВМ и внутреннем адресе.
Это свидетельство зависимости от адреса/сетевого пути. Точное место и причина
потери данных не установлены. Не утверждать, что доказана блокировка провайдером,
что ошибочна группа безопасности, или что стирание ОС исправило соединение.

## Как было 27 октября

В восстановленном контексте пользователь запускал `bash ~/Downloads/vm_direct.sh`
на Маке; этот установщик передавал код по SSH и вызывал Certbot внутри ВМ.
Первый успех около 12:40 UTC (15:40 Москвы), сертификат до 3 ноября;
API, worker, таймер активны, HTTPS проверялся с Мака. Позже добавлялось
DNS-имя sslip.io к IP-сертификату командой Certbot `--expand` и deploy hook.
Нет подтверждения, что сертификат выпускался на Маке/у ассистента и переносился
на ВМ. У ассистента прямой SSH также был недоступен из его среды.

Сохранены извлечённые исходники того установщика. Старые cleanup/finalize
включают удаление пользовательских файлов; network содержит попытку резервировать
статический IP. Это исторический код, **не маршрут смены IP и не команда к запуску**.
Свежая сборка 7 ноября отключала эти действия, меняла namespace на vm-compute
и оставляла исходные API/worker. Исходники декодированы для чтения, без base64.

## Ошибки ассистента, которые нельзя повторять

- Продолжать придумывать ремонт после прямого требования пользователя начать
  с нуля. Исполнять выбранный им объём; не подменять решение своей осторожностью.
- Смешивать Mac и VM, писать обёртку SSH при уже открытой сессии ВМ.
- Тестировать новый ACME-клиент только моками и объявлять готовность, не проверив
  установленную версию библиотеки. Не писать клиент заново при рабочем Certbot.
- Объявлять протокол неподдерживаемым по `StopIteration`/`NotImplementedType`.
- Путать локальную проверку с соединением из ChatGPT; объявлять полный откат
  без проверки всех затронутых состояний; выдавать новый скрипт за старый успешный.
- Продолжать одинаковые CA-запросы после подтверждённого connection error
  или установку новых пакетов, когда рабочие зависимости уже есть.
- Обещать восстановление на пустой машине, если комплект зависит от venv на старом диске.

Цена инцидента по оценке пользователя: около 3,5 часов и примерно 15% бюджета
кредитов. Это оценка пользователя, не измерение биллинга. Техническая задача
должна оставаться короткой; экономия достигается применением сохранённого
решения и остановкой при известном отказе, а не новыми обходами без оснований.

## Исходники

Каталог `sources/` содержит точные сохранённые файлы и декодированные payload;
их SHA-256 и происхождение — в `SOURCE_MANIFEST.json`.

- `successful_finish_158_160_159_114.txt`: **точный успешный** блок 7 ноября.
- `fresh_original/`: читаемые компоненты свежего API/worker/установщика;
  `fresh_original.sh`: полный исторический установочный блок с контрольной суммой.
- `continue_install.txt`: продолжение через историю команд, переиспользование venv.
  Зависит от истории интерактивной оболочки, не предназначен для холодного старта.
- `original_20261027/`: извлечённые компоненты первоначальной установки;
  cleanup/network/finalize исторические, не запускать для смены адреса.
- `vm_repair_dns.py` и его тесты: последняя исправленная экспериментальная
  TLS-ALPN-ветка; исправление кода не дало сертификат на прежнем IP.
- Первые HTTP/lego-версии уже в истории Git:
  `9b535420673c6dbfd58aa16b958f3745e82b4dbb` и
  `0a305b97ab59c613b51068dd197ac1a541c8f131`.

Полный автономный reinstall на пустой Ubuntu с загруженными зависимостями
не проверен этим архивированием. Комплект исходников сохранён; wheel-пакеты,
закрытые ключи, ACME account и server.json в Git не копировались.
Повторяемый штатный маршрут для сохранившейся ВМ — `infra/reconnect_vm.py`.
