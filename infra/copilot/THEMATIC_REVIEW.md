# Автоматическая тематическая проверка научных обновлений

Каждое научное обновление автоматически запускает **одного native Copilot CLI в корне полного checkout vm-lab**. Copilot сам читает репозиторий, ищет по файлам и реестрам, прослеживает схемы и при необходимости использует GitHub MCP для Issues, PR, комментариев и истории.

## Поток

1. GitHub фиксирует событие или периодическая сверка обнаруживает пропущенное изменение.
2. Сборщик сохраняет только точное событие и его версии в `EVENTS.json`. Полный корпус не собирается, не сериализуется и не пересылается в prompt.
3. Actions checkout'ит репозиторий. Copilot CLI запускается в его корне и самостоятельно исследует материалы. Модельный токен используется для inference; отдельный `GITHUB_TOKEN` имеет только read-доступ к репозиторию и GitHub MCP.
4. Copilot возвращает краткий отчёт. Доверенный publisher сохраняет отчёт и квитанцию в отдельной ветке и draft PR. Исходные реестры и научные статусы не меняются.

## Минимальный отчёт

Не более 350 слов:
- что изменилось;
- какие направления/критерии затронуты (точные адреса);
- важные новые связи, противоречия или пробелы;
- один следующий проверяемый вопрос/тест;
- что осталось непроверенным.

Не перечислять всё прочитанное и не пересказывать корпус. Если существенных находок нет, сказать это прямо. Ссылки без чтения не считаются свидетельством; текстовое сходство не называется статистической корреляцией. Гипотезы не объявляются доказанными. Отчёт не является научной приёмкой.

## Безопасность и границы

- Copilot работает с локальным checkout и read-only GitHub MCP.
- Запись файлов, shell-команды, commit и push Copilot запрещены.
- Модельный токен не получает права записи в репозиторий.
- Отдельный publisher пишет только фиксированные файлы отчёта/квитанции и техническое состояние мониторинга.
- Пустая сверка обновляет технический монитор и не вызывает модель.
- Повтор одного и того же события определяется сохранёнными версиями; пропущенные устойчивые изменения подбираются периодической сверкой.
- Неполный доступ, непрочитанные внешние источники и ограничения контекста указываются в кратком отчёте, а не маскируются заявлением о полном исследовании.

## Проверка

Сквозной тест должен подтвердить, что Copilot действительно работает в корне checkout, читает заранее неизвестный тестовый файл из реестра и открывает указанную Issue через GitHub MCP. Наличие ссылки в prompt или успешный ответ модели сами по себе не подтверждают чтение. Фактический результат фиксируется в `DELIVERY.json` и Actions run.

Реализация: `infra/copilot_thematic_native.py`, `infra/copilot_thematic_events.py`, workflow `.github/workflows/copilot-thematic.yml`. Старые пакетные модули `copilot_thematic_corpus.py` и `copilot_thematic_review.py` больше не входят в рабочий workflow; сохранены для истории и сравнения.
