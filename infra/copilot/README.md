# GPT ↔ Copilot: управление реестрами и внешними моделями

**Фактическое состояние, 12 ноября:** исходный `/vm-lab` оператор через gh-aw
не прошёл первый inference и не опубликовал PR. Прежнее утверждение о его готовности
на Free было преждевременным. Тот же PAT и CLI 1.0.103 успешно ответили через
штатный native Auto за 3,299 s: [контроль 43229879097](https://github.com/IgorSabirov/vm-lab/actions/runs/43229879097).
Токен менять не требуется. [Диагноз и граница вывода](reports/CONNECTION_DIAGNOSIS_20261112.md).

Ограниченный рабочий кандидат для первой задачи: владелец отправляет
`/vm-lab-native-pilot` в Issue #16. Доверенный сборщик читает закреплённые источники
и запускает проверки; native Auto получает только JSON-контекст без инструментов;
отдельный publisher создаёт draft PR с двумя фиксированными файлами отчёта.
Проверяется фактический SHA PR. Это проверка полезного пути до публикации,
а не готовый универсальный редактор реестров. Повтор при существующем PR/отчёте
блокируется до обращения к модели. Ни VM, ни платная подписка не включаются.

Первый отчёт уже получен за 21,379 s и сохранён в main через
[PR #25](https://github.com/IgorSabirov/vm-lab/pull/25). При первом запуске Actions
создал ветку, но открытие PR вернуло 403 из-за настройки разрешений репозитория;
тот PR открыл GPT через подключение владельца. После изменения настройки
`/vm-lab-native-publish` в Issue #16 проверяет только публикацию: сверяет хеш
сохранённого отчёта и открывает отдельный draft PR с `PUBLICATION_CHECK.json`.
Модель не вызывается. Общий publisher умеет продолжить после частичного сбоя:
проверяет дерево/родителя существующей ветки, сохраняет чужие изменения и
переиспользует уже открытый PR. В квитанции нет преждевременного PASS:
факт публикации устанавливается по автору PR и связанному запуску Actions.

Поручение владельца от 12 ноября 2026, [задача #14](https://github.com/IgorSabirov/vm-lab/issues/14).
Copilot получает ответственность за техническое ведение реестров, поиск публичных
реализаций и подготовку их интеграции. GPT формулирует научную задачу, проверяет
содержательный результат и обсуждает противоречия. Пользователь принимает научные
выводы. ВМ оставлена резервом; подходящие разрешённые проверки выполняются в GitHub.

## Как передать задачу без ручного переноса между моделями

GPT создаёт Issue или комментарий **от имени владельца**, начинающийся с `/vm-lab`.
Пример готовой команды:

```text
/vm-lab
Задача: проверь связи result:R122 с question:U010 и реестром предпосылок.
Используй текущий main и укажи его полный SHA. Новую физическую трактовку не принимай.
Исправь только доказуемые ошибки навигации/синхронизации. Для новых смысловых связей
укажи точный источник, основание и границу. Пересобери производные представления,
выполни проверки и опубликуй один draft PR с отчётом.
```

Для поиска внешних моделей:

```text
/vm-lab
Найди до пяти публичных реализаций совместной динамики меток и контактной структуры
для question:U010/result:R122. Сначала прочитай существующий SOURCE_INDEX, исключи
дубли. До трёх запросов поиска. Проверь commit, лицензию, реализованный закон,
авторский контроль и какие предпосылки даны. Не исполняй внешний код. Сохрани
сравнение, отвергнутые варианты и обоснованные предложения связей в draft PR.
```

Workflow [Copilot repository operator](../../.github/workflows/copilot-operator.md)
компилируется штатным **GitHub Agentic Workflows** и исполняется независимо от чата.
Принимаются команды администратора; случайный посетитель публичного репозитория
не получает право расходовать квоту. Доступны и ручные Actions → Run workflow.
Ссылки на Issue/PR автоматически попадают в [наш Project](https://github.com/users/IgorSabirov/projects/2).

Цепочка: задача → чтение реестров/поиск GitHub → правки в рабочем каталоге →
проверки → проверка выходного патча → draft PR → проверка его точного SHA → GPT.
Открытый PR и его отчёт — место обратной связи. Новый уточняющий `/vm-lab` запрос
должен ссылаться на него и содержать новый довод, а не повторять прежнее поручение.

## Что выполняет автоматизация

| Обязанность | Реализация и граница |
|---|---|
| Читать карточки и связи | `tools/copilot_context.py summary/card/neighbors/sources`; существующий INDEX, 66 предпосылок и SOURCE_INDEX, без нового научного реестра |
| Искать публичные модели | Встроенный GitHub MCP: поиск репозиториев, чтение файлов и коммитов; поиск не означает воспроизведение результата |
| Вести реестры | Пары Markdown/JSON, доказуемые исправления, компилятор связей, предложения новых связей с источником |
| Готовить интеграцию | Проверенные метаданные, точный upstream SHA, лицензия, DRAFT-контракт и явные неизвестные критерии |
| Исполнять проверки | Ограниченный набор команд и существующие тесты на GitHub-hosted Ubuntu; внешнее содержимое не исполняется автоматически |
| Публиковать | Один draft PR через safe outputs; модель не получает write-token репозитория |
| Проверять опубликованное | `copilot-pr-validation.yml` находит PR по ссылке на исходный run и проверяет его фактический head SHA без секретов |
| Продолжать после обрыва чата | GitHub run и артефакты; сначала забрать тот же результат, не отправлять дубликат |

Автоматический оператор может публиковать только реестровые файлы, DRAFT-контракты
и `infra/copilot/reports/`. Исполнимые адаптеры и новые расчёты идут отдельной
согласованной задачей/PR. Нативный профиль `external-models` подготовлен и для такой
работы в CLI/IDE или платном Cloud Agent. Это граница первой роли, не ограничение
на всю последующую интеграцию. Подключение к ВМ не требуется для работы оператора.

Нет автоматического научного PASS, закрытия U/N, смены исходного закона, обновления
принятых upstream pins или merge. Предполагаемое знание Copilot о GitHub не заменяет
проверку актуального файла. PR от GITHUB_TOKEN сам не запускает обычный PR CI:
поэтому добавлена отдельная проверка точного SHA. Она не подменяет `merge-gate`;
когда GPT переводит проверенный PR из draft в ready, обычный PR pipeline стартует
от пользовательского действия и должен пройти до слияния.

Native Auto на Free проверен прямым запросом; готовность всего оператора отдельно
подтверждается опубликованным результатом. Pro также
даёт cloud/review за $10; Pro+ расширяет объём и выбор моделей. Переключение тарифа
не меняет научные полномочия и не требует миграции реестров.

Наш экономный профиль: `gpt-5.6-luna-free-auto`, до 12 ходов, 30 AI Credits на основной агентский run,
до 60 за 24 часа для основного workflow; проверка выходов имеет отдельный предел
10 AI Credits. Это **не общая квота подписки** и не точная стоимость запуска.
Суммарный расход включает оба этапа; фактическую стоимость брать из run accounting.
Нет AI-опроса каждого push, расписания AI-поиска и автоматического повторения целой
сессии (`max-retries: 0`). Уже работающий монитор upstream продолжает дешёвую
проверку метаданных по своему расписанию. Повторный run после UNKNOWN требует
сначала просмотра прежних журналов. Ограничения бюджета/времени объявлены заранее.

Основной агентский шаг — до 6 минут; job — до 10, остальные jobs ограничены явно.
Логи/артефакты хранятся 7 дней; полезный итог сохраняется в PR. Ни тариф, ни платные
превышения автоматизация не включает. На платном плане владелец сохраняет бюджет
дополнительного расхода равным нулю, если не разрешил иное. Мы не утверждаем, что
эта настройка аккаунта уже проверена или изменена данным PR.

В публичном vm-lab стандартные GitHub-hosted runners бесплатны по текущим правилам
Actions. Хранилище артефактов, larger runners и облачные песочницы имеют отдельные
правила оплаты. Подписка Copilot не покупает неограниченные вычисления. Для наших
небольших CPU-проверок используем Actions; иной ресурс/время сначала оцениваем,
ВМ остаётся резервом. Происхождение результата и численная проверка сохраняются.

## Единственная необходимая авторизация для личного репозитория

1. Создать [fine-grained PAT](https://github.com/settings/personal-access-tokens/new?name=vm-lab-Copilot&description=vm-lab+Copilot+inference&copilot_requests=read)
   от личного аккаунта IgorSabirov: **Account permissions → Copilot Requests: Read**.
   Ему не нужны права записи содержимого проекта.
2. Сохранить в [Actions secret репозитория](https://github.com/IgorSabirov/vm-lab/settings/secrets/actions/new)
   с именем **`COPILOT_GITHUB_TOKEN`**. Само значение в чат не отправлять.
3. Выполнить preflight и первую `/vm-lab` задачу. Наличие секрета —
   `AUTH_CONFIGURED_NOT_VERIFIED`; только завершённый содержательный ответ
   подтверждает inference. Остаток квоты и доступ аккаунта заранее не выдумываются.

`PROJECTS_TOKEN` и обычный `GITHUB_TOKEN` не заменяют этот вход. Новый режим
`copilot-requests: write` у gh-aw рассчитан на централизованный биллинг организации;
для личного репозитория он не включён. Дополнительного широкого PAT для создания
PR не требуется: write-permissions получает отдельный safe-output job.

## История, проверка полезности и сопровождение

Адресная диагностика inference: владелец может отправить ровно `/vm-lab-diagnose`
в комментарии Issue. Workflow `Copilot native inference diagnostic` выполняет
один фиксированный запрос через native CLI 1.0.103 с `--model auto`, без gh-aw
API proxy, инструментов, файлов проекта или custom instructions. Предел: 30 AI Credits (минимум, принимаемый CLI) и 120 секунд.
Это потолок, не ожидаемая стоимость одного короткого ответа. Он не изменяет защиту рабочего оператора, не создаёт PR,
не покупает квоту и не принимает произвольный prompt. Артефакт
`copilot-native-control` содержит только краткий ответ/ошибку с удалением токена.
Это различающий контроль для 502; `NATIVE_INFERENCE_PASS` ещё не означает,
что рабочая цепочка ведения реестра прошла end-to-end.

Сохранён [изолированный мост](../copilot_bridge.py): CLI 1.0.105, без tools и скрытого
чтения проекта. Его прежний протокол [COPILOT.md](../../COPILOT.md) действует для
текстовых рецензий. Новая роль оператора не переделывает этот режим в агента ВМ.

Исторические полезные результаты: [дефект проверки эрмитовости](../../analysis/COPILOT_RESEARCH_PILOT_v001/RESULT.md),
[проверка предложенной оптимизации](../../analysis/COPILOT_OPPORTUNITY_v001/RESULT.md),
[двухходовая сессия](../../analysis/COPILOT_RELIABILITY_v001/RESULT.md).
В последнем случае возобновление доказано между завершёнными процессами, не после
утраты машины. В новом контуре устойчивость обеспечивает GitHub Actions, а не UUID
локального процесса. Производительность предложения проверяется измерением:
один совет Copilot ранее замедлял RHS в 16–30 раз, затем был отозван.

Для каждого пилота сохранять: найденные и подтверждённые дефекты, отвергнутые
замечания, реально принятые изменения, время и измеренный расход, оставшиеся
неизвестные. Число ответов/PR не является мерой научной продуктивности.

Компилятор gh-aw 1.2.2 закреплён на `399a445fe2d8926c616b54b1b82a16b5b2be4445`.
`tools/compile_copilot_workflow.py --compiler /path/to/verified/linux-amd64`
проверяет SHA256 бинарника, компилирует, ограничивает все framework jobs и срок
артефактов, записывает `COMPILE.json`. CI сверяет хеш исходника и lock-файла и
обычную workflow policy; для сгенерированного YAML исключений из policy нет.
Новый compiler/CLI не обновлять вслепую. Ограничения в тексте prompt (например,
число прочитанных файлов) не выдавать за отдельный технически enforced лимит.
