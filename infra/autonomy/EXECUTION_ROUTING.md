# Маршруты и бюджеты вычисления — 15 ноября 2026

Прямое решение владельца: независимые полные реализации/секции матрицы — Actions;
непрерывная интеграция, не помещающаяся в hosted job с запасом, — ВМ одним процессом.
Это инженерная политика, не изменение S3/S2/BH1, критериев или научной приёмки.

## Маршрут

| Условие | Исполнитель |
|---|---|
| Целый пакет вместе с подготовкой/проверками/публикацией ≤600 с | local, среда ИИ |
| Пакет >600 с; каждая секция из целых задач вместе с накладными расходами ≤21600 с | GitHub Actions |
| Непрерывная задача с подготовкой/проверкой/публикацией >21600 с | ВМ, один процесс |

Если короткие независимые задачи собраны в слишком большой batch, разделяют batch
по границам **целых** задач. Это не основание отправлять его на ВМ. Если одна
реализация сама не помещается в job, применяется маршрут ВМ. Непрерывный расчёт
имеет ровно одну задачу и одну секцию. Его не превращают в последовательность
перезапусков ODE. Checkpoint: `not_required` или `method_defined` со ссылкой на
контракт метода; ни один режим не включает автоматический retry/resume.

## Предварительный контракт

`RUN_REQUEST.execution_plan` указывает на JSON `vm-lab-execution-plan-v1`.
Исполняемая схема — `execution_policy.validate`; синтетические примеры всех
маршрутов — `infra/test_autonomy.py::example`. Это тестовые данные, не калибровка
реального BBN и не разрешение запускать пример.

Обязательные поля:

- `package_id`, `source_commit` (полные 40 hex), `publication_branch`;
- `workload_kind`: `independent_realizations` или `continuous`; `executor`:
  `local`, `github_actions`, `vm`; `parallel_sections`;
- `input_manifest`, `acceptance`, `calibration`: относительный `path` и SHA-256.
  Калибровка также указывает `executor`, `environment_reference`, `measured_seconds`.
  Валидатор проверяет наличие/байты; содержательная применимость измерения
  проверяется по RUNTIME_GATE, а не выводится из одного наличия хеша;
- `tasks`: уникальный `id`, `forecast_seconds`, `process_seconds`, при MC — `seed`.
  В A/B один seed разрешён для разных task IDs. Менять состав после старта нельзя;
- `sections`: уникальный `id`, `task_ids`, `setup_seconds`, `compute_seconds`,
  `verification_seconds`, `publication_seconds`, `wall_seconds`, `memory_bytes`.
  В секции задачи последовательны; параллельность задаётся между секциями;
- `budget`: `package_seconds`, `section_seconds`, `process_seconds`,
  `memory_bytes`, `output_bytes`, `vm_seconds` (null вне маршрута ВМ);
- `checkpoint_policy`, при `method_defined` — `checkpoint_contract` с хешем;
- `scientific_acceptance=false`, `automatic_retry=false`.

Глобальные 5400/2400 с отменены только для новых планов. Каждый бюджет конечен,
положителен и закреплён **до вычислений**. `package_seconds` — сумма резервов
исполнителей всех секций, а не wall time параллельного workflow. Жёсткие лимиты
отделены от прогноза. Накладные расходы учитываются один раз; проверка и выгрузка
получают ненулевой резерв. Суммарный пик памяти одновременно работающих секций
не превышает бюджет пакета (текущий максимум 4 GiB); совокупные выходы ≤2 GiB.

Для ВМ дополнительно нужен `verified_vm_limits`: `executor_id`, `wall_seconds`,
`memory_bytes`, `output_bytes`, `evidence={path,sha256}`. Worker должен фактически
поддерживать весь конечный `vm_seconds`; отсутствие лимита GitHub не удостоверяет
лимиты worker. Доставка — существующий LAUNCH_RUNBOOK/RUN_CONTRACT, исходники
только через GitHub и immutable SHA. Сохраняются журнал, ресурсы, входы и артефакты.

Сначала коммит исходников, входов, калибровки и критериев, затем коммит execution
plan/RUN_REQUEST со ссылкой на исходный SHA. В Actions допустимая разница после
source_commit — только эти два файла. PLAN.branch, publication_branch и фактическая
ветка совпадают. Динамический checkout больше не возвращает работу в опорную ветку.

Проверка без запуска:

```sh
python infra/autonomy/execution_policy.py path/to/EXECUTION_PLAN.json
```

## Допуск, секции и завершение

Единый журнал — `infra/autonomy/LEDGER.json` в
`science/autonomous-research-20261114`. `admit.decision/reserve` используются всеми
исполнителями до submit, включая local/VM. GitHub API-запись требует текущий blob SHA;
409 → перечитать журнал и заново решить; неопределённый сетевой ответ → не submit,
сначала восстановить состояние. Резерв нельзя освобождать по одному истечению часов.

Один package_id резервируется один раз; все section/job IDs принадлежат ему.
Продолжение заранее заданных секций не является новым пакетом. Нельзя добавлять
задачи/seed/другую постановку в уже открытый пакет. Live Actions сверяется с ledger;
неопознанный запуск учитывается консервативно до разбора. Остаются один активный
пакет, один новый пакет на событие и два новых пакета за скользящие 24 часа.

Каждый специализированный секционный workflow использует общую concurrency group
`ccc-bbn-research-pipeline` на уровне workflow, проверяет admission один раз,
передаёт неизменяемые артефакты секций и проверяет полное покрытие в агрегаторе.
Дедупликация выполняется по `(package_id, section_id, source_sha, plan_sha256)`.
Завершённые секции не пересчитываются. Незавершённая/неизвестная — REVIEW, а не retry.
Секции не требуют пробуждения ChatGPT: их зависимости находятся в workflow.

Существующий CCC dispatcher исполняет один цельный stage package. Для него добавлен
проверяемый маршрут и общий compute deadline; он отклоняет многосекционный план,
чтобы не повторить весь опыт в каждом job. Пакетный runner для будущего S3 MC должен
вызывать реальные подмножества матрицы; он не появляется автоматически из этой
правки инфраструктуры. Схема валидатора уже позволяет последовательные и
параллельные секции, но научный S3 runner/GP posterior этой работой не созданы.

В hosted workflow маршруты local/VM дают HANDOFF без резервирования/вычисления;
диспетчер использует соответствующий исполнитель и общий reserve до фактического
submit. Запись terminal закрывает резерв только после подтверждённого выхода всех
процессов. `finish.py` обслуживает односекционный Actions путь. Поле publication_sha
указывает опубликованный commit; COMPLETED здесь означает техническое исполнение,
не научный PASS. FAILED и исходные доказательства нельзя переписывать.

## Внедрение и незакрытые долги

Изменение подготовлено от PR #54, source a90564d2cbe9c89cbbeb3ffb7295359c09f86d3d.
CONTROL.active_branch/active_pr и CURRENT/RUN_REQUEST/очередь остаются прежними.
Изменения отдельного PR не объявляются развёрнутыми в опорной ветке; указатель
переемника обновляется только после подтверждённого допуска/запуска согласно
правилам владельца. Научные PR автоматически не сливаются.

Таймер пробуждения BUDGET_WAIT не входит в эту миграцию маршрутов. `not_before`
не является таймером. Непрерывность всей автономной цепочки пока не подтверждена.
Сервисы ВМ не изменялись, полномасштабные расчёты и внешние AI не запускались.
