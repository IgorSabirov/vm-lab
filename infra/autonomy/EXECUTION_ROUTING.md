# Исполнитель по решению владельца; гейт времени без потолка

Директива 16 ноября 2026: [COMPUTE_AUTHORITY.md](../../COMPUTE_AUTHORITY.md).

Площадку local / github_actions / vm выбирает только владелец. Время не является
критерием выбора, отказа или остановки. `execution_policy.validate` проверяет
заданный executor, совпадение среды калибровки, источники, полное покрытие задач,
память и выходы. Автоматической маршрутизации и временных потолков нет.

Сохраняются package_id, полный source_commit, publication_branch, тип делимости,
матрица задач, input_manifest, acceptance, измеренная calibration с хешами,
checkpoint_policy, scientific_acceptance=false и automatic_retry=false.
Калибровка обязана описывать выбранного исполнителя. Непрерывная интеграция не
делится на перезапуски; независимые задачи покрываются ровно один раз.

`tasks[].forecast_seconds`, setup/verification/publication_seconds определяют
прогноз полного времени. Диапазон и основания фиксируются по RUNTIME_GATE до
старта. Старые process_seconds, compute_seconds, wall_seconds и budget.*seconds
не являются таймерами; новые планы могут оставлять потолки null. Поле
`timeout_minutes` результата валидатора равно null. Фактические свойства внешней
платформы учитываются в паспорте, не превращаясь в разрешение сменить площадку.

Для ВМ проверяются executor_id, фактические ресурсы памяти/диска и свидетельство
проверки worker. Доставка — GitHub и неизменяемый SHA через штатный LAUNCH_RUNBOOK.
Общий LEDGER, CAS admission, учёт живых процессов, сохранение FAIL/REVIEW,
защита от дублей и отдельная научная приёмка сохраняются. Завершение публикации
не запускает повторную интеграцию; резерв закрывается после выхода процессов.

Старые замороженные SHA и отчёты не изменяются. Новый запуск использует новую
версию исполнителя без проектного таймера и сохраняет прогноз/факт. Изменение
документов не развёртывает код на ВМ и не запускает научный пакет.
