# Действующая исследовательская система

Одна рабочая очередь: [Projects](https://github.com/users/IgorSabirov/projects/2).
Один источник допуска: [CONTROL](https://github.com/IgorSabirov/vm-lab/blob/science/autonomous-research-20261114/infra/autonomy/CONTROL.json)
и [общий LEDGER](https://github.com/IgorSabirov/vm-lab/blob/science/autonomous-research-20261114/infra/autonomy/LEDGER.json).
`infra/OPERATIONS.json` — указатель на них, не второй контроллер.

## Что открыть сейчас

[Последний запуск Projects working board](https://github.com/IgorSabirov/vm-lab/actions/workflows/projects-sync.yml):
job `operations`, его Summary и артефакт `research-operations`.
Обновление — существующий часовой schedule, событие Project events после изменения
PR, изменение реализации на main, ручной workflow_dispatch. Job `operations`
не зависит от секрета Projects и не останавливается из-за отказа синхронизации доски.
Артефакт содержит JSON и читаемый Markdown; новые служебные commits не создаются.
Это наблюдение, а не дополнительный механизм запуска научных задач.

Обзор фиксирует HEAD опорной и активной веток, читает CONTROL/PIPELINE/RUN_REQUEST/
CURRENT и LEDGER по этим SHA, сверяет политику, хеши SUMMARY/ARTIFACTS, перечисляет
все активные Actions независимо от возраста и outstanding reservations local/Actions/VM.
В конце повторно читает HEAD: движение ветки означает несогласованный снимок,
а не разрешение вычисления. Отказ API/пагинации даёт INCOMPLETE, не пустую очередь.
На каждом PR проверяются последние checks точного HEAD; pending нового check
не скрывается старым зелёным результатом. Draft и научная приёмка не выводятся из CI.

**Граница проверки:** хеши двух квитанций не равны повторной проверке каждого
сырого артефакта, domain-verifier или физического mapping. Эти уровни остаются
в закреплённых отчётах. Обзор не заменяет `admit.reserve` с CAS.

## Один цикл до завершения

1. Задание содержит вопрос, родителей и критерий завершения. Подготовительный PR
   ещё не является готовым замороженным научным контрактом.
2. Для готового опыта фиксируются package_id, исходный SHA, входы, матрица/seeds,
   критерии, runner/verifier, измеренная калибровка и конечные бюджеты.
3. Существующий контроллер сверяет live состояния и резервирует один пакет в
   общем ledger. Суточной квоты нет; повтор события не создаёт новый пакет.
4. После расчёта публикуются неизменные артефакты и терминальная квитанция.
   Восстановление публикации не повторяет вычисление. FAIL/REVIEW сохраняются.
5. Инженерная проверка, научный вывод и решение владельца записываются раздельно.
   Новый результат виден из main даже до научной приёмки и merge его ветки.
6. Исправление инфраструктуры проходит собственный PR и exact-head CI; при
   действующем поручении на внедрение доводится до main и live readback.
   Научные PR автоматически не сливаются. Ошибка замороженного задания не
   запускает саморемонт или научный retry.

Завершение — проверяемый результат и закрытое конкретное обязательство. Число
commits, R-карточек, процентов зелёного CI и сокращение количества веток не являются
научной отдачей. `skipped` при неподходящем событии — не сбой. `action_required`
остаётся отдельным состоянием допуска; защиту бот-PR ради зелёной статистики не снимаем.

## Исправления по поручению 15 ноября

Основания: [issue #68](https://github.com/IgorSabirov/vm-lab/issues/68),
[CI 43710634142](https://github.com/IgorSabirov/vm-lab/actions/runs/43710634142),
[reporter 43710820398](https://github.com/IgorSabirov/vm-lab/actions/runs/43710820398).

- Reporter получал 403 при комментарии в PR: добавлено явное `pull-requests: write`.
  Код берётся только из доверенного workflow SHA; устаревший HEAD не комментируется,
  повтор одного run-id не публикуется снова. Ошибка доставки не маскируется PASS.
- Два теста допуска ошибочно читали live RUN_REQUEST и S3 stage из текущей ветки.
  Их фикстуры изолированы; повреждённый manifest/payload по-прежнему отвергается.
  Научные контракты ради успешного теста не переносятся и не меняются.
- Публикатор workspace сравнивает деревья до commit. Уже опубликованные байты,
  включая потерянное подтверждение push, дают no-op после свежего чтения remote.
  Конкурентные посторонние изменения сохраняются.

Одинаковое сообщение commit само по себе не доказывает дубль: workspace exporter
публикует пакетами. Исправляется конкретный отсутствовавший tree guard. RAW publisher
уже имел проверку идентичного manifest и не переписывается.

## Что сохраняется и что ещё не готово

Исторические RAW, исходные FAIL и SHA не удаляются, git history не переписывается.
Экспорт крупных данных должен иметь durable archive, manifest, hash и проверенное
восстановление до удаления какой-либо копии. Actions artifact с конечным retention
не заменяет долговременный архив. Размер .git не уменьшается удалением рабочих файлов.
Исправленный host-side publisher доступен в main; обновление установленной на ВМ
копии требует штатного маршрута развёртывания по SHA и отдельного readback.

На момент первичного осмотра: активен PR #54; S0/S1/S_ETA/BH0/S3_INPUT_AUDIT имеют
опубликованные свидетельства; следующая очередь `PREPARATION_REQUIRED`, а не ожидание
суточной квоты. Для S3 нужны физическая ковариация скоростей и независимый CMB-вход;
для S2 — физические карты и закон. Совместное исполнение ADD_F2 и Serbian в #65 —
инженерный результат, не общий физический генератор. Эти пробелы не закрываются
слиянием draft-PR или добавлением новых проверок инфраструктуры.

Для текущих чисел и SHA использовать живой обзор, а не этот датированный абзац.
