# Решение владельца: площадка, время кода и итог пробы Work → Chat

17 ноября 2026. Применяется к новым действиям раньше прежних инструкций этой попытки.
Связь: [Issue #83](https://github.com/IgorSabirov/vm-lab/issues/83), [PR #84](https://github.com/IgorSabirov/vm-lab/pull/84).

## Окончательное действующее поручение

> «ЭТОТ ПРРОГОН ТЫ ГОНИШЬ НА СЕБЕ. Доступно? Полный прогон. Зафиксируй наше исследование по методике и продолжим науку.»

Выбрана локальная вычислительная среда ассистента. Предшествующее поручение
«запускай на гите» отменено последующим «Стоп» до запуска Actions.
Научный запуск GitHub Actions и запуск ВМ в рамках этой попытки не выполнялись.
Полный исполнимый предмет текущего пакета — 6032 случая блока ADD C1 и отдельная
калибровка 128 случаев; другие фазы общего протокола ADD не обозначаются выполненными.

Сохраняется правило: площадку физических вычислений выбирает только владелец.
Прогноз длительности не выбирает площадку автоматически.
Гейт относится к **времени исполнения кода**, без подготовки кода/среды, чтения,
упаковки/переноса исходников, очереди, общения и публикации.
Эти затраты можно измерять отдельно, но нельзя прибавлять к прогнозу исполнения
или расходовать ими разрешённое пользователем время расчёта.
Сборка операторов/факторизация внутри самого алгоритма остаётся частью исполнения кода.
Калибровка учитывается отдельно от основного корпуса.
Прогноз с диапазоном не является проектным таймером остановки.
Фактическое ограничение внешней платформы указывается отдельно с источником.

## Что проверяла методическая проба

Вопрос: можно ли готовить научный пакет в Work, исполнять его в обычном Chat,
а весь обмен проводить через GitHub, с возможной экономией кредитов Work?

| Этап | Наблюдение | Основание |
|---|---|---|
| Подготовка инструкции и исходников в GitHub | Выполнено | cddfc41f2b1e1467745573579458a01d71813c96 |
| Чтение в обычном Chat | По сообщению, предоставленному владельцем, выполнено | Ответ Chat, процитированный в разговоре |
| Запись прочитанных исходников в Python-среду Chat | Не выполнена по тому же сообщению | Chat заявил отсутствие «моста»; конкретного отказавшего вызова Python не предъявил |
| Калибровка, расчёт, публикация из Chat | Не выполнены | В ответе прямо указано отсутствие прогона и итогового commit |
| Объединение в самодостаточный файл | Упаковка и хеши проверены в Work; фактический расчёт в Chat не подтверждён | 0272e39b624f5f1e11ecb3d5ab24d514a47b79a8 и 91ae979661b2ee1191d06d161dd90b21b77d0337 |
| Решение по объединённому файлу | Владелец отклонил подход; исключён из актуального дерева, история сохранена | «Это плохая идея объединить… инструкцию по получению каждого этапа» |
| Оплата/экономия | Не измерена | Успешного выполнения в обычном Chat и сопоставления расхода нет |

**Итог: NO_GO_CURRENT_ATTEMPT** — сквозная схема в текущей попытке не получена.
Это операционный результат, не доказательство невозможности Python в Chat
или невозможности передачи текста между инструментами.
Отсутствие сетевого доступа Python само по себе не исключает передачу прочитанного
текста в аргументе Python-вызова. Доступность и ограничения конкретных инструментов
проверяются фактическими вызовами, а не предположением.
Продолжение выяснения тарифов/переноса сейчас прекращено по решению владельца.

## Рабочая методика без объединения исходников

Нормальный проект хранит независимые модули, спецификацию, параметры и результаты
отдельными файлами. Исполнитель получает ровно файлы следующего этапа по одному
зафиксированному SHA; не распаковывает непрозрачный монолит и не перечитывает весь проект.

| Этап | Что получить | Что выполнить/сохранить |
|---|---|---|
| 1. Источники | SPEC.json, PLAN.json, SOURCE_MANIFEST.sha256 | Зафиксировать исходный SHA и состав |
| 2. Код | ring_engine.py, graph_engine.py, run_block1.py | Сохранить по отдельности, сверить SHA-256; не менять правила |
| 3. Калибровка | Полученные модули | run_block1.py --calibrate; сохранить CALIBRATION/PREFLIGHT до основного расчёта |
| 4. Полный корпус | Те же замороженные исходники и свежий PREFLIGHT | run_block1.py --run; сохранить RESULTS/WITNESSES и лог |
| 5. Сверка | Эталонные RESULTS/WITNESSES на исходном SHA | Сравнить детерминированные поля и полноту; время/среду учитывать отдельно |
| 6. Публикация | Только новые результаты, квитанции и хеши | Commit в GitHub, readback точного SHA; не считать старый эталон новым прогоном |

В Chat каждый этап должен быть отдельным вызовом исполнения; после обрыва продолжать
с сохранённого результата, не повторять вычисления ради экспорта.
Точный универсальный лимит одного Python-вызова в обычном Chat не установлен этой
пробой; не назначать выдуманные 60/120 секунд или прежние 10 минут.
Если интерфейс сообщает реальное ограничение, записать его отдельно.
Состав научного расчёта ради неизвестного ограничения не менять.
