# Публикация исходных файлов NOW LONG

Поручение 9 ноября 2026: ВМ сама публикует результаты как отдельные файлы,
без ZIP и без передачи большого Base64 через чат. Научный прогон не повторяется.

Скрипт: `infra/publish_now_raw.py` (Python 3, стандартная библиотека и Git).
Запускать **на хосте ВМ**, вне изолированного вычислительного worker.
Текущий MCP worker не имеет сети и доступа к ключам; запуск скрипта через
start_python_job не выполнит публикацию. Нужен один запуск из терминала ВМ.

Используется существующий `/etc/vm-lab-sync/config.json` с его GitHub remote
и SSH-командой. Секреты не копируются в репозиторий и не выводятся. Службы,
API, worker и их настройки не меняются. Нужны права чтения существующего
конфига/ключа и результатов, поэтому команда запускается через sudo.

Источник: `/var/lib/vm-compute/work/results/now_long_main_da72a3a_20261108/`.
Назначение: `results/NOW_LONG_da72a3a_20261108_RAW/` в `main`.

Публикуется весь `main_output/`: 3083 файла rows, 235 traces, 235 geometry,
все сводки, checkpoint, показатели и исходные метаданные. Рядом сохраняются
PROCESS.json, process.log, ARCHIVE.json, отдельный FOUR_CANDIDATE_RETURN.json,
worker status/request/output, прогноз, план калибровки и квитанции калибровки.
Имеющийся FULL_OUTPUT.zip не загружается: его содержимое передаётся исходными
файлами; квитанция архива сохраняется. Другие исходные файлы не преобразуются.

Перед публикацией проверяются завершение, исходный научный SHA, количество
файлов и неизменность исходного снимка. На каждый файл сохраняются размер,
SHA-256 и Git blob SHA-1 в PUBLICATION_MANIFEST.json. Данные попадают в один
коммит поверх свежего main; обычный push, без force. Параллельное продвижение
main приводит к повторной сборке на свежей вершине, максимум три попытки.
Уже опубликованный идентичный пакет принимается без нового коммита;
отличающийся пакет в том же каталоге не перезаписывается.

После push скрипт снова получает main с GitHub и сравнивает полное дерево
каталога с подготовленным снимком, включая все blob IDs и манифест.
Единственный маркер успеха: `PUBLISHED_AND_VERIFIED` с SHA, количеством,
размером и ссылкой. Ошибка/прерывание не объявляются успехом; безопасно повторить.
Статус гейта REVIEW_REQUIRED и scientific_confirmation=false сохраняются.
U001/U002 и научные реестры этим техническим переносом не переоцениваются.

Для автономного исполнения после выхода из терминала:

```bash
sudo systemd-run --unit=now-raw-publish --collect /usr/bin/python3 -I -u /var/lib/vm-compute/work/code/publish_now_raw.py
```

Журнал: `sudo journalctl -u now-raw-publish --no-pager -n 30`.
При повторе во время работающей службы systemd откажет в повторном имени;
дополнительно скрипт держит блокировку в `/run/lock/`.

Локальная проверка: `python3 -m unittest discover -s infra -p test_publish_now_raw.py -v`.
Два теста: реальный Git commit/push/fetch и сохранение бинарных/CRLF байтов,
повтор без дубля и отказ на конфликт; полный ожидаемый инвентарь и отказ
на недостачу/симлинк. Доступ к реальному GitHub с ВМ проверяется при запуске,
локальный тест его не подтверждает.
