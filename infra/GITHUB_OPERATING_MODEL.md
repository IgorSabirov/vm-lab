# GitHub operating model vm-lab

Дата: 11 ноября 2026. Назначение: разложить GitHub на минимальные объекты и определить, как они обслуживают исследовательский процесс, не подменяя его научную онтологию.

## 1. Атомы Git

| Атом | Что хранит GitHub | Роль в vm-lab |
|---|---|---|
| Blob | Неизменяемое содержимое файла | Исходный отчёт, код, таблица, JSON, инструкция |
| Tree | Состав каталога и ссылки на blobs/trees | Согласованный снимок набора материалов |
| Commit | Tree + родители + сообщение и авторство | Фиксированная версия доказательства, протокола или инструмента |
| Parent edge | Причинно-историческая связь коммитов | История изменений; не научная причинность |
| Branch/ref | Изменяемое имя, указывающее на commit | Независимая работа и точка ревью |
| Tag/release | Именованная фиксация версии | Архивируемая версия кода/набора; не научный статус |

SHA blob/commit удостоверяет байтовую идентичность объекта в Git, а не истинность содержания. Git-родитель фиксирует историю репозитория, а не физическую генеалогию исследуемой системы.

## 2. Атомы совместной работы

| Атом | Назначение | Граница применения |
|---|---|---|
| Issue | Рабочий вопрос, задача, ошибка или запрос ревью | Не копия R-записи; закрытие не закрывает U/L |
| Issue Form | Структурированный приём задачи | Собирает вопрос, источники, генеалогию, полномочия, бюджет и критерий |
| Pull Request | Предложение изменения относительно базовой ветви | Не научная приёмка; merge только интеграция кода/документа |
| Review / review thread | Адресная проверка диффа | Замечания к файлам/строкам; решение человека остаётся явным |
| Label / milestone | Фильтр и группировка текущих задач | Метаданные управления работой, не типы научных утверждений |
| Project V2 | Очередь активной работы и её статусы | Не зеркалирует весь научный реестр; рабочий Done не равен научному RESOLVED |

## 3. Атомы автоматизации

| Атом | Назначение | Что ему разрешено |
|---|---|---|
| Actions workflow | Запуск повторяемой проверки на фиксированном SHA | Проверки заявленных технических свойств |
| Job / step | Отдельная единица исполнения и диагностики | Проверяемый этап с минимальными правами и timeout |
| Artifact | Выход конкретного запуска | Логи, диагностические файлы, архивы; хранить происхождение |
| Cache | Повторное использование промежуточных зависимостей | Только если есть измеренная повторная стоимость |
| Dependabot | Предложения обновления Actions/зависимостей | Только PR; без автоматического научного/релизного принятия |
| Secret / environment | Контролируемый доступ к ВМ или сервису | Не выводить в логи/репозиторий; минимум прав и явные границы |

Технический PASS удостоверяет только то, что реально проверили. Smoke/unit-test не является научным запуском. Workflow не должен незаметно менять научные статусы или публиковать результат вместо приёмки.

## 4. Научные атомы vm-lab и типы связей

Источники истины:
- `RESULTS_REGISTER.json`: R/C/L и типизированные отношения;
- `OPEN_QUESTIONS.json`: U;
- `PREMISES_CURRENT.md`: 66 предпосылок A01–G08 и девять N-долгов.

Компилятор строит отдельные типы узлов:
- `result:Rxxx` — результат;
- `construct:Cxxx` — конструкция;
- `link:Lxx` — открытая граница;
- `question:Uxxx` — открытый вопрос;
- `premise:A01…G08` — предпосылка;
- `obligation:N01…N09` — исследовательский долг, отличный от предпосылки;
- `source:path` — конкретный управляемый источник-свидетельство с контрольными суммами.

Рёбра типизированы: `parent`, `addresses`, `direct_conditional_evidence`, `historical_navigation_not_proof`, `boundary_open`, `informs_not_closes`, `updates_not_closes`, `managed_evidence_source`.

Прямое условное свидетельство, историческая навигация, родство записей и открытый вопрос — не взаимозаменяемы. Количество связей не является мерой научного прогресса.

## 5. Агент как участник процесса

В репозитории закрепляются три разных интерфейса:
1. `AGENTS.md` — долговременные правила работы агента, границы полномочий и проектная цель.
2. GitHub Issue Form — локальная задача: вопрос, источники, R/C/L/U/N, разрешённые действия, бюджет, критерий завершения.
3. PR template — описание диффа, свидетельств, тестов, изменённых статусов и остатка.

Агент действует от доступных ему разрешений и фиксированной ветви. Он не должен:
- считать закрытый Issue или merged PR научной приёмкой;
- создавать 129 Issues из 129 результатов;
- менять R/C/L/U/N научный статус только из-за CI;
- принимать новый закон, носитель, меру или архитектуру без содержательного решения;
- запускать VM или удалять/перезаписывать данные вне явного полномочия.

GitHub не становится сам по себе автономным агентом. Issue/PR — интерфейс постановки и ревью; наличие формы не означает, что агент автоматически наблюдает или исполняет каждый Issue.

## 6. Один рабочий контур

`Issue → Analysis → Ready → Running → Review → Done` — это рабочие стадии задачи, не научная лестница.

Результат работы возвращается к тем же родителям:
`вопрос → план → изменение → свидетельство → ограничение → обратные ссылки`.

Для документационных и инфраструктурных PR допускается завершение без научного изменения. Для научного PR необходим отдельный разбор утверждения, предпосылок, метода, области и контрпримеров. Обновления производных файлов должны быть воспроизводимы из исходников.

## 7. Реализация 12 ноября

- Два реестра, N-долги, D-решения, внешние разборы и управляемые источники связаны общим графом v3.
- Development checks: каждый PR, адресная матрица из шести наборов, стабильный merge-gate. Серверная обязательность пока недоступна на текущем тарифе приватного репозитория.
- Registry advisor связывает типизированные ID в Issues; CI failure advisor сообщает только технический отказ.
- Result intake PR создаёт черновик для results/run_id. Если GitHub запрещает создание PR токеном Actions, workflow явно завершится ошибкой; ветка и квитанция сохранятся для создания PR через коннектор.
- Ручной Freeze reviewed snapshot создаёт draft release проверенного SHA main.
- [Контракт запуска и миграции](RUN_CONTRACT.md); новый мост опубликован, deployment не заявляется.
- [Принятые решения](../decisions/README.md), [снимок состояния](../continuity/ACTIVE_STATE.json), [подробный разбор](reviews/GITHUB_20261112/REPORT.md).
- Projects описан, но не создан: нет Projects API в коннекторе и нет авторизованной браузерной сессии.

## 8. Осознанно не включено

- Автоматический merge/auto-approve.
- Автоматическое закрытие U/L/R на основании Issue/PR.
- AI-генерация научных связей или статусов без проверки.
- GitHub Pages как публичная витрина.
- CodeQL как универсальное решение главного риска: научная корректность не сводится к статическому анализу кода.
- Actions cache без повторно используемых зависимостей и измеренной пользы.
- Автоматическое развёртывание на пользовательскую ВМ по любому push.
