# Авторское C++-ядро с интерфейсом Python

Здесь используется оригинальная библиотека `symmetric_matrix_signature` из
[кода сербской группы](../../third_party/piecewise_flat_qg/README.md).
Алгоритм не переписан на Python: тонкий C ABI принимает пакет симметричных матриц,
а Python получает инерцию `(число положительных, отрицательных, нулевых)` и
диагностику. Это самостоятельный инструмент; NOW v0.3 его пока не вызывает.

## Сборка и проверка

Из корня репозитория, в Linux с компилятором C++11, Python 3.12+ и NumPy:

```bash
python tools/piecewise_flat_qg/build_and_check.py \
  --build /tmp/vm-lab-piecewise-flat-qg \
  --report /tmp/vm-lab-piecewise-flat-qg-build.json
```

Скрипт работает без скачиваний и CMake: проверяет закреплённые хеши, собирает
библиотеку, восемь авторских тестовых наборов, три исходных генератора и малую
проверку склейки. Затем проверяет Python-интерфейс и измеряет три способа
классификации на 4096 матрицах 4×4. Общий предел исполнения — 300 секунд;
команды, времена и вывод сохраняются в отчёте. Большие авторские генераторы
только собираются. Их запуск не входит в эту команду. Исходные CMake-файлы
сохранены для дальнейшего освоения стандартной авторской сборки.

Сборка использует `-O2 -fno-fast-math`: свободное преобразование вычислений
компилятором здесь нежелательно. Выводы о скорости относятся к измеренной
машине и задаче, а не к языку вообще.

## Использование

```python
import sys
import numpy as np

sys.path.insert(0, "tools/piecewise_flat_qg")
from signature_kernel import SignatureKernel

kernel = SignatureKernel("/tmp/vm-lab-piecewise-flat-qg/libvm_signature.so")
result = kernel.classify(np.diag([1., 1., 1., -1.]))
print(result["counts"])  # [[3, 1, 0]]
```

Можно передать массив формы `(batch, n, n)` одним вызовом. Допустимы
`1 <= n <= 256` и `1 <= batch <= 1000000`, с учётом доступной памяти.
По умолчанию любой ненадёжный результат вызывает `ValueError`. Для исследования
причины нужно явно вызвать `classify(matrices, strict=False)` и читать
`status`, `reliable`, `symmetry_adjusted`, `numerically_ambiguous`,
`zero_tolerance`; строку с ошибкой нельзя использовать как классификацию.

Обёртка не исправляет симметрию входа молча. Авторское ядро может усреднить
незначительную асимметрию, но помечает такой результат ненадёжным, и строгий
интерфейс его отвергает. Если симметризация обоснована построением матрицы,
её следует сделать явно до вызова и сохранить размер поправки.

## Что перенесено

- Оригинальная LDLᵀ-факторизация с выбором блоков 1×1/2×2, масштабированием
  и проверкой чувствительности результата к порогу.
- Пакетный вызов C++ из Python: Python управляет опытом, C++ выполняет ядро.
- Авторские проверки и дополнительная проверка нашего интерфейса.
- Триангулятор: `mesh_probe.cpp` строит два 4-симплекса с общей гранью и минимальную
  4-сферу, проверяет инцидентности и общие объекты рёбер.

`1e-30` из генераторов — порог знака детерминанта Кэли–Менгера. Это **не**
порог классификатора LDLᵀ: у него собственные масштабные и машинные допуски.
Ни один из этих методов не гарантирует точную классификацию произвольно близко
к вырождению. Честный флаг неопределённости — полезная часть результата.
