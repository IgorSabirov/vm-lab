# Проверка подготовки E002b v001

29 октября 2026. **Локальные проверки: 5/5, 72,960 с, exit code 0.** Это время тестов в среде подготовки, не время ВМ и не научный результат. Прогноз основного этапа A остаётся 482,497 с с диапазоном 289,498–675,496 с.

Подготовлен исполняемый этап A: без повреждений, 8 траекторий, 240000 основных RK4-шагов +1200 preflight. Заявка на ВМ не отправлена. Этап B определён протоколом, но его отдельный код/конфигурация запуска будут опубликованы после проверки A.

## Команда и ожидаемые результаты

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m unittest discover -s infra -p 'test_e002b.py' -v
```

Короткий тест также выполняет preflight четырёх генераторов и весь путь записи массивов, описи, CSV, метрик и RESULT. Его научный статус принудительно BLOCKED (`test_mode_not_scientific`); это не проверка стационарности на T200 и не основание запускать повреждения.

`infra/verify_e002b_report.py` не импортирует расчётные модули. Он заново вычисляет средние последнего окна и показатели сопоставления из опубликованных CSV, сверяет сетки, объём работы, экстремумы, решения, блокировки и арифметику описи. Полные матрицы через GitHub не передаются, поэтому нормы rho этот скрипт заново не вычисляет. Проверка транспортных хешей и идентичности запуска выполняется отдельно через `infra/github_result_reader.py`.

## Происхождение и границы

Численное ядро `e002_exp/model.py`, функции состояния/стационарности и зависимости взяты без изменения из исходного коммита E002 `9809c90cd3d3042157a6aa2f28ec09889f7b7651`. Git blob SHA локальных копий совпадают с этим коммитом. Новые файлы — управление feasibility, matching, отчёт и его независимый пересчёт; старый расчёт E002 не переписывается.

Калибровка скоростей взята из неповреждённых QS/QQ fine E002; зафиксированы источник и SHA256 метрик. Результаты повреждений не используются для подгонки RR. В этой версии нет оптимизатора и lambda-скана.

Это проверка кода подготовки, а не живая проверка доставки нового задания GitHub↔ВМ. Проверки старой инфраструктуры здесь повторно не объявляются выполненными. Численный результат A, фактическое время ВМ, объём файлов, отсутствие export_errors и пользовательская приёмка появятся только после отдельного запуска и чтения его закреплённого GitHub-отчёта.
